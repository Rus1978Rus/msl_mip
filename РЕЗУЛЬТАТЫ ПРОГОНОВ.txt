### V3. P1 FAIL-CLOSED: degraded-флаг меняет вердикт?

**VERDICT: CONCERN**

**Код:**
```python
_TLD_SOURCE_DEGRADED = False

def _tlds():
    # ...
    if not isinstance(s, (set, frozenset)) or len(s) < 100:
        _TLD_SET = frozenset()
        _TLD_SOURCE_DEGRADED = True
    # ...
    except Exception:
        _TLD_SET = frozenset()
        _TLD_SOURCE_DEGRADED = True
```

**Поведение при degraded:**
- `_TLD_SET = frozenset()` → пустой набор
- `labels[-1].lower() in _tlds()` → всегда `False`
- `_looks_like_domain` → всегда `False`
- `_detect_context_at` → всегда `FREE_TEXT` (или PATH/HOST по старой логике со схемой)

**Это НЕ fail-closed.** При degraded:
- `gоog／le.com` → `FREE_TEXT` → PASS (пропуск!)
- `http://gоog／le.com` → HOST (схема не зависит от TLD)

**Fail-closed** означает: при ошибке — **консервативно**, т.е. **не пропускать**. Здесь: при ошибке — **FREE_TEXT** → **пропуск**.

**Рекомендация:** При `_TLD_SOURCE_DEGRADED = True` и **голом домене** (без схемы) — не понижать до FREE_TEXT, а **сохранять PATH** (или HOST) с флагом:
```python
if _TLD_SOURCE_DEGRADED:
    # Cannot verify TLD — assume domain-like tokens are suspicious
    if _has_dot_structure(token):  # >=2 метки по форме
        return "PATH"  # или "HOST", консервативно
```

**Или проще:** При `_TLD_SOURCE_DEGRADED` — `_looks_like_domain` возвращает `True` для ЛЮБОГО токена с ≥2 метками (без проверки TLD). Это **консервативно** — не пропускает, но может ложить.

**Текущий подход (только флаг):** Не fail-closed. Рекомендую усилить.

### V5. P6 left+right вместо replace: несколько масок в одном токене?

**VERDICT: PASS**

**Код:**
```python
if _looks_like_domain(left_part + right_part):  # PATCH_6: drop only THIS mask
    return "HOST"
```

**Пример:** `gоog／le.／com` (две маски)

**Для первой маски (`／` после `gоog`):**
- `token = "gоog／le.／com"`
- `rel = 4` (позиция первой маски)
- `left_part = "gоog"`, `right_part = "le.／com"`
- `left_part + right_part = "gоogle.／com"` → `_looks_like_domain`?
  - `gоogle` — `isalnum()`? Кириллическая `о` — да.
  - `／com` — `／` — структурный символ → `False`
  - → `False` (не домен)

**Проблема:** `gоog／le.／com` — первая маска не распознаётся как HOST, потому что `／com` содержит `／`.

**Но:** Вторая маска (`／` после `le.`):
- `rel = 7` (позиция второй маски)
- `left_part = "gоog／le."`, `right_part = "com"`
- `left_part + right_part = "gоog／le.com"` → `／` — структурный → `False`

**Обе маски в `gоog／le.／com` → FREE_TEXT?**

**Анализ:** `gоog／le.／com` — это **две маски** в одном токене. Текущий код проверяет **только текущую маску**. Первая маска: `left_part + right_part = "gоogle.／com"` — не домен (содержит `／`). Вторая маска: `left_part + right_part = "gоog／le.com"` — не домен (содержит `／`).

**Но:** `gоog／le.／com` — если заменить ВСЕ маски на ASCII `/` → `google.com` — валидный домен. Текущий код **не распознаёт** это, потому что `left_part + right_part` содержит оставшиеся маски.

**Это баг?** Да, но **крайний случай** (две маски в одном токене). В реальности:
- `gоog／le.com` — одна маска → HOST
- `gоog／le.／com` — две маски → FREE_TEXT (ложный пропуск)

**Частота:** Две маски в одном токене — **крайне редко**. Атакующий предпочтёт одну маску.

**Рекомендация:** Не блокирует, но стоит отметить в LIMITATION_STATEMENT.

### V3. P1 (fail‑closed) — флаг есть, но поведение не меняется

Учитывая, что `load_single_tlds` всегда предоставляет работающий fallback (live‑fetch → cache → embedded), вероятность реальной деградации крайне мала. Тем не менее, для максимальной осторожности можно при деградации считать любой доменоподобный токен с маской как минимум PATH (MEDIUM). ### V5. P6 (несколько масок в одном токене) — **FAIL**
Текущая реализация `_looks_like_domain(left_part + right_part)` **не удаляет другие вхождения маски** (`／`) в left_part или right_part.  
**Пример:** `gоog／le.／com`  
- Для первой маски: left_part = `'gоog'`, right_part = `'le.／com'`.  
- Склеенная строка: `'gоogle.／com'` — содержит `／`, что не является допустимым символом метки → `_looks_like_domain` возвращает False → вместо HOST получаем FREE_TEXT.  

Это реальный обход: атакующий может добавить вторую маску в тот же токен, чтобы подавить детекцию первой.

**Исправление:** при проверке «разорван ли домен» следует удалять **все** вхождения `／` из left_part + right_part (или из всего токена без текущей маски). Безопасный способ:  
`_looks_like_domain( (left_part + right_part).replace('\uff0f', '') )`  
или формировать токен, из которого удалены все маски. Это не повлияет на другие вызовы, так как детектор не имеет побочных эффектов.

**Вывод:** требуется немедленное исправление.

## V5. P6 left+right вместо replace: несколько масок в одном токене

**STATUS: FAIL**

**Доказательство:**

Код:

Это убирает **ТОЛЬКО ТЕКУЩУЮ маску**, не все маски в токене.

**Кейс:** `gоog／le.／com` (две маски в одном токене)

Для первой маски (позиция 4):
- `token = "gоog／le.／com"`
- `left_part = "gоog"`
- `right_part = "le.／com"`
- `_looks_like_domain("gоog")` → 1 метка → False
- `_looks_like_domain("le.／com")` → `_domain_prefix("le.／com")` → `"le.／com"` → `split(".")` → `["le", "／com"]` → `"／com"` содержит `／` (не `isalnum()`) → False
- G2 не срабатывает
- Left is domain: False
- Mask breaks domain: `_looks_like_domain("gоog" + "le.／com")` = `_looks_like_domain("gоogle.／com")` → `_domain_prefix("gоogle.／com")` → `"gоogle.／com"` → `split(".")` → `["gоogle", "／com"]` → `"／com"` содержит `／` → False
- **Результат: FREE_TEXT** (должно быть HOST!)

Для второй маски (позиция 8):
- `left_part = "gоog／le."`
- `right_part = "com"`
- `_looks_like_domain("gоog／le.")` → `_domain_prefix("gоog／le.")` → `"gоog／le."` → `split(".")` → `["gоog／le", ""]` → пустая метка → False
- `_looks_like_domain("com")` → 1 метка → False
- G2 не срабатывает
- Left is domain: False
- Mask breaks domain: `_looks_like_domain("gоog／le." + "com")` = `_looks_like_domain("gоog／le.com")` → `_domain_prefix("gоog／le.com")` → `"gоog／le.com"` → `split(".")` → `["gоog／le", "com"]` → `"gоog／le"` содержит `／` → False
- **Результат: FREE_TEXT** (должно быть HOST!)

**Обе маски дают FREE_TEXT!** Это обход.

**Причина:** `_looks_like_domain` проверяет, что ВСЕ метки состоят из `isalnum()` или `-`. Но `／` не является `isalnum()`, так что метка с `／` не проходит проверку.

**Решение:** Перед проверкой домена, нужно убрать **ВСЕ** маски из токена, а не только текущую. Например:
```python
token_without_all_masks = token.replace("／", "")
if _looks_like_domain(token_without_all_masks):
    return "HOST"
```

Но тогда мы потеряем информацию о позиции маски (HOST vs PATH). Нужна более сложная логика:
1. Если токен БЕЗ ВСЕХ масок является доменом → любая маска в этом токене → HOST
2. Иначе → обычная логика (G2, PATH, FREE_TEXT)

        cut = min(cut, p)
return token[:cut].strip(_STRIP_OUTER)
Это гарантирует, что порт и путь не попадают в проверку TLD, а конструкции вроде evil.com:443 корректно распознаются как домен (G2/V-a).

Табуляция и новая строка
Границы токена определяются пробельными символами (isspace()), что включает табуляцию и новую строку:

python


Копировать
while left_bound > 0 and not text[left_bound - 1].isspace():
    left_bound -= 1
while right_bound < len(text) and not text[right_bound].isspace():
    right_bound += 1
Это гарантирует, что токены не "склеиваются" через табуляцию или новую строку.

Zero-width символы
Zero-width символы (U+200B, U+200C, U+200D и др.) не считаются пробельными в Python (isspace() для них возвращает False), поэтому они могут оказаться внутри метки. Однако, при проверке метки на допустимые символы (isalnum() или дефис), такие символы не пройдут проверку, так как не являются ни буквой, ни цифрой, ни дефисом:

python


Копировать
if not all(ch.isalnum() or ch == "-" for ch in lbl):
    return False
Таким образом, zero-width символы внутри метки приведут к тому, что метка не будет признана валидной, и домен не будет распознан.
