# Учебный блокчейн с майнингом (Proof of Work)

Маленький самодостаточный пример на чистом Python (только стандартная
библиотека), который показывает механику майнинга изнутри.

## Запуск

```bash
python3 mining_demo.py
```

## Что демонстрирует

1. **Майнинг = перебор nonce.** Майнер меняет число `nonce` в блоке и
   пересчитывает SHA-256, пока хеш не начнётся с нужного количества нулей
   (сложность). Число попыток — это и есть «работа» в proof-of-work.
2. **Coinbase-транзакция.** Первая транзакция в блоке начисляет майнеру
   награду: эмиссия (новые монеты) + комиссии со всех транзакций блока.
3. **Проверка сетью.** Каждый узел независимо валидирует блок: корректность
   хеша, связь с предыдущим блоком и — главное — что награда **ровно** равна
   разрешённой. Блок мошенника, где майнер вписал себе лишнего, отвергается,
   несмотря на честно найденный хеш.

Это иллюстрация к идее из обсуждения: «намайнить» — это ценой вычислений
выиграть право записать блок и начислить себе награду, но только ту, что
разрешают правила и которую проверяют все остальные.

## `mining_zero_card.py` — майнинг в стиле «модуль + интегратор»

Отвечает на вопрос: можно ли прогнать хеш блока через «карточку нуля» и
пайплайн модуль/sequence/интегратор, чтобы получить нужное число нулей?

Ответ разложен на две роли майнинга:

- **ПОИСК** (произвести нули) — перебор nonce + SHA-256. Это умеет только хеш.
  Карточка нуля — детектор: она нули *узнаёт*, но не *производит*, и по одному
  хешу не даёт подсказки, какой nonce брать следующим. Поиск ей не ускорить.
- **ПРОВЕРКА** (посчитать нули) — вот сюда пайплайн ложится точно:
  - single-sign (карточка нуля): «этот символ — ведущий ноль?»
  - sequence: «серия ведущих нулей, привязанная к offset 0» (тот же класс
    паттерна, что `../` или `//`)
  - integrator: политика `длина серии ≥ сложность → PASS`, иначе `HOLD`

Итог: карточка нуля — честный **валидатор сложности** (заменяет строку
`hash.startswith("0"*N)` вердиктом PASS/HOLD), но всю работу по добыче нулей
всё равно делает SHA-256. Пайплайн её не ускоряет.

```bash
python3 mining_zero_card.py
```

## `poa_ledger.py` — монета БЕЗ майнинга (Proof of Authority)

Другой полюс: реестр, где право дописать блок даёт **подпись**, а не перебор
нулей. Это модель NOTARIUS (подписанная хеш-цепь событий), превращённая в
монету:

- `CREATED` = эмиссия — подписывает только доверенный **authority**;
- `TRANSFERRED` = перевод — подписывает только **отправитель** (владелец ключа
  адреса).

Защита держится не на майнинге, а на трёх вещах: подписи Ed25519 (нельзя
потратить с чужого адреса), хеш-цепь `prev_hash` (подмена прошлого рвёт
ссылки), один доверенный корневой ключ. Демо показывает эмиссию, переводы,
балансы и то, как один и тот же `verify()` **без майнинга** ловит атаки:
подделку чужого перевода, перерасход, подмену истории, самочеканку.

**Честная цена (обеда всё равно нет — она просто сместилась):** майнинг платит
энергией и никому не доверяет; здесь платят **доверием** — authority управляет
эмиссией, а форк/двойную трату локальная цепь не видит (в демо обе ветки
конфликта валидны по отдельности). Разрешить это можно только внешним
свидетелем (NOTARIUS cosign) — та самая задача, которую в PoW решает майнинг.

Требует пакет `cryptography` (ради Ed25519) — в отличие от PoW-демо выше,
которое обходится стандартной библиотекой.

```bash
pip install cryptography
python3 poa_ledger.py
```

## Чего здесь нет (это модель, а не настоящая монета)

Намеренно упрощено ради наглядности: нет цифровых подписей транзакций (любой
может отправить от чужого имени), нет P2P-сети и синхронизации узлов, нет
автоподстройки сложности и разрешения форков. Настоящие сети (Bitcoin и др.)
добавляют всё это поверх той же базовой механики.
