UNANIMOUS СКЕЛЕТ (все 7)
============================================================
Аддитивный O(n)-preflight на входе analyze(), ДО scan_signs/sequence (файлы sequence под
CI-пином, ноль правок). ОДИН проход-взвешивание: bytes + счёт класса-138 + доля доминантного
знака + триггер-счётчики (+ script-profile видимого текста, 3/7). ДВУХЪЯРУСНО: сигнал (анализ
продолжается + DENSITY_ANOMALY-витнес; ГОЛЫЙ pass при высоком счёте ЗАПРЕЩЁН → закрывает
измеренную дыру флуд→pass) / свёртка (ОДНА HOLD-сводка, не N подсветок, не авто-блок,
hold_pending_review = рекомендация человеку). Отвергнуть byte-only И density-only. Режим A
только; B/C — отдельные фронты; O1 — другой слой (density-факт может позже питать O1).
Тройной+ acceptance: ZWSP 21/21 + mutation 5/5 + oracle с НЕИЗМЕННЫМИ ожиданиями + FP-корпус
честного ввода + flood-bounce + mutation-батарея самого рубежа. Числа — ФОРМУЛОЙ поверх
замера (T ≥ ~10× max честного; T_count ≤ sqrt(work_budget/измеренный k)); benchmark
threshold−1/0/+1 обязателен.

КОНСЕНСУС 5/6 ПО G3 (Qwen — выброс)
============================================================
G3 = рубеж-ПЕРВЫМ + фикс O(n²) (`_detect_context_at`/`_find_literal_matches` → предвычислить/
мемоизировать общие факты один раз, БЕЗ смены ветвления) как ОТДЕЛЬНЫЙ/параллельный гейт-круг,
НИКОГДА не прицепом к рубежу (трогает ВЕРИФИЦИРОВАННЫЙ relation-путь → свой differential-гейт
«семантика не изменилась»). CUT G3a-голый (чуть-ниже-T всё ещё O(T²)). CUT G3c (Qwen: свои же
пороги впускают измеренный 8.3с-кейс). Оттенок: «рубеж закрывает DoS сейчас» (Kimi/Grok/Gemini)
vs «фикс нужен для полного закрытия» (OpenAI) — по существу согласны, спор в формулировке.

ЗАКРЫТИЯ KIMI (брать — архитектурно обоснованы)
============================================================
G9. DECODER-DESYNC (Kimi-only, 1/5, но обоснована и ложится на байт-якорь): если рубеж
  декодирует вход ИНАЧЕ, чем sequence-слой (битый UTF-8/overlong/суррогаты) — атакующий прячет
  членов класса от счётчика, показывая анализу. ЗАКРЫТИЕ: счёт класса-138 по UTF-8 БАЙТ-
  ПАТТЕРНАМ (E2 80 8B…) либо строго тем же декодером; mutation-кейс обязателен.
G10. SMOKESCREEN (подтверждён 2/5: Kimi закрывает, Qwen независимо заметила но приняла как
  компромисс — неверно): флуд как дымзавеса (6000 невидимых + 40 видимых фишинга в хвосте);
  голая свёртка ПРЯЧЕТ нагрузку. ЗАКРЫТИЕ: при свёртке анализ ВИДИМОЙ ПРОЕКЦИИ (strip класса →
  производный вид, позиции в orig, пометка PROJECTION); плотный флуд оставляет МАЛУЮ проекцию →
  анализ дёшев. «strip чтобы УВИДЕТЬ, не решать» (_demask). НЕ принимать «маска-под-флудом не
  ловится» как компромисс (ошибка Qwen).

============================================================
СВОД v3 — РАЗВИЛКИ ПОД АВТОРА (не усреднять; рекомендации координатора)
============================================================
1. ЗАЩИТА КОРОТКОГО ВВОДА: структурный пол — count-floor (Kimi, конъюнкция count И ratio) ИЛИ
   length-floor L_min (Gemini). ОТВЕРГНУТЬ голую дизъюнкцию без пола (Grok/Qwen — хрупко на
   коротком плотном вводе). Рекомендация: структурный пол (L_min проще).
2. ЛИМИТИРУЕМАЯ ВЕЛИЧИНА: триггер-aware (Kimi — квадратика триггер-обусловлена; делает рубеж-
   один достаточным по бюджету) + байт как backstop. Рекомендация: триггер-aware + пол.
3. БАЙТ-ПОТОЛОК: свободный backstop ~64КБ–сотни КБ (синтез 64КБ / Kimi / твой черновик «десятки
   КБ честного») vs тугой 8–16КБ (Grok/GPT/Qwen — риск FP на длинной честной вставке).
   Рекомендация: свободный backstop (байт — наименее важный cap).
4. SCRIPT-PROFILE: модулировать порог по скрипту видимого текста (Kimi/GPT/синтез — CJK/Thai-
   безопасно) vs плоский (Grok/Gemini/Qwen). Рекомендация: script-profile.
5. G6 GUARD-CAP: держать раздельно/report-only (GPT/Kimi/Grok/Qwen = 4) vs поглотить в рубеж
   (Gemini = 1). Рекомендация: РАЗДЕЛЬНО (4/5 + дисциплина: class_guard имеет свой shadow-oracle;
   общая КОНСТАНТА-семья допустима, общая роль — нет).
6. G3-ФОРМУЛИРОВКА: «рубеж закрыл DoS» vs «нужен фикс для закрытия» — все (кроме Qwen) согласны,
   что фикс = отдельный гейт-круг; спор только в слове «закрыто».

ОТВЕРГНУТО (по ходу): голый байт-потолок; голая плотность/дизъюнкция-без-пола; witness-после-
sequence; N подсветок вместо сводки; PASS-после-abort; «resource-limit = доказанная атака»;
оконный скан первых 4КБ (обход префиксом); «фикс локален, путь не трогает» (занижает G3b-риск);
принять smokescreen как компромисс.
