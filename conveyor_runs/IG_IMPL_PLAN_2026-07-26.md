============================================================
1. ТОЧКА ИНТЕГРАЦИИ (из §1/§0 решения)
============================================================
- Новый модуль `input_guard.py` (English-only код). Функция `input_guard_scan(text) -> IGReport`.
- Вызов ПЕРВОЙ операцией в `msl_mip_runtime.analyze()`, ДО `scan_signs`/`process_sequence`.
- sequence-файлы под CI-пином (НОЛЬ правок; уже near-linear после D-ONSQ-FIX). НЕ вызывать
  `_detect_context_at`/`_find_literal_matches`/`_demask` из рубежа (звать хотспот = свой DoS).
- При T_collapse: `sequence_output = NOT_RUN`, анализируется только ВИДИМАЯ ПРОЕКЦИЯ (G10).

============================================================
2. ОДИН O(n)-ПРОХОД (взвешивание; §2 решения)
============================================================
Единственный проход по text, без regex/аллокаций/вызовов sequence; 10МБ < 50мс; early-abort при
доказанной патологии. Считает за проход:
- byte-anchor: счёт класса-138 по UTF-8 БАЙТ-ПАТТЕРНАМ (E2 80 8B и т.д.) — G9 decoder-desync
  (снисходительный декодер видит больше канонического счётчика);
- class-138 count (Cf∧DI) — тем же байт-якорем;
- dominant_share: доля самого частого кодпоинта;
- trigger_total: невидимые + слэши + sequence-роль-символы (маски карт);
- script-profile видимого текста (ASCII/машинный → базовый порог; CJK/Thai/Arabic → поднятый).

============================================================
3. РЕШЕНИЕ (двухъярусно, конъюнктивно, script-модулированно; §3)
============================================================
- T_signal (count>N И ratio>%): анализ ПРОДОЛЖАЕТСЯ + `DENSITY_ANOMALY` (ВОЗМОЖНАЯ/queue);
  ГОЛЫЙ pass при count>N ЗАПРЕЩЁН (закрывает измеренную дыру флуд→pass).
- T_collapse (count>M И ratio>% ИЛИ trigger_total>K ИЛИ dominant_share>S ИЛИ bytes>BYTE_BACKSTOP):
  свёртка → одна сводка `INGESTION_HOLD_SUMMARY` (РЕАЛЬНАЯ/hold — рекомендация) + анализ ВИДИМОЙ
  ПРОЕКЦИИ (strip класса → производный вид, позиции в orig, пометка PROJECTION) вместо голой свёртки.
- ЖЁСТКИЙ вычислительный cap — профиль-независим (профиль-spoof CJK-паддингом всё равно бьётся о него).

============================================================
4. КАЛИБРОВКА ПОРОГОВ (ФОРМУЛОЙ поверх замера; §6)
============================================================
- T (плотность) ≥ ~10× max честного корпуса + запас батареи.
- T_count ≤ sqrt(work_budget / измеренный k) — k из профиля (после D-ONSQ-FIX relation-путь O(n),
  так что k меньше — пере-снять на живом ядре).
- BYTE_BACKSTOP свободный (~64КБ, порядок сотен КБ) — не тугой (тугой = FP на честном длинном).
- benchmark threshold −1/0/+1 обязателен. НЕ «на глаз».

============================================================
5. КОНТРАКТ ОТЧЁТА (anti-masquerade; §5)
============================================================
top-level поле `input_guard { schema_version, mode:"A", status: OK|DENSITY_SIGNAL|
  INGESTION_HOLD_SUMMARY, reason_class, action_recommendation, counters{class138, dominant_share,
  trigger_total, bytes}, sampled_offsets, projection_verdict, truncated }`.
При short-circuit: `sequence_output = NOT_RUN`, `content_risk = NOT_ASSESSED`.
RESOURCE_LIMIT_EXCEEDED ≠ ДОКАЗАННАЯ АТАКА (текст в reason_class).

============================================================
6. ACCEPTANCE-ГЕЙТ (ПЕРЕД мержем; §8 — ОБЯЗАТЕЛЬНО)
============================================================
Новый `tests/gate_input_guard_mode_a.py` + расширение существующих:
- ZWSP 21/21 + mutation 5/5 + oracle с НЕИЗМЕННЫМИ ожиданиями (рубеж НЕ трогает суб-порог входы);
- DELTA-CENSUS: меняются РОВНО авторизованные ячейки (флуды), всё честное — бит-идентично;
- FP-корпус: 40Б/65Б/200Б/2КБ/CJK/Persian/код — НЕ должны свернуться (честный длинный проходит);
- flood-bounce < 0.1с на 13 атак до 10М символов;
- guard-mutation-батарея: off-by-one, byte/char, decoder-desync (G9), overflow, smokescreen→проекция
  (G10), оконный-скан-запрещён;
- SPY: при hard-bounce счёт вызовов `_detect_context_at`/`_find_literal_matches`/`_demask` = 0.

============================================================
7. ГРАНИЦЫ / НЕ В ЭТОМ ЗАХОДЕ
============================================================
- Границы: полный O(n)-проход по ВСЕЙ строке (не оконный первых 4КБ — обход честным префиксом).
- НЕ трогаем: класс-138, три уровня, witness-рамку, sequence-путь (CI-пин).
- Режимы B (файлы/zip) и C (потоки) — отдельные КРУПНЫЕ фронты. rate-limiting — инфраструктура.
- O(n²)-фикс sequence — уже сделан (D-ONSQ-FIX); V3 (claimed) — отдельный круг.
