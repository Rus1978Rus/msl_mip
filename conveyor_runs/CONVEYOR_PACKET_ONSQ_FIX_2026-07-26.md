  по ВСЕМУ токену — `_strip_label_invisibles` (339: `join(... if not _is_domain_label_invisible(ch))`)

  Общие факты токена (его stripped-форма, domain-prefix, контекст) ОДИНАКОВЫ для всех вхождений в
  этом токене, но пересчитываются заново каждый раз.

ЦЕЛЬ: та же тропа, near-linear, БЕЗ изменения ни одного вердикта/офсета/reason (ZERO-DELTA),
  доказано differential-гейтом. НЕИЗМЕРИМО здесь: худший вход в проде (зависит от рубежа Mode A).

ЭРРАТУМ_1 (по leg-1 GPT-5.6, обосновано кодом; замер §1 не затронут): выше сказано «контекст
  токена одинаков для всех вхождений» — это НЕВЕРНО про detected_context. `_detect_context_at`
  offset-СПЕЦИФИЧЕН (scheme_at ищется только до текущего rel; URL-компонент — сравнением rel с
  границами authority/query/fragment; had_leading_structural — на префиксе до rel; left/right_part —
  split вокруг ИМЕННО этой маски; host-span — по projected-позиции этой маски). ОБЩИЕ = ФАКТЫ
  ТОКЕНА (границы, mask-алфавит, полностью demasked-токен, проекция, позиции ://@/?#, domain-runs,
  TLD-state, prefix/suffix-суммы, source→projected карта). Значит фикс = «токен→общие факты» +
  «(факты, offset)→контекст», НЕ «токен→один контекст». Измеренная §1-атрибуция (доминанта
  _is_domain_label_invisible O(m²), корень = пересчёт всего токена на вхождение) — верна.

============================================================
V1. «ОБЩИЕ ФАКТЫ ОДИН РАЗ». Считать stripped-форму/domain-prefix/контекст токена ОДНОКРАТНО и
    переиспользовать для всех вхождений в нём: (A) мемоизация по токену (dict token→facts);
    (B) предвычисление фактов по токенам ДО цикла вхождений; (C) реструктура — `_detect_context_at`
    принимает готовые факты. Какой доказуемо эквивалентен и проще? Убедиться, что «токен» и его
    границы идентичны текущим (иначе дельта).
V2. МИКРО-ЦЕНА `_is_domain_label_invisible` (315). Чистая функция от ch (Cf / bidi-control /
    DI-extra / braille). Кэш по кодпоинту (lru_cache или предвычисленный frozenset/таблица) —
    zero-delta по построению. Брать? Взаимодействие с V1 (если V1 убирает O(m²)-вызовы, нужен ли V2).
V3. `claimed`-ПОКРЫТИЕ O(m²) (143). Интервальная структура / монотонный указатель (матчи по
    возрастанию) вместо `any(...)`. Доминанта ли для НЕ-невидимок (напр. slash-флуд)? Чинить в этом
    круге или отдельным? Доказать эквивалентность (тот же набор covered).
V4. DIFFERENTIAL-ГЕЙТ. Каким корпусом доказываем ZERO-DELTA: батареи ZWSP/ZWJ/BOM + FP-корпус +
    широкий не-патологический корпус + DoS-корпус — сравнение ПОЛНОГО отчёта (вердикт, effective,
    witness, uncarded, reasons, offsets, ordering, projection, сериализация), не только вердикта.
    Порог «быстрее» (напр. 2000-бег < X мс; ×2 удвоения ≤ ×~2 времени, не ×4). Spy на счётчики вызовов.
V5. ОФСЕТЫ/ПОРЯДОК. Не меняет ли правка порядок/офсеты в отчёте (delta-census поймает)? Любая
    смена порядка reasons = дельта, даже при том же вердикте.
V6. ОБЛАСТЬ. Чинить только доминанту (V1+V2: `_is_domain_label_invisible` через общие-факты + per-cp
    кэш) в этом круге, а `claimed` (V3) отдельным? Или всё сразу? Минимально-достаточно для near-linear.
V-OTHER: измерение вне V1–V6; если подход неверен (напр. долг снимается только реструктурой
    stage-барьера, а не мемоизацией) — сказать прямо (LOOPHOLE). Подтвердить/опровергнуть, что
    рубеж Mode A этот фикс НЕ заменяет (2000<cap, но 24с).
