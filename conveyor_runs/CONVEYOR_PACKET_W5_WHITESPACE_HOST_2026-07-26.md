  ПРОБЕЛЫ-ДВОЙНИКИ (NBSP U+00A0, NARROW NBSP U+202F, FIGURE SPACE U+2007, EN QUAD U+2000,
  IDEOGRAPHIC SPACE U+3000, …) — категория Unicode **Zs (Space_Separator)**, а НЕ Cf. Надзорный
  класс-138 = Cf ∧ Default_Ignorable, поэтому эти пробелы в него НЕ входят, и эскалация host-разрыва
  D-INV-GEN (замкнутая на класс-138) их НЕ ловит. Тот же таксономический пробел, что у VS (Mn,
  закрыт AUTHOR_DECISION_20260726_D-W4-VS-AXIS) — только для класса Zs. Судим ДИЗАЙН оси ДО кода:
  трогает верифицированный host-путь (батареи ZWSP 21/21, ZWJ/BOM 11/11).

§1. ФАКТ (измерено на живом ядре 2026-07-26 — данные, НЕ на голосование; спорить только замером)
============================================================
КОРЕНЬ (unicodedata + _monitored_138_set): NBSP U+00A0, NNBSP U+202F, FIGURE SPACE U+2007,
  EN QUAD U+2000, IDEOGRAPHIC SPACE U+3000 = категория **Zs**, in_class138 = **False**. Граница:
  WORD JOINER U+2060 = Cf, in_class138 = True (он покрыт). Пробел = НЕ Cf → вне 138 по построению.

ТЕКУЩЕЕ ПОВЕДЕНИЕ (BEFORE), analyze() на живом ядре:
  вход                                  semantic  effective            witness
  paypal<NBSP>.com   (host-разрыв)         pass      pass               WITNESS_PRESENT
  goog<NBSP>le.com   (host mid-label)      pass      pass               WITNESS_PRESENT
  pay<NNBSP>pal.com  (host-разрыв)         pass      pass               WITNESS_PRESENT
  КОНТРОЛЬ paypal<ZWSP>.com (карточный)    hold      hold               NONE
  ВЫВОД: пробел-двойник, РВУЩИЙ host-метку (домены не содержат пробелов), сегодня → pass (максимум
    witness), тогда как тот же разрыв карточным ZWSP → hold. Silent-ish дыра в машинном контексте.

ЛЕГИТ (должны остаться ЧИСТО): `Mr.<NBSP>Smith` (проза) → pass, attn=NONE; `mot<NNBSP>: x`
  (французская типографика — NNBSP обязателен перед `:;!?`) → pass, attn=NONE. Пробел-двойник в
  ПРОЗЕ / типографике легитимен; нелегитимен он в СТРУКТУРЕ (host-метка).
НЕИЗМЕРИМО: реальная частота NBSP-host-атак vs легит-i18n-типографики в живом тексте — без корпуса
  честно не оценить.

§2. ВОПРОС РЕВЬЮЕРАМ
============================================================
Выбрать ДИЗАЙН оси «пробел-двойник в host» так, чтобы: эскалировать пробел, рвущий host-метку
  (сейчас pass); НЕ будить легит-типографику (french NNBSP, NBSP в прозе); держать witness-рамку
  (уровень=рекомендация, никакого авто-strip); НЕ сломать батареи (пробелы вне ZWSP/ZWJ/BOM — но
  любое изменение host-классификации = delta-census по-ячеечно); честно назвать остаток. По каждому
  V1–V6 — позиция + «где дыра».
