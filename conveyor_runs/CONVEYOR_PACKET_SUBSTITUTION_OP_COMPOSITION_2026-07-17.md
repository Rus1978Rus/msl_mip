§1. ФАКТ (не на ревью — данные в теле)
============================================================
- ЗАКРЫТО (D-SUBSTITUTION-OP, 2026-07-17, commit 9be280e, STATUS DRAFT): op = НАБОР
  операций per-мишень, НЕ одна op (счёт круга 4:0 среди 4 реальных вердиктов). op —
  явный аргумент compute-пола: substitutable(X,Y,op). НЕ пересматривается.
- НАБОР ЗНАКОВ ФИКСИРОВАН = поднадзорный класс 138 (Cf∧Default_Ignorable). Разбивка:
  PURE 23 / DIRECTIONAL 12 / TAG 97 / DEPRECATED 6 = 138.
- ОТКРЫТО (O2b, ЭТОТ круг): КАКИЕ именно операции op_i входят в канонический набор
  ПО УМОЛЧАНИЮ, под какие мишени, и сколько их минимально достаточно.
- ФАКТЫ ПО ПРОГОНУ (tests/verify_substitution_op.py, не claim — asserts в репо):
    * OP-2 (Cf-strip) ≡ OP-3 (DI-strip) внутри 138 — ОДНА операция «strip-весь-класс»;
    * полный граф class-strip = C(138,2) = 9453 неупорядоченные пары («всё со всем» =
      шум для witness, нет приоритизации);
    * NFC и NFKC меняют 0/138 — нормализация НЕ трогает ни один знак класса, т.е. как
      class-strip op НЕ работает (0 рёбер); значима только вне 138;
    * OP-1 zero-width strip НЕ трогает 12 directional (bidi≠BN) — мимо Trojan Source.
  НЕ проверено прогоном (честно): IDNA/UTS-46 (нет чистого UTS-46 в stdlib) —
    reviewer-claimed, НЕ run-verified.

============================================================
§3. КАНДИДАТЫ op_i (из raw прошлого круга + прогон)
============================================================
Для каждой: мишень; что реально ловит; статус по прогону/расколу.

C1. IDNA-MAPPING / UTS-46 — мишень: ДОМЕНЫ / URL (регистраторы, браузеры,
    антифишинг). Ловит: доменные подмены невидимыми при mapping/validation. Статус:
    сильный кандидат (R1,R2,R3,R4). НЕ run-verified здесь — ревьюер: подтверди, что
    IDNA действительно убирает/маппит члены класса, а не просто запрещает.
C2. BIDI-CONTROL-DETECTION — мишень: ИСХОДНЫЙ КОД / имена файлов / review-UI
    (Trojan Source, CVE-2021-42574). ВНИМАНИЕ: это op ДЕТЕКЦИИ (сравнение логического
    и визуального порядка), НЕ strip — набор ГЕТЕРОГЕНЕН (strip-ops + detection-op).
    Ревьюер: согласен ли держать detection-op в одном наборе со strip-op, или это
    отдельная ось?
C3. TAG-STRIP / TAG-WITNESS — мишень: ВХОДЫ LLM / agent-метаданные (E00xx инъекции).
    Ловит: 97 TAG-членов класса. Кандидат (R1, R4).
C4. ZERO-WIDTH STRIP (OP-1) — мишень: наивные санитайзеры логинов/полей. РАСКОЛ 3/2
    (держать/убрать). Прогон: «zero-width» не UCD-свойство, границу задавать списком;
    мимо directional/tag. Ядро-кандидат PURE/BN=23, наивный список ~5-7. Ревьюер:
    судьба OP-1 + если держать — как зафиксировать границу «zero-width».
C5. Cf-STRIP / ПОЛНЫЙ CLASS-STRIP (OP-2≡OP-3) — мишень: строгие нормализаторы /
    агрессивные санитайзеры / часть LLM-защит. Прогон: полный граф 9453 = «всё со
    всем» = шум. Кандидат ТОЛЬКО как СТРОГИЙ/тестовый профиль (не приоритизация).
    Ревьюер: держать как один op_i для строгих мишеней или убрать как бесполезный
    для witness?
C6. UAX-31 IDENTIFIER-PROFILE — мишень: идентификаторы / логины / имена переменных.
    Кандидат (R1). Часто = zero-width-strip или запрет Cf в контексте.
C7. НОРМАЛИЗАЦИЯ (NFC/NFKC) — мишень: пароли / идентификаторы. ПРОГОН: 0/138 —
    на классе тождество, 0 рёбер. Включена в §3 как ЯВНО ОТВЕДЁННЫЙ кандидат: моделирует
    реальную мишень, но как class-strip op НЕ работает. Ревьюер: подтверди отвод или
    оспорь (если видишь член класса, который NFKC реально сворачивает).
C-OTHER (открытая графа): ревьюер предлагает свою op_i под названную мишень;
    UTS-39 skeleton/confusable-fold — ВИЗУАЛЬНАЯ ось (R1 сам пометил «adjacent, не
    ядро»), в набор невидимой подмены НЕ входит, но назови, если считаешь иначе.

рекомендация, не статус.
