§0. ТИП КРУГА — BY_SPEC (СЛЕПАЯ НОГА) + ПРАВИЛА СЛЕПОТЫ
============================================================
Двуногая симуляция: BY_SPEC (эта нога — предсказание по ОПИСАНИЮ) × BY_CODE (уже снята —
измеренная проба). После сбора ответов — RECONCILE двух ног; расхождение BY_SPEC↔BY_CODE
= карточка НЕДООПРЕДЕЛЕНА (описание не ведёт к поведению).

============================================================
§2. СЕКЦИЯ ZWJ (U+200D)
============================================================
ДАНО (свойства знака — и только они):
  - Unicode: U+200D ZERO WIDTH JOINER; General_Category = Cf (формат); невидим,
    нулевая ширина; Default_Ignorable = Yes; Join_Control = YES.
  - Что делает: СКЛЕИВАЕТ соседние знаки (требует соединённой формы).
  - Где легитимен по стандарту: эмодзи-секвенции (составные эмодзи), арабское/индийское
    письмо (курсивное соединение форм).

ОЦЕНИТЬ (для КАЖДОГО контекста — уровень §1 + обоснование + «как обойдут»):
  Z1. ZWJ внутри эмодзи-семьи (составной эмодзи).
  Z2. ZWJ между ЛАТИНСКИМИ буквами внутри host (имени домена).
  Z3. ZWJ внутри персидского/арабского слова.
  Z4. ZWJ внутри токена / идентификатора (машинная строка).
  Z5. ZWJ в свободном тексте (проза).

============================================================
§3. СЕКЦИЯ BOM (U+FEFF)
============================================================
ДАНО (свойства знака — и только они):
  - Unicode: U+FEFF ZERO WIDTH NO-BREAK SPACE; современная основная роль — BYTE ORDER
    MARK (маркер порядка байт / начала потока); General_Category = Cf; невидим, нулевой
    ширины; Default_Ignorable = Yes; Join_Control = NO.
  - Что делает: СЛУЖЕБНЫЙ МАРКЕР потока/файла. Легитимность ПОЗИЦИОННАЯ — как ПЕРВЫЙ
    символ файла/потока.
  - Старая функция (zero-width no-break space) ДЕПРЕКЕЙТНУТА с Unicode 3.2 (заменена
    на U+2060 WORD JOINER) — то есть в СЕРЕДИНЕ текста легитимной функции почти нет.

ОЦЕНИТЬ (для КАЖДОГО контекста — уровень §1 + обоснование + «как обойдут»):
  B1. Ведущий BOM в начале файла / текста (первый символ).
  B2. BOM в СЕРЕДИНЕ host (внутри имени домена).
  B3. BOM в СЕРЕДИНЕ токена / email-локальной части.
  B4. Ведущий BOM ПЕРЕД целым доменом (домен идёт сразу за BOM).
  B5. Parser-desync: BOM там, где часть парсеров его срежет, часть оставит (рассинхрон
      представления между системами).
