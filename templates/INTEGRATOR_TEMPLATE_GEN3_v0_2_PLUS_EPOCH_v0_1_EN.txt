ARCHITECTURE_PRINCIPLES
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ MODULE
MODULE analyzes the sign and produces OUTPUT_STATUS
INTEGRATOR receives OUTPUT_STATUS and makes a runtime decision
INTEGRATOR does not override sign semantics — only adapts the action
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ RUNTIME
INTEGRATOR is an adapter layer, not a terminal system
INTEGRATOR is not a parser, validator, product, or policy
Terminal actions (BLOCK, DELETE, BAN, NOTIFY) are the responsibility of RUNTIME, not INTEGRATOR
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ POLICY_ENFORCER
INTEGRATOR translates the MODULE signal into a RUNTIME action
INTEGRATOR does not set policy independently
Policy (what is considered acceptable) is defined by RUNTIME_OWNER, not INTEGRATOR_TEMPLATE
INTEGRATION_CHAIN:
SIGN_CORE_CARD → MODULE_INSTANCE → [SEQUENCE_MODULE_INSTANCE → SEQUENCE_INTEGRATOR] → INTEGRATOR_INSTANCE → RUNTIME
CONFIGURATION_DRIVEN:
INTEGRATOR logic is not hardcoded for a specific runtime
Adaptation rules are loaded from RUNTIME_POLICY_MAP at initialization
Changing runtime = connecting a different policy, not rewriting INTEGRATOR
ZONE_PASSTHROUGH:
INTEGRATOR receives ZONE information from MODULE OUTPUT_STATUS
INTEGRATOR does not recalculate ZONE — only uses it for routing
ZONE_3 requires EPOCH-aware routing (accounting for ACTIVE_EPOCH when selecting action)

3. PROCESSING_PIPELINE
PIPELINE_STAGES: 6 processing stages (STAGE_1–6)
STAGE_1: INPUT_VALIDATION
INPUT: MODULE_OUTPUT + RUNTIME_POLICY
ACTION: input data validation
CHECK: MODULE_OUTPUT contains all required fields
CHECK: EFFECT_FIELDS_STATUS = VALID (if INVALID → critical card error)
CHECK: FORBIDDEN_ACTION = MODULE_MUST_NOT_BLOCK_DIRECTLY (INTEGRATOR did not receive direct blocking from MODULE)
CHECK: RUNTIME_POLICY is loaded and compatible with INTEGRATOR_TEMPLATE
FAILURE: ERROR_TYPE = MODULE_OUTPUT_INVALID or POLICY_NOT_FOUND
STAGE_2: RISK_ROUTING
INPUT: validated MODULE_OUTPUT
ACTION: determination of processing route by RISK_LEVEL
ROUTING:
RISK_LEVEL = NONE → STAGE_3a (PASS_THROUGH)
RISK_LEVEL = LOW → STAGE_3a (PASS_THROUGH) or STAGE_3b (MONITOR) per POLICY
RISK_LEVEL = MEDIUM → STAGE_3b (MONITOR) or STAGE_3c (FLAG) per POLICY
RISK_LEVEL = HIGH → STAGE_3c (FLAG) or STAGE_3d (ESCALATE) per POLICY
RISK_LEVEL = CRITICAL → STAGE_3d (ESCALATE)
ZONE_ROUTING: if ACTIVE_EPOCH ≠ NOT_APPLICABLE → apply ZONE_3_EPOCH_RULES
STAGE_3a: PASS_THROUGH
INPUT: LOW/NONE RISK MODULE_OUTPUT
ACTION: pass-through to runtime without special actions
RUNTIME_ACTION_REQUEST: INFO (default)
NOTE: INTEGRATOR does not add risk, does not change INTERPRETATION
STAGE_3b: MONITOR
INPUT: LOW/MEDIUM RISK MODULE_OUTPUT
ACTION: pass-through to runtime with monitoring flag
RUNTIME_ACTION_REQUEST: MONITOR
NOTE: runtime decides how to respond to the monitoring flag
STAGE_3c: FLAG_FOR_REVIEW
INPUT: MEDIUM/HIGH RISK MODULE_OUTPUT or AMBIGUITY_FLAG = YES
ACTION: forming a request for human review
RUNTIME_ACTION_REQUEST: FLAG_FOR_REVIEW or HUMAN_REVIEW
AMBIGUITY_HANDLING: if AMBIGUITY_FLAG = YES → ESCALATION_CHAIN.activate()
NOTE: INTEGRATOR does not make a final judgment — passes to human
STAGE_3d: ESCALATE
INPUT: HIGH/CRITICAL RISK MODULE_OUTPUT
ACTION: escalation via ESCALATION_CHAIN
RUNTIME_ACTION_REQUEST: HUMAN_REVIEW / ESCALATE (specific action is determined by RUNTIME_OWNER)
FORBIDDEN: INTEGRATOR cannot independently issue a BLOCK/BAN/DELETE verdict
NOTE: final action is the responsibility of RUNTIME and its policy
STAGE_4: EPOCH_CONTEXT_INJECTION
NOTE: EPOCH_CONTEXT is audit metadata for auditability, not a change of sign semantics.
INPUT: result of STAGE_3 + ACTIVE_EPOCH (if ZONE_3)
ACTION: enriching OUTPUT_DECISION with epoch context
LOGIC: if ACTIVE_EPOCH ≠ NOT_APPLICABLE → add EPOCH_CONTEXT to OUTPUT_DECISION
ZONE_3_EPOCH_RULES: apply special runtime rules for this epoch (if specified)
PURPOSE: ensure decision auditability — "why exactly this action for 💀 in EPOCH_3"
NOTE: INTEGRATOR does not change RISK_LEVEL — only documents context
STAGE_5: DECISION_ASSEMBLY
CHECK: INTERPRETATION from MODULE_OUTPUT is unchanged (MUTATION_04 check)
INPUT: all results from STAGE_1–4
ACTION: assembly of final OUTPUT_DECISION
STRUCTURE: see OUTPUT_INTERFACE
VALIDATION: verification of completeness of all fields
CHECK: INTEGRATOR_LIMITATION_NOTE is present in OUTPUT_DECISION
RETURN: OUTPUT_DECISION or ERROR_STATUS
STAGE_6: AFTER_RUN_CLEANUP
INPUT: OUTPUT_DECISION or ERROR_STATUS
ACTION: check for absence of residue (AFTER_RUN_RESIDUE: FORBIDDEN)
CHECK: temporary data is cleared
CHECK: RUNTIME_POLICY is not cached between sessions (SESSION_ONLY)
CHECK: logs passed to runtime (if required)
OUTPUT: CLEANUP_CONFIRMATION
NOTE: STAGE_6 does not change OUTPUT_DECISION

4. RUNTIME_ADAPTATION_MODEL
RUNTIME_TYPES (examples — non-exhaustive list):
DISCORD_MODERATION: reaction to messages in chats
CONTENT_FILTER_API: REST API for content filtering
NLP_PIPELINE: embedding into NLP text processing
CHATBOT_SAFETY: safety of dialogue systems
EMAIL_SCANNER: email analysis
DOCUMENT_ANALYZER: document analysis
ADAPTATION_RULES:
RULE_1: each RUNTIME_TYPE has its own RUNTIME_POLICY with ACTION_MAP
RULE_2: ACTION_MAP maps (RISK_LEVEL, RECOMMENDED_ACTION) → RUNTIME_ACTION_REQUEST
RULE_3: INTEGRATOR_INSTANCE does not know RUNTIME implementation details — only its ACTION_MAP
RULE_4: one INTEGRATOR_TEMPLATE can spawn INTEGRATOR_INSTANCE for different RUNTIME_TYPE
RULE_5: changing runtime = replacing RUNTIME_POLICY, not rewriting INTEGRATOR
ACTION_MAP_EXAMPLE_STATUS: ILLUSTRATIVE / NON_NORMATIVE
ACTION_MAP_EXAMPLE (illustrative, non-normative):
NOTE: Example action names do not define required runtime behavior. Specific RUNTIME_ACTION are determined by RUNTIME_OWNER.
RISK_LEVEL=NONE, RECOMMENDED_ACTION=INFO → RUNTIME_ACTION_REQUEST: pass
RISK_LEVEL=LOW, RECOMMENDED_ACTION=MONITOR → RUNTIME_ACTION_REQUEST: log_only
RISK_LEVEL=MEDIUM, RECOMMENDED_ACTION=FLAG_FOR_REVIEW → RUNTIME_ACTION_REQUEST: queue_for_review
RISK_LEVEL=HIGH, RECOMMENDED_ACTION=HUMAN_REVIEW → RUNTIME_ACTION_REQUEST: hold_pending_review
RISK_LEVEL=CRITICAL, RECOMMENDED_ACTION=ESCALATE_TO_INTEGRATOR → RUNTIME_ACTION_REQUEST: immediate_escalation
RUNTIME_ACTION_EXECUTION: FORBIDDEN_FOR_INTEGRATOR_TEMPLATE
NOTE: INTEGRATOR emits an action request for RUNTIME. RUNTIME decides and executes. INTEGRATOR_TEMPLATE does not execute BLOCK / DELETE / BAN / NOTIFY.
NOTE: specific RUNTIME_ACTION are determined by RUNTIME_OWNER, not INTEGRATOR_TEMPLATE
ZONE_3_EPOCH_ROUTING:
PURPOSE: different epochs of one sign may require different actions in one runtime
EXAMPLE: 💀 in EPOCH_1 (literal death) vs EPOCH_3 (laughter/irony) — different ACTION in medical vs youth runtime
LOGIC: ZONE_3_EPOCH_RULES[ACTIVE_EPOCH][RUNTIME_ID] → EPOCH_SPECIFIC_ACTION_OVERRIDE
EPOCH_CONTEXT_INJECTION_LIMIT:
ZONE_3_EPOCH_RULES may affect RUNTIME_ACTION_REQUEST only through RUNTIME_POLICY.
ZONE_3_EPOCH_RULES must not modify:
INTERPRETATION
RISK_LEVEL_RECEIVED
ACTIVE_EPOCH
MODULE_OUTPUT fields
FORMULA: EPOCH_POLICY_ROUTING ≠ SEMANTIC_REINTERPRETATION
ZONE_3_EPOCH_ROUTING_FALLBACK: In the absence of OVERRIDE — passthrough (standard ACTION_MAP is used).
NOTE: action override is possible only through explicit RUNTIME_POLICY configuration, not by default.

RUNTIME_ID: runtime identifier

RUNTIME_ACTION_REQUESTED: requested / recommended action for runtime
EPOCH_CONTEXT: active epoch (if applicable)

POLICY: logging according to RUNTIME_OWNER audit policy; persistent logging is not required by INTEGRATOR_TEMPLATE
LIMITATION: if AFTER_RUN_RESIDUE: FORBIDDEN — logs are not saved between sessions
CONFIGURATION_RULES:
RULE_1: INTEGRATOR cannot operate without a loaded RUNTIME_POLICY
RULE_2: INTEGRATOR cannot use MODULE_OUTPUT with EFFECT_FIELDS_STATUS = INVALID
RULE_3: INTEGRATOR must check compatibility of RUNTIME_POLICY with INTEGRATOR_TEMPLATE version
RULE_4: INTEGRATOR passes all ERROR_STATUS to LOGGING_INTERFACE of the current session; persistent logging is determined by RUNTIME_OWNER
RULE_5: INTEGRATOR does not cache RUNTIME_POLICY between sessions (SESSION_ONLY)
RULE_6: INTEGRATOR cannot execute BLOCK/BAN/DELETE.
RULE_6A: RUNTIME_POLICY may contain ACTION_REQUEST of type REQUEST_BLOCK / REQUEST_DELETE / REQUEST_BAN, if explicitly permitted by RUNTIME_OWNER.
RULE_6B: INTEGRATOR only passes ACTION_REQUEST. Actual execution remains with RUNTIME.
INVALID_POLICY: ACTION_MAP contains direct EXECUTE_BLOCK / EXECUTE_DELETE / EXECUTE_BAN without runtime-confirmation boundary.

6. ADVERSARIAL_COVERAGE — RUN CARD SEED
MIN_TOTAL_VECTORS: 12 (6 categories A-F, 2 per category)
CATEGORY_A: POLICY_MANIPULATION (2)
A1: Substitution of RUNTIME_POLICY_PATH — INTEGRATOR checks integrity of loaded policy. Path substitution is the responsibility of RUNTIME, not INTEGRATOR.
A2: Corrupted RUNTIME_POLICY — ACTION_MAP contains invalid actions (e.g., BLOCK directly)
CATEGORY_B: MODULE_OUTPUT_INJECTION (2)
B1: MODULE_OUTPUT with EFFECT_FIELDS_STATUS = INVALID — INTEGRATOR must reject, not apply
B2: MODULE_OUTPUT with FORBIDDEN_ACTION violated — MODULE passed direct action instead of recommendation
CATEGORY_C: RISK_ESCALATION_BYPASS (2)
C1: RISK_LEVEL = CRITICAL processed as NONE (skipping STAGE_3d)
C2: AMBIGUITY_FLAG = YES ignored — INTEGRATOR made a decision without escalation
CATEGORY_D: EPOCH_ROUTING_EXPLOIT (2)
D1: ZONE_3 sign processed without EPOCH_CONTEXT — decision made without considering epoch
D2: ACTIVE_EPOCH deliberately substituted in MODULE_OUTPUT to obtain a softer ACTION
CATEGORY_E: BOUNDARY_VIOLATION (2)
E1: INTEGRATOR independently issued a BLOCK verdict without ACTION_MAP — violation of RULE_6
E2: INTEGRATOR changed INTERPRETATION from MODULE_OUTPUT — violation of PASSTHROUGH principle
CATEGORY_F: SESSION_LEAK (2)
F1: RUNTIME_POLICY cached between sessions (violation of RULE_5: SESSION_ONLY)
F2: OUTPUT_DECISION from one session passed to another without reinitializing INTEGRATOR
ACTUAL_TOTAL_VECTORS: 12
COVERAGE_STATUS: SUFFICIENT (12 ≥ 12)
