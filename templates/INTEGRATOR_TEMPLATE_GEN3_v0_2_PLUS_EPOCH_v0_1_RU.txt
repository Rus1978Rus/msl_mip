ARCHITECTURE_PRINCIPLES
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ MODULE
MODULE анализирует знак и выдаёт OUTPUT_STATUS
INTEGRATOR получает OUTPUT_STATUS и принимает runtime-решение
INTEGRATOR не переопределяет семантику знака — только адаптирует действие
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ RUNTIME
INTEGRATOR — связующий слой, не конечная система
INTEGRATOR не является парсером, валидатором, продуктом, политикой
Конечные действия (BLOCK, DELETE, BAN, NOTIFY) — ответственность RUNTIME, не INTEGRATOR
CORE_PRINCIPLE: INTEGRATOR_TEMPLATE ≠ POLICY_ENFORCER
INTEGRATOR транслирует сигнал MODULE в действие RUNTIME
INTEGRATOR не устанавливает политику самостоятельно
Политика (что считать приемлемым) определяется RUNTIME_OWNER, не INTEGRATOR_TEMPLATE
INTEGRATION_CHAIN:
SIGN_CORE_CARD → MODULE_INSTANCE → [SEQUENCE_MODULE_INSTANCE → SEQUENCE_INTEGRATOR] → INTEGRATOR_INSTANCE → RUNTIME
CONFIGURATION_DRIVEN:
Логика INTEGRATOR не hardcoded для конкретного runtime
Правила адаптации загружаются из RUNTIME_POLICY_MAP при инициализации
Изменение runtime = подключение другой политики, не переписывание INTEGRATOR
ZONE_PASSTHROUGH:
INTEGRATOR получает ZONE-информацию из MODULE OUTPUT_STATUS
INTEGRATOR не пересчитывает ZONE — только использует для routing
ZONE_3 требует EPOCH-aware routing (учёт ACTIVE_EPOCH при выборе действия)

ERROR_TYPE:

ERROR_RESPONSE: INTEGRATOR должен вернуть ERROR_STATUS вместо OUTPUT_DECISION
ERROR_LOGGING: ошибка передаётся в LOGGING_INTERFACE текущей сессии. Persistent logging определяется RUNTIME_OWNER audit policy.

3. PROCESSING_PIPELINE
PIPELINE_STAGES: 6 этапов обработки (STAGE_1–6)
STAGE_1: INPUT_VALIDATION
INPUT: MODULE_OUTPUT + RUNTIME_POLICY
ACTION: валидация входных данных
CHECK: MODULE_OUTPUT содержит все обязательные поля
CHECK: EFFECT_FIELDS_STATUS = VALID (если INVALID → критическая ошибка карточки)
CHECK: FORBIDDEN_ACTION = MODULE_MUST_NOT_BLOCK_DIRECTLY (INTEGRATOR не получил прямой блокировки от MODULE)
CHECK: RUNTIME_POLICY загружена и совместима с INTEGRATOR_TEMPLATE
FAILURE: ERROR_TYPE = MODULE_OUTPUT_INVALID или POLICY_NOT_FOUND
STAGE_2: RISK_ROUTING
INPUT: валидированный MODULE_OUTPUT
ACTION: определение маршрута обработки по RISK_LEVEL
ROUTING:
RISK_LEVEL = NONE → STAGE_3a (PASS_THROUGH)
RISK_LEVEL = LOW → STAGE_3a (PASS_THROUGH) или STAGE_3b (MONITOR) по POLICY
RISK_LEVEL = MEDIUM → STAGE_3b (MONITOR) или STAGE_3c (FLAG) по POLICY
RISK_LEVEL = HIGH → STAGE_3c (FLAG) или STAGE_3d (ESCALATE) по POLICY
RISK_LEVEL = CRITICAL → STAGE_3d (ESCALATE)
ZONE_ROUTING: если ACTIVE_EPOCH ≠ NOT_APPLICABLE → применить ZONE_3_EPOCH_RULES
STAGE_3a: PASS_THROUGH
INPUT: LOW/NONE RISK MODULE_OUTPUT
ACTION: передача в runtime без специальных действий
RUNTIME_ACTION_REQUEST: INFO (по умолчанию)
NOTE: INTEGRATOR не добавляет риск, не изменяет INTERPRETATION
STAGE_3b: MONITOR
INPUT: LOW/MEDIUM RISK MODULE_OUTPUT
ACTION: передача в runtime с флагом мониторинга
RUNTIME_ACTION_REQUEST: MONITOR
NOTE: runtime решает, как реагировать на флаг мониторинга
STAGE_3c: FLAG_FOR_REVIEW
INPUT: MEDIUM/HIGH RISK MODULE_OUTPUT или AMBIGUITY_FLAG = YES
ACTION: формирование запроса на human review
RUNTIME_ACTION_REQUEST: FLAG_FOR_REVIEW или HUMAN_REVIEW
AMBIGUITY_HANDLING: если AMBIGUITY_FLAG = YES → ESCALATION_CHAIN.activate()
NOTE: INTEGRATOR не выносит финального суждения — передаёт человеку
STAGE_3d: ESCALATE
INPUT: HIGH/CRITICAL RISK MODULE_OUTPUT
ACTION: эскалация по ESCALATION_CHAIN
RUNTIME_ACTION_REQUEST: HUMAN_REVIEW / ESCALATE (конкретное действие определяет RUNTIME_OWNER)
FORBIDDEN: INTEGRATOR не может самостоятельно вынести вердикт BLOCK/BAN/DELETE
NOTE: финальное действие — ответственность RUNTIME и его политики
STAGE_4: EPOCH_CONTEXT_INJECTION
NOTE: EPOCH_CONTEXT — audit metadata для аудитоспособности, не изменение семантики знака.
INPUT: результат STAGE_3 + ACTIVE_EPOCH (если ZONE_3)
ACTION: обогащение OUTPUT_DECISION контекстом эпохи
LOGIC: если ACTIVE_EPOCH ≠ NOT_APPLICABLE → добавить EPOCH_CONTEXT в OUTPUT_DECISION
ZONE_3_EPOCH_RULES: применить специальные правила runtime для данной эпохи (если заданы)
PURPOSE: обеспечить аудитоспособность решения — "почему именно это действие для 💀 в EPOCH_3"
NOTE: INTEGRATOR не меняет RISK_LEVEL — только документирует контекст
STAGE_5: DECISION_ASSEMBLY
CHECK: INTERPRETATION из MODULE_OUTPUT не изменена (проверка MUTATION_04)
INPUT: все результаты STAGE_1–4
ACTION: сборка финального OUTPUT_DECISION
STRUCTURE: см. OUTPUT_INTERFACE
VALIDATION: проверка полноты всех полей
CHECK: INTEGRATOR_LIMITATION_NOTE присутствует в OUTPUT_DECISION
RETURN: OUTPUT_DECISION или ERROR_STATUS
STAGE_6: AFTER_RUN_CLEANUP
INPUT: OUTPUT_DECISION или ERROR_STATUS
ACTION: проверка отсутствия остатков (AFTER_RUN_RESIDUE: FORBIDDEN)
CHECK: временные данные очищены
CHECK: RUNTIME_POLICY не кэшируется между сессиями (SESSION_ONLY)
CHECK: логи переданы runtime (если требуется)
OUTPUT: CLEANUP_CONFIRMATION
NOTE: STAGE_6 не изменяет OUTPUT_DECISION

4. RUNTIME_ADAPTATION_MODEL
RUNTIME_TYPES (примеры — не исчерпывающий список):
DISCORD_MODERATION: реакция на сообщения в чатах
CONTENT_FILTER_API: REST API фильтрации контента
NLP_PIPELINE: встраивание в NLP-обработку текста
CHATBOT_SAFETY: безопасность диалоговых систем
EMAIL_SCANNER: анализ электронной почты
DOCUMENT_ANALYZER: анализ документов
ADAPTATION_RULES:
RULE_1: каждый RUNTIME_TYPE имеет свою RUNTIME_POLICY с ACTION_MAP
RULE_2: ACTION_MAP маппирует (RISK_LEVEL, RECOMMENDED_ACTION) → RUNTIME_ACTION_REQUEST
RULE_3: INTEGRATOR_INSTANCE не знает деталей реализации RUNTIME — только его ACTION_MAP
RULE_4: один INTEGRATOR_TEMPLATE может порождать INTEGRATOR_INSTANCE для разных RUNTIME_TYPE
RULE_5: смена runtime = замена RUNTIME_POLICY, не переписывание INTEGRATOR
ACTION_MAP_EXAMPLE_STATUS: ILLUSTRATIVE / NON_NORMATIVE
ACTION_MAP_EXAMPLE (иллюстративный, не нормативный):
NOTE: Example action names do not define required runtime behavior. Конкретные RUNTIME_ACTION определяются RUNTIME_OWNER.
RISK_LEVEL=NONE, RECOMMENDED_ACTION=INFO → RUNTIME_ACTION_REQUEST: pass
RISK_LEVEL=LOW, RECOMMENDED_ACTION=MONITOR → RUNTIME_ACTION_REQUEST: log_only
RISK_LEVEL=MEDIUM, RECOMMENDED_ACTION=FLAG_FOR_REVIEW → RUNTIME_ACTION_REQUEST: queue_for_review
RISK_LEVEL=HIGH, RECOMMENDED_ACTION=HUMAN_REVIEW → RUNTIME_ACTION_REQUEST: hold_pending_review
RISK_LEVEL=CRITICAL, RECOMMENDED_ACTION=ESCALATE_TO_INTEGRATOR → RUNTIME_ACTION_REQUEST: immediate_escalation
RUNTIME_ACTION_EXECUTION: FORBIDDEN_FOR_INTEGRATOR_TEMPLATE
NOTE: INTEGRATOR emits an action request for RUNTIME. RUNTIME decides and executes. INTEGRATOR_TEMPLATE does not execute BLOCK / DELETE / BAN / NOTIFY.
NOTE: конкретные RUNTIME_ACTION определяются RUNTIME_OWNER, не INTEGRATOR_TEMPLATE
ZONE_3_EPOCH_ROUTING:
PURPOSE: разные эпохи одного знака могут требовать разных действий в одном runtime
EXAMPLE: 💀 в EPOCH_1 (literal death) vs EPOCH_3 (laughter/irony) — разные ACTION в медицинском vs молодёжном runtime
LOGIC: ZONE_3_EPOCH_RULES[ACTIVE_EPOCH][RUNTIME_ID] → EPOCH_SPECIFIC_ACTION_OVERRIDE
EPOCH_CONTEXT_INJECTION_LIMIT:
ZONE_3_EPOCH_RULES may affect RUNTIME_ACTION_REQUEST only through RUNTIME_POLICY.
ZONE_3_EPOCH_RULES must not modify:
INTERPRETATION
RISK_LEVEL_RECEIVED
ACTIVE_EPOCH
MODULE_OUTPUT fields
FORMULA: EPOCH_POLICY_ROUTING ≠ SEMANTIC_REINTERPRETATION
ZONE_3_EPOCH_ROUTING_FALLBACK: При отсутствии OVERRIDE — passthrough (используется стандартный ACTION_MAP).
NOTE: переопределение действия возможно только через явную конфигурацию RUNTIME_POLICY, не по умолчанию..

5. CONFIGURATION_INTERFACE
CONFIGURATION_INPUT:
RUNTIME_POLICY_PATH: путь к файлу политики runtime (или реестр политик)
POLICY_REGISTRY: централизованный реестр RUNTIME_POLICY (абстрактный интерфейс, формат определяется реализацией: файловая система, БД, REST API)
INTEGRATOR_PARAMETERS:
DEFAULT_ACTION_ON_AMBIGUITY: действие при AMBIGUITY_FLAG = YES
DEFAULT: FLAG_FOR_REVIEW
ESCALATION_CHAIN_CONFIG: цепочка эскалации (уровни, тайм-ауты, fallback)
EPOCH_ROUTING_ENABLED: YES / NO (включён ли ZONE_3_EPOCH_ROUTING)
AUDIT_MODE: FULL / MINIMAL (уровень детализации логов)
LOGGING_INTERFACE:
LOG_FORMAT: структурированный лог (JSON)
REQUIRED_FIELDS:
TIMESTAMP: временная метка события
SESSION_ID: идентификатор сессии
INTEGRATOR_UID: идентификатор экземпляра INTEGRATOR
RUNTIME_ID: идентификатор runtime
SOURCE_SIGN_CODEPOINT: знак
RISK_LEVEL_RECEIVED: риск от MODULE
RUNTIME_ACTION_REQUESTED: запрошенное / рекомендованное действие для runtime
EPOCH_CONTEXT: активная эпоха (если применимо)
POLICY_RULE_APPLIED: ссылка на применённое правило политики
POLICY: логирование согласно audit policy RUNTIME_OWNER; persistent logging не требуется INTEGRATOR_TEMPLATE
LIMITATION: если AFTER_RUN_RESIDUE: FORBIDDEN — логи не сохраняются между сессиями
CONFIGURATION_RULES:
RULE_1: INTEGRATOR не может работать без загруженной RUNTIME_POLICY
RULE_2: INTEGRATOR не может использовать MODULE_OUTPUT с EFFECT_FIELDS_STATUS = INVALID
RULE_3: INTEGRATOR должен проверять совместимость RUNTIME_POLICY с INTEGRATOR_TEMPLATE версией
RULE_4: INTEGRATOR передаёт все ERROR_STATUS в LOGGING_INTERFACE текущей сессии; persistent logging определяется RUNTIME_OWNER
RULE_5: INTEGRATOR не кэширует RUNTIME_POLICY между сессиями (SESSION_ONLY)
RULE_6: INTEGRATOR не может исполнять BLOCK/BAN/DELETE.
RULE_6A: RUNTIME_POLICY может содержать ACTION_REQUEST типа REQUEST_BLOCK / REQUEST_DELETE / REQUEST_BAN, если это явно разрешено RUNTIME_OWNER.
RULE_6B: INTEGRATOR передаёт только ACTION_REQUEST. Фактическое исполнение остаётся за RUNTIME.
INVALID_POLICY: ACTION_MAP содержит прямой EXECUTE_BLOCK / EXECUTE_DELETE / EXECUTE_BAN без runtime-confirmation boundary.

6. ADVERSARIAL_COVERAGE — RUN CARD SEED
MIN_TOTAL_VECTORS: 12 (6 categories A-F, 2 per category)
CATEGORY_A: POLICY_MANIPULATION (2)
A1: Подмена RUNTIME_POLICY_PATH — INTEGRATOR проверяет целостность загруженной политики. Подмена пути — ответственность RUNTIME, не INTEGRATOR.
A2: Повреждённая RUNTIME_POLICY — ACTION_MAP содержит недопустимые действия (например, BLOCK напрямую)
CATEGORY_B: MODULE_OUTPUT_INJECTION (2)
B1: MODULE_OUTPUT с EFFECT_FIELDS_STATUS = INVALID — INTEGRATOR должен отклонить, не применять
B2: MODULE_OUTPUT с FORBIDDEN_ACTION нарушена — MODULE передал прямое действие вместо рекомендации
CATEGORY_C: RISK_ESCALATION_BYPASS (2)
C1: RISK_LEVEL = CRITICAL обработан как NONE (пропуск STAGE_3d)
C2: AMBIGUITY_FLAG = YES проигнорирован — INTEGRATOR принял решение без эскалации
CATEGORY_D: EPOCH_ROUTING_EXPLOIT (2)
D1: ZONE_3 знак обработан без EPOCH_CONTEXT — решение принято без учёта эпохи
D2: ACTIVE_EPOCH намеренно подменён в MODULE_OUTPUT для получения мягкого ACTION
CATEGORY_E: BOUNDARY_VIOLATION (2)
E1: INTEGRATOR самостоятельно вынес вердикт BLOCK без ACTION_MAP — нарушение RULE_6
E2: INTEGRATOR изменил INTERPRETATION из MODULE_OUTPUT — нарушение принципа PASSTHROUGH
CATEGORY_F: SESSION_LEAK (2)
F1: RUNTIME_POLICY кэширована между сессиями (нарушение RULE_5: SESSION_ONLY)
F2: OUTPUT_DECISION одной сессии передан в другую без переинициализации INTEGRATOR
ACTUAL_TOTAL_VECTORS: 12
COVERAGE_STATUS: SUFFICIENT (12 ≥ 12)
