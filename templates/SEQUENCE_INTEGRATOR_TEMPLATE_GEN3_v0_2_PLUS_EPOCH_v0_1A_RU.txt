ARCHITECTURE_PRINCIPLES:
  PRINCIPLE_1: SEQUENCE_INTEGRATOR получает SEQUENCE_OUTPUT от SEQUENCE_MODULE
  PRINCIPLE_2: SEQUENCE_INTEGRATOR анализирует sequence-специфику, не только RISK_LEVEL
  PRINCIPLE_3: SEQUENCE_INTEGRATOR формирует RUNTIME_ACTION_REQUEST (advisory), не FINAL_VERDICT
  PRINCIPLE_4: SEQUENCE_INTEGRATOR учитывает INTENSITY (количество одинаковых знаков)
  PRINCIPLE_5: SEQUENCE_INTEGRATOR учитывает COMBINATION (разные знаки вместе)
  PRINCIPLE_6: SEQUENCE_INTEGRATOR учитывает EPOCH_CONFLICT (разные эпохи в одной последовательности)
  PRINCIPLE_7: SEQUENCE_INTEGRATOR не изменяет INTERPRETATION отдельных знаков
  PRINCIPLE_8: SEQUENCE_INTEGRATOR не является runtime — только адаптер
  PRINCIPLE_9: SEQUENCE_INTEGRATOR не устанавливает политику — только применяет SEQUENCE_INTEGRATOR_POLICY
  PRINCIPLE_10: SEQUENCE_INTEGRATOR не кэширует результаты между сессиями (SESSION_ONLY)
  PRINCIPLE_11: SEQUENCE_INTEGRATOR_TEMPLATE является специализированным профилем INTEGRATOR_TEMPLATE
  PRINCIPLE_12: SEQUENCE_INTEGRATOR_TEMPLATE наследует все ограничения INTEGRATOR_TEMPLATE
  PRINCIPLE_13: SEQUENCE_INTEGRATOR_TEMPLATE расширяет INTEGRATOR_TEMPLATE, не заменяет его

INTEGRATION_CHAIN:
  INPUT: SEQUENCE_OUTPUT → SEQUENCE_INTEGRATOR_INSTANCE
  OUTPUT: RUNTIME_ACTION_REQUEST → RUNTIME
  BOUNDARY: SEQUENCE_INTEGRATOR ≠ SEQUENCE_MODULE (SEQUENCE_INTEGRATOR адаптирует, SEQUENCE_MODULE агрегирует)
  BOUNDARY: SEQUENCE_INTEGRATOR ≠ INTEGRATOR (SEQUENCE_INTEGRATOR обрабатывает sequence, INTEGRATOR обрабатывает одиночный знак)
  BOUNDARY: SEQUENCE_INTEGRATOR может работать вместе с INTEGRATOR (если runtime требует оба)

PROCESSING_PIPELINE:

PIPELINE_STAGES: 7 этапов обработки (STAGE_1–7)

STAGE_1: SEQUENCE_INPUT_VALIDATION
  INPUT: SEQUENCE_OUTPUT + SEQUENCE_INTEGRATOR_POLICY
  CHECK_0: SEQUENCE_INTEGRATOR_POLICY_VALIDATION (структура политики: INTENSITY_RULES, COMBINATION_RULES, EPOCH_CONFLICT_RULES присутствуют)
  CHECK_1: SEQUENCE_OUTPUT содержит все обязательные поля
  CHECK_2: SEQUENCE_EFFECT_FIELDS_STATUS = VALID
  CHECK_3: SEQUENCE_INTEGRATOR_POLICY загружена и совместима
  CHECK_4: SEQUENCE_LENGTH ≤ MAX_SEQUENCE_LENGTH (совпадение с SEQUENCE_MODULE)
  CHECK_5: SEQUENCE_LENGTH ≥ 2 (защита от повреждённого SEQUENCE_OUTPUT)
    IF SEQUENCE_LENGTH < 2 → ERROR_TYPE = SEQUENCE_OUTPUT_INVALID
  CHECK_6: POLICY_CONSISTENCY — SEQUENCE_POLICY.MAX_SEQUENCE_LENGTH = SEQUENCE_INTEGRATOR_POLICY.MAX_SEQUENCE_LENGTH
    IF mismatch → ERROR_TYPE = SEQUENCE_POLICY_INTEGRATOR_MISMATCH
  CHECK_7 (PATCH_NOTE v0_1_PATCH_24): IF
    SEQUENCE_CANDIDATE_MATCH присутствует в SEQUENCE_OUTPUT →
    валидировать, что значение ∈ {структура с CANDIDATE_ID,
    MULTIPLE_MATCHES, NOT_APPLICABLE, NO_MATCH, CHECK_UNAVAILABLE}.
    Поле ОПЦИОНАЛЬНОЕ — его ОТСУТСТВИЕ не вызывает FAILURE (CHECK_1
    проверяет только обязательные поля, это поле в их число не
    входит).
  FAILURE: ERROR_TYPE = SEQUENCE_OUTPUT_INVALID или SEQUENCE_POLICY_INVALID

STAGE_2: INTENSITY_ANALYSIS
  INPUT: SOURCE_INTERPRETATION_LIST + SOURCE_SIGN_LIST + SEQUENCE_LENGTH
  ACTION: определение интенсивности по под-последовательностям
  LOGIC:
    SUB_SEQUENCE_SCAN: поиск повторяющихся под-последовательностей (N ≥ 2 одинаковых знаков подряд)
    INTENSITY_DETECTION:
      IF repeated same CODEPOINT or same SIGN_GROUP → INTENSITY_FLAG = YES
      INTENSITY_LEVEL per sub-sequence:
        LOW: 2 одинаковых знака подряд
        MEDIUM: 3 одинаковых знака подряд
        HIGH: 4-9 одинаковых знаков подряд
        CRITICAL: 10+ одинаковых знаков подряд (spam-подозрение)
    GLOBAL_INTENSITY: MAX(INTENSITY_LEVEL всех sub-sequences)
    IF GLOBAL_INTENSITY ≥ HIGH → повышение SEQUENCE_RISK_LEVEL на 1 уровень
    IF GLOBAL_INTENSITY = CRITICAL → SEQUENCE_RISK_LEVEL = CRITICAL (spam)
  EXAMPLE: 💀💀💀😭 = sub-sequence [💀💀💀] → INTENSITY MEDIUM
    (PATCH_NOTE v0_1_PATCH_11: исправлено с HIGH на MEDIUM —
    пример был устаревшим остатком до введения таблицы порогов
    v0_1_PATCH_05 (LOW:2/MEDIUM:3/HIGH:4-9/CRITICAL:10+) и не был
    приведён в соответствие при патче таблицы. 3 одинаковых знака
    подряд = MEDIUM по таблице, не HIGH. Найдено независимо
    GPT-5.5 и Gemini при SEQUENCE_PIPELINE_FIRST_RUN, подтверждено
    координатором прямым сопоставлением строк документа,
    AUTHOR_DECISION_20260625_004.)
  EXAMPLE: 💀💀💀💀💀💀💀💀💀💀 = 10x → INTENSITY CRITICAL
  NOTE: INTENSITY_ANALYSIS не создаёт новую семантику — только количественную оценку
  FORMULA: SAME_INTERPRETATION ≠ SAME_SIGN_INTENSITY
  FORMULA: SUB_SEQUENCE_INTENSITY = STRUCTURAL_PROPERTY

STAGE_3: COMBINATION_ANALYSIS
  INPUT: SOURCE_INTERPRETATION_LIST + EPOCH_SEQUENCE_CONTEXT + SOURCE_SIGN_LIST
  ACTION: определение комбинации и распознавание идиом
  IDIOM_RECOGNITION:
    SOURCE: IDIOM_REGISTRY (загружается из SEQUENCE_INTEGRATOR_POLICY.COMBINATION_RULES.KNOWN_IDIOMS)
    MECHANISM: точное совпадение последовательности CODEPOINT или INTERPRETATION
    IDIOM_LIMIT: IDIOM_RULES may only match predefined policy entries. SEQUENCE_INTEGRATOR must not infer new idioms.
    IF NOT_RECOGNIZED → apply UNKNOWN_COMBINATION rule
  LOGIC:
    IF элементы имеют разные INTERPRETATION → COMBINATION_FLAG = YES
    IF COMBINATION известна как IDIOM (в IDIOM_REGISTRY) → IDIOM_FLAG = YES
    IF COMBINATION известна как IDIOM, но не в IDIOM_REGISTRY → UNKNOWN_COMBINATION_FLAG = YES
    IF COMBINATION создаёт конфликт эпох → EPOCH_CONFLICT_FLAG = YES
    IF COMBINATION_FLAG = YES AND IDIOM_FLAG = NO → apply UNKNOWN_COMBINATION_RULE
  UNKNOWN_COMBINATION_RULE:
    DEFAULT_ACTION: no modification (BASE_ACTION remains unchanged)
    ACTION_RATIONALE: "unknown combination, no specific rule"
    OUTPUT_WARNING: UNKNOWN_COMBINATION_DETECTED
    IF IDIOM_REGISTRY is empty:
      IDIOM_FLAG = NO
      UNKNOWN_COMBINATION_FLAG = YES if COMBINATION_FLAG = YES
      BASE_ACTION remains unchanged
      OUTPUT_WARNING = IDIOM_REGISTRY_EMPTY
    NOTE: runtime may apply additional analysis if needed
  EXAMPLE: 💀😭 = IDIOM "очень смешно" → IDIOM_FLAG = YES, apply IDIOM_ACTION
  EXAMPLE: 💀☠️ = EPOCH_CONFLICT → EPOCH_CONFLICT_FLAG = YES
  EXAMPLE: 💀🔥 = неизвестная комбинация → UNKNOWN_COMBINATION_FLAG = YES, no modification
  NOTE: COMBINATION_ANALYSIS не создаёт новую семантику — только классифицирует известные комбинации
  FORMULA: IDIOM_MATCH ≠ NEW_SEMANTIC_INTERPRETATION
  FORMULA: UNKNOWN_COMBINATION ≠ NEW_IDIOM

STAGE_4: EPOCH_CONFLICT_ROUTING
  INPUT: EPOCH_SEQUENCE_CONTEXT + EPOCH_CONFLICT_RULES
  ACTION: маршрутизация конфликта эпох (не разрешение)
  LOGIC:
    IF EPOCH_CONFLICT_FLAG = YES → применить EPOCH_CONFLICT_RULES
    EPOCH_CONFLICT_ROUTING_PRIORITY:
      1. PLATFORM_SPECIFIC (если есть правило для данной платформы — highest priority)
      2. CONTEXT_GATE (если контекст однозначно определяет эпоху)
      3. RECENCY (более новая эпоха доминирует, если нет контекста)
      4. AMBIGUITY (если конфликт не разрешён → AMBIGUITY_FLAG = YES)
    RULE_1: PLATFORM_SPECIFIC — правила платформы имеют приоритет
    RULE_2: CONTEXT_GATE — определить доминирующую эпоху по контексту (platform, cohort)
    RULE_3: RECENCY — более новая эпоха доминирует (если нет контекста)
    RULE_4: AMBIGUITY — если конфликт не разрешён → AMBIGUITY_FLAG = YES
  OUTPUT: ROUTING_EPOCH_CONTEXT или UNRESOLVED
  NOTE: EPOCH_CONFLICT_ROUTING не решает, какая эпоха "правильная" — только выбирает routing context
  NOTE: ROUTING_EPOCH_CONTEXT не перезаписывает ACTIVE_EPOCH в исходных элементах
  NOTE: RULE_3 (RECENCY) является упрощённым fallback внутри ROUTING_PRIORITY и не отменяет принцип Higher_epoch_suppresses_lower из SPEC_FOUNDATION. При наличии данных DORMANT_EPOCHS они имеют приоритет над простым RECENCY.
  FORMULA: ROUTING_EPOCH_CONTEXT ≠ ACTIVE_EPOCH_REWRITE
  FORMULA: EPOCH_CONFLICT_ROUTING ≠ EPOCH_TRUTH_DECISION

STAGE_5: ACTION_SELECTION
  INPUT: результаты STAGE_2–4 + SEQUENCE_INTEGRATOR_POLICY
  ACTION: выбор RUNTIME_ACTION_REQUEST
  LOGIC:
    BASE_ACTION: ACTION_MAP[SEQUENCE_RISK_LEVEL] (как в INTEGRATOR_TEMPLATE)
    INTENSITY_MODIFIER: если INTENSITY_FLAG = YES → модификация ACTION
    COMBINATION_MODIFIER: если COMBINATION_FLAG = YES → модификация ACTION
    EPOCH_CONFLICT_MODIFIER: если EPOCH_CONFLICT_FLAG = YES → модификация ACTION
    FINAL_ACTION: применить модификаторы в порядке MODIFIER_PRECEDENCE
  MODIFIER_PRECEDENCE:
    PRIORITY_1: EFFECT_FIELDS_INVALID / SEQUENCE_OUTPUT_INVALID (автоматический отказ)
    PRIORITY_2: EPOCH_CONFLICT_UNRESOLVED (конфликт эпох — highest priority)
    PRIORITY_3: SEQUENCE_AMBIGUITY = YES (неопределённость требует review)
    PRIORITY_4: CRITICAL risk (критический риск)
    PRIORITY_5: INTENSITY_HIGH / SPAM suspicion (спам-подозрение)
    PRIORITY_6: KNOWN_IDIOM (распознанная идиома)
    PRIORITY_7: BASE_ACTION (базовое действие по умолчанию)
  MODIFIER_APPLICATION:
    RULE_1: Применять модификаторы в порядке приоритета
    RULE_2: Если модификаторы конфликтуют → ACTION_MODIFIER_CONFLICT = YES
    RULE_3: При ACTION_MODIFIER_CONFLICT → route to HUMAN_REVIEW / INTEGRATOR_INSTANCE
    RULE_4: Не применять конфликтующие модификаторы автоматически
  MODIFIERS:
    INTENSITY_LOW: no modification, ACTION_RATIONALE += "intensity_low"
    INTENSITY_MEDIUM: BASE_ACTION + RISK_ESCALATION (+1 level), ACTION_RATIONALE += "intensity_medium"
    INTENSITY_HIGH: BASE_ACTION + RISK_ESCALATION (+2 levels), ACTION_RATIONALE += "intensity_high"
    INTENSITY_CRITICAL: BASE_ACTION → FLAG_FOR_REVIEW (spam-подозрение), ACTION_RATIONALE += "intensity_critical_spam"
    COMBINATION_IDIOM: apply IDIOM_ACTION from COMBINATION_RULES, ACTION_RATIONALE += "known_idiom"
    EPOCH_CONFLICT: BASE_ACTION + AMBIGUITY_FLAG = YES, ACTION_RATIONALE += "epoch_conflict_unresolved"
    ACTION_MODIFIER_CONFLICT: HUMAN_REVIEW, ACTION_RATIONALE += "modifier_conflict_detected"
  NOTE: ACTION_SELECTION формирует advisory-запрос, не обязательное действие

STAGE_6: OUTPUT_ASSEMBLY
  INPUT: все результаты STAGE_1–5
  ACTION: сборка RUNTIME_ACTION_REQUEST
  CHECK_1: RUNTIME_ACTION_REQUEST определён
  CHECK_2: ACTION_RATIONALE не пуста
  CHECK_3: SEQUENCE_INTEGRATOR_LIMITATION_NOTE присутствует
  RETURN: RUNTIME_ACTION_REQUEST или ERROR_STATUS
  NOTE: STAGE_6 не изменяет RUNTIME_ACTION_REQUEST после сборки

STAGE_7: FINALIZATION_CLEANUP_BEFORE_SESSION_CLOSE
  INPUT: RUNTIME_ACTION_REQUEST или ERROR_STATUS (собран в STAGE_6)
  ACTION: проверка отсутствия остатков (AFTER_RUN_RESIDUE: FORBIDDEN)
  CHECK_1: временные данные очищены
  CHECK_2: SEQUENCE_INTEGRATOR_POLICY не кэшируется (SESSION_ONLY)
  CHECK_3: SEQUENCE_OUTPUT не кэшируется между сессиями
  OUTPUT: CLEANUP_CONFIRMATION
  NOTE: STAGE_7 выполняется после сборки OUTPUT, но перед закрытием сессии
  NOTE: STAGE_7 не изменяет RUNTIME_ACTION_REQUEST
  NOTE: STAGE_7 не влияет на результат, возвращённый в STAGE_6

SEQUENCE_INTEGRATOR_POLICY_MODEL:

SEQUENCE_INTEGRATOR_POLICY:
  ABSTRACT: SEQUENCE_INTEGRATOR_POLICY определяет правила адаптации sequence
  STRUCTURE:
    INTENSITY_RULES:
      THRESHOLD_2: правило для 2 одинаковых знаков
      THRESHOLD_3: правило для 3 одинаковых знаков
      THRESHOLD_4: правило для 4+ одинаковых знаков (spam-подозрение)
      RISK_ESCALATION: YES / NO (повышать ли RISK при интенсивности)

    COMBINATION_RULES:
      KNOWN_IDIOMS: список распознанных комбинаций
      IDIOM_ACTION: специальное действие для идиомы
      UNKNOWN_COMBINATION: правило для неизвестных комбинаций

    EPOCH_CONFLICT_RULES:
      RESOLUTION_MODE: CONTEXT_GATE / RECENCY / PLATFORM / AMBIGUITY
      DEFAULT_EPOCH: какая эпоха доминирует по умолчанию
      CONFLICT_ACTION: действие при неразрешённом конфликте

    RUNTIME_SPECIFIC_RULES:
      PLATFORM: Discord / TikTok / LinkedIn / etc.
      COHORT: Gen Z / Millennial / Boomer
      DOMAIN: medical / legal / educational
