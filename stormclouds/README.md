# ⚡ StormClouds — гроза кода

Симуляция облаков и молний, где **код по‑настоящему рождается из хаоса**.

Каждая туча несёт фрагмент Python. «Ветер» гоняет тучи по небу; при
столкновении они обмениваются зарядом и сбрасывают свой фрагмент в
**грозовой очаг**. Когда заряд очага достигает порога — **молния**:
накопленные фрагменты собираются в программу и **исполняются** маленьким
встроенным интерпретатором Python, а результат (с выводом и с ошибками у
строк, которым не хватило переменных) уходит в журнал разрядов.

Идея выросла из простого вопроса — «когда тучи трутся друг о друга,
получается электричество?» — и его переноса на код: а что если блоки кода
сталкивать как тучи и смотреть, какие «разряды» из этого родятся.

## Метафора → механика

| Явление       | Что происходит на самом деле                                  |
| ------------- | ------------------------------------------------------------- |
| 🌬️ Ветер      | Случайный дрейф туч по сетке                                   |
| 💥 Столкновение | Тучи обмениваются зарядом и отдают свой фрагмент в очаг       |
| ⚡ Молния      | Собранная из фрагментов программа **исполняется** (REPL)      |
| Заряд ±       | Знак заряда тучи (тёплый = плюс, холодный = минус)             |

Ошибки — это фича: видно, как из случайного порядка иногда собирается
рабочий кусок, а иногда — синтаксический мусор. Строка, которой не хватило
переменной, помечается и пропускается; остальные продолжают исполняться.

## Запуск

Проекту не нужны сборка и зависимости — это статическая страница.

```bash
# просто открыть файл в браузере
open stormclouds/index.html        # macOS
xdg-open stormclouds/index.html    # Linux

# или поднять локальный сервер
python3 -m http.server -d stormclouds 8000
# → http://localhost:8000
```

## Структура

```
stormclouds/
├── index.html            # разметка приборной панели
├── styles.css            # тема «ночная гроза»
├── js/
│   ├── interpreter.js    # мини-Python: токенайзер → парсер → вычислитель (StormLang)
│   └── simulation.js     # тучи, ветер, столкновения, разряды, рендер
├── tests/
│   └── interpreter.test.js
└── README.md
```

`interpreter.js` — чистый модуль без DOM; его можно подключать в браузере
(глобальный `StormLang`) или в Node (`require`), что и используют тесты.

## Мини-язык (подмножество Python)

Каждый фрагмент — одна самостоятельная строка. Поддерживается:

- присваивание: `x = 5`, `x = x + 1`, `msg = "storm"`
- арифметика: `+ - * / %` (деление целочисленное, как `//`)
- сравнения: `> < >= <= == !=`
- `print(...)` с несколькими аргументами
- однострочный `if <cond>: <stmt>`
- однострочный `while <cond>: <stmt>` (с защитой ≤ 1000 итераций)
- `for i in range(n): <stmt>` и `for i in range(a, b): <stmt>`

```js
StormLang.runProgram(['x = 5', 'print(x + 1)']);
// → { out: ['6'], trace: [...], env: { x: 5 } }
```

## Управление

- **⏸ Пауза / ▶ Пуск** — остановить/продолжить симуляцию
- **🌬 Порыв ветра** — встряхнуть все тучи
- **＋ Туча** — добавить тучу со случайным фрагментом
- **⚡ Разряд** — форсировать молнию с текущим очагом
- **↺ Сбросить** — очистить небо и журнал
- **Скорость** — темп ветра
- **клик по небу** — новая туча в этой точке
- **клик по туче** — сменить её фрагмент

## Куда можно развить

- **Эволюция** — фрагменты, что чаще дают валидный вывод, «размножаются»
  (генетическое программирование).
- **Память неба** — namespace, живущий между разрядами, чтобы программа
  росла со временем.
- **Связь чипа с тучей** — в журнале подсвечивать, какая туча (`C1…Cn`)
  дала каждую строку.
- **Свой мини-язык** вместо подмножества Python, заточенный под сборку из
  случайных кусков.
