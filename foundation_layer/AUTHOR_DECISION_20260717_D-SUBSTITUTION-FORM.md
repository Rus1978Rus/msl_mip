РЕШЕНИЕ (кратко)
============================================================
ФОРМА substitution — СЛОЁНАЯ (гибридная): устойчивый КАРКАС из групп по поведению/
свойству + ОПЦИОНАЛЬНЫЙ слой деталей. Слоёность — ПОБЕДИВШАЯ форма конвейера (её
держат ВСЕ 5 ревьюеров). НЕ единогласие по СОДЕРЖАНИЮ слоя деталей — там честный
перевес, не консенсус. Фильтр/op и число — открыты, отдельными шагами.

============================================================
ПРОВЕНАНС (расклад конвейера — честно, по raw)
============================================================
Конвейер по CONVEYOR_PACKET_SUBSTITUTION_FORM_2026-07-17. Перепроверка по raw
(Claude Code): реальных ревью-вердиктов 5 (не 7; один блок — эхо пакета).

СЛОЁНАЯ ФОРМА (каркас-группы + слой деталей) — ПЕРЕВЕС ПО ФОРМЕ: все 5 ревьюеров
  строят именно слоёную архитектуру (устойчивый скелет + слой деталей поверх), а НЕ
  плоскую единую структуру. В этом смысле «гибрид/слоёность лидирует» — это общая
  форма ответа, не спорная.

Внутри слоя РАСЩЕПЛЕНИЕ (не единогласие):
  - КАРКАС: F07 (разбиение по UCD: PURE 23 / DIRECTIONAL 12 / TAG 97 / DEPRECATED 6)
    держат ВСЕ 5 как устойчивую филтр-независимую группировку — ЕДИНОГЛАСНО;
  - СОДЕРЖАНИЕ СЛОЯ ДЕТАЛЕЙ (как описывать сами пары) — ПЛЮРАЛИТЕТ, не консенсус:
      * F17 (вписать в SIGN_RELATIONS карточки) ...... 3/5 (Gemini, DeepSeek-R1, Qwen)
        — ПЛЮРАЛИТЕТ в слое деталей;
      * вычислять по запросу (F14/F16 + новая F19) .... 2/5 (GPT-5.6, ревьюер без имени).
  ОТСЕЧЕНЫ ~единогласно: F10 (пары под один фиксированный фильтр), F18 (witness-only),
    матрица N×N, семейство R(F).
  НОВАЯ форма из круга: FORM-19 (GPT) — per-sign «processing signature», из которой
    отношение ВЫЧИСЛЯЕТСЯ (в пакете её не было).

ЧЕСТНО: перевес «гибрид/слоёность» — это про ОБЩУЮ ФОРМУ (скелет + слой), которую
разделяют все 5. Это НЕ значит, что гибрид обошёл SIGN_RELATIONS по голосам: в слое
ДЕТАЛЕЙ как раз SIGN_RELATIONS — плюралитет (3/5). Две вещи не путать.

============================================================
РЕШЕНИЕ — ЧТО ЗАКРЫТО
============================================================
1. ФОРМА = СЛОЁНАЯ (закрыто): не плоская структура, а КАРКАС + опциональный слой
   деталей. Это общая форма, победившая на конвейере (5/5 строят слоями).
2. КАРКАС = F07 (закрыто, единогласно 5/5): разбиение класса 138 по UCD-свойству
   (PURE/DIRECTIONAL/TAG/DEPRECATED). Филтр-независим, уже посчитан из unicodedata,
   даёт приоритизацию witness (PURE выше, TAG ниже). Это НЕ само отношение — это
   устойчивый скелет, на который навешивается слой деталей.

============================================================
ОБНОВЛЕНИЕ 2026-07-17 — O1 (СЛОЙ ДЕТАЛЕЙ) ЗАКРЫТ АВТОРОМ = ГИБРИД
============================================================
РЕШЕНИЕ (O1): содержание слоя деталей = ГИБРИД:
  - compute-on-demand (F14/F19) — КЛАССОВЫЙ ПОЛ: все 138 знаков получают вычислимое
    отношение подмены из per-sign сигнатуры (op — явный аргумент, пары не хранятся);
  - SIGN_RELATIONS (F17) — ОБОГАЩЁННЫЙ СЛОЙ: для знаков С КАРТОЧКОЙ (сейчас 1 из 138,
    ZWSP) дополнительно ведётся курируемое человеком описание пар.
  Обе формы ложатся на уже закрытую СЛОЁНУЮ форму (каркас F07 + слой): compute = пол
  слоя деталей на весь класс, SIGN_RELATIONS = его обогащение на карточных знаках.

ПРОВЕНАНС (честно): гибрид — АВТОРСКИЙ ВЫБОР, НЕ плюралитет конвейера. В слое деталей
  плюралитет держал F17 (3/5), compute — 2/5; гибрида как отдельного варианта на
  голосовании НЕ было. Основание автора (не голоса круга): рамка проекта — witness над
  ВСЕМ классом 138; F17 в одиночку оставляет 137 знаков без слоя деталей (нет карточки
  = нет описания подмены), что рамке противоречит; compute даёт пол на все 138, F17
  обогащает важные (карточные). Две формы не исключают друг друга.

ГРАНИЦА O1: закрыто ЧТО кладём в слой (compute-пол + SIGN_RELATIONS-обогащение).
  НЕ закрыто: op (O2) — от него зависят САМИ пары; число (O3). Построение per-sign
  сигнатур и ключа SIGN_RELATIONS — реализационные шаги ПОСЛЕ выбора op.
