════════════════════════════════════════════════════════════════
БЛОК SIGN_RELATIONS — СТРУКТУРА
════════════════════════════════════════════════════════════════

ГДЕ ЖИВЁТ. Новый блок в карточке знака-маски. У обычного знака блока
НЕТ — карточка остаётся как есть (D-REL-1: каждый знак — просто знак).
Блок появляется ТОЛЬКО когда знак реально связан отношением, заведённым
ЯВНО (не авто-выведенным).

ОДНО РЕБРО (минимальная форма, D-REL-2):
  SIGN_RELATIONS:
    RELATION_001:
      RELATION_TYPE: <CONFUSABLE_OF / NFKC_MAPS_TO / VISUAL_MIMIC_OF>
      TARGET: <кодпоинт или последовательность канона, напр. U+002F>
      CONTEXT_SCOPE: <один или несколько из:
        URL / HOST / PORT / PATH / EMAIL / IDENTIFIER / IDN / CODE /
        FREE_TEXT / ANY>
      VERIFICATION_STATUS: <VERIFIED / CANDIDATE / MANUAL_OVERRIDE>
      RUNTIME_EFFECT: RELATION_ONLY

  RUNTIME_EFFECT=RELATION_ONLY — зашитый инвариант: ребро сообщает
  «похож на такой-то знак в таком-то контексте» и НИЧЕГО про риск.
  Риск решается НЕ здесь (D-REL-4).

CONTEXT_SCOPE — ПОЯСНЕНИЕ (расширен по конвейеру):
  URL        — url целиком
  HOST       — доменная часть (атака gοοgle.com с греч. o — ловится тут)
  PORT       — часть порта
  PATH       — путь после хоста
  EMAIL      — адрес почты
  IDENTIFIER — идентификатор/handle
  IDN        — международные доменные имена (Punycode/Unicode-домены)
  CODE       — исходный код
  FREE_TEXT  — свободный текст
  ANY        — контекст не важен (использовать ОСТОРОЖНО: ANY означает
               «маска везде», высокий риск ложных срабатываний —
               применять только когда связь действительно контекст-
               независима, напр. невидимый управляющий символ)

════════════════════════════════════════════════════════════════
ИСТОЧНИК ИСТИНЫ (правка по конвейеру — против рассинхрона)
════════════════════════════════════════════════════════════════
- SIGN_RELATIONS = ЕДИНСТВЕННЫЙ источник истины для РАНТАЙМА. Только
  рёбра этого блока рантайм читает как отношения.
- CONFUSABLES = человекочитаемая ДОКУМЕНТАЦИЯ / провенанс. Рантайм
  НЕ читает CONFUSABLES как рёбра. Остаётся для людей и истории.
- Одна связь описывается в ОДНОМ месте (в RELATIONS, если нужна
  рантайму). Дублирования «/ ↔ ⁄» в двух блоках как активных данных
  НЕТ → рассинхрон исключён.

════════════════════════════════════════════════════════════════
LEGACY / D1 — ЧЕРЕЗ НЕВМЕШАТЕЛЬСТВО (правка по конвейеру)
════════════════════════════════════════════════════════════════
- Авто-проекция старых CONFUSABLES в активные рёбра ОТМЕНЕНА
  (создавала ложные срабатывания: двойник, релевантный только в URL,
  со scope=ANY считался бы маской ВЕЗДЕ — нарушение RELATION_FOUND ≠
  THREAT).
- Пять карточек v0_3 (DOT/SOLIDUS/SKULL/SKULL_CROSSBONES/AT) НЕ
  получают SIGN_RELATIONS автоматически. У них блока нет → они
  работают как самостоятельные знаки, ровно как сейчас. D1 сохранён
  НЕВМЕШАТЕЛЬСТВОМ, а не проекцией.
- Рёбра заводятся ТОЛЬКО явно, с указанным CONTEXT_SCOPE, когда
  карточка реально прорабатывается (напр. будущая боевая карточка ／).

════════════════════════════════════════════════════════════════
ПАРСЕР
════════════════════════════════════════════════════════════════
SIGN_RELATIONS — именованный блок с записями RELATION_NNN, как сейчас
CONFUSABLES с CONFUSABLE_NNN. Новый экстрактор _extract_relations —
близнец существующего _extract_confusables (тот же паттерн
children_with_prefix). Отсутствие блока = пустой список (legacy, D1).

════════════════════════════════════════════════════════════════
ЛОКУС ВЕРДИКТА (D-REL-4, одобрено конвейером без правок)
════════════════════════════════════════════════════════════════
- single-sign (module_engine): нашёл знак-маску → эмитит risk=NONE +
  прикрепляет КАНДИДАТА ОТНОШЕНИЯ к статусу + опц. гипотезу зонда
  канона (данные, D-REL-5). Вердикта НЕ выносит.
- sequence (sequence_engine): кандидат отношения + CONTEXT_SCOPE
  (защищённый контекст?) + соседи → ВЫНОСИТ риск + шаг за обфускацию
  (D-REL-6). RISK = RELATION + PROTECTED_CONTEXT + SEQUENCE_PATTERN.
- интегратор: сводит как сейчас.

ЗОНД КАНОНА (D-REL-5): module_engine может спросить matcher канона
«что бы значил канон здесь» → результат в статус как ГИПОТЕЗА-данные,
НЕ риск. Зонд ОПЦИОНАЛЕН, результат НЕ финальный (matcher канона на
:／/ спотыкается — проверено кейс-тестом).

КЕЙС ＠ (D-REL-3): одна карточка ＠, одно ребро CONTEXT_SCOPE:
URL/HOST/EMAIL. Вне scope (японский текст) — ребро не активируется,
знак самостоятельный. Внутри — активируется. Без дубликата карточки.
