2. ПРОЗА ПРАВИЛА  [STATUS: EXPLANATORY_ONLY — поясняет, не определяет; истина = §1]
============================================================
[Принцип доработки (2026-07-17): прежняя проза была ПЕРЕСКАЗОМ предиката («форматный
 и игнорируемый») — а пересказ синонимами всегда возвращал вилку (сузить «форматный»
 до нулевой ширины → ~35; расширить до Mn-невидимок → >138). Поэтому проза заменена
 на ОПЕРАЦИОННУЮ ПРОЦЕДУРУ-ПОИСК: читатель не интерпретирует слова, а выполняет
 механический lookup двух свойств UCD. Процедура однозначна ПО ПОСТРОЕНИЮ — кто
 исполнит её буквально, получит ровно 138, потому что это не толкование, а проверка
 двух булевых полей.]

ОПРЕДЕЛЕНИЕ (нормативное): X — член поднадзорного класса ⟺ у кодпоинта X
  ОБА свойства Unicode Character Database истинны:
    (1) General_Category == Cf      (значение поля «Cf», не «формат вообще»);
    (2) Default_Ignorable_Code_Point == Yes  (из DerivedCoreProperties.txt).
  Оба True → член. Хоть одно False → НЕ член. Третьего нет.

ПРОЦЕДУРА ЧИТАТЕЛЯ (как получить класс, не гадая):
  для каждого кодпоинта: посмотреть gc в UnicodeData.txt и DI в
  DerivedCoreProperties.txt; включить ⟺ gc=="Cf" И DI=="Yes". Функция знака,
  «неразличимость для фильтра», ширина, наличие глифа — В ПРОЦЕДУРЕ НЕ УЧАСТВУЮТ.
  Итог механически = 138 (UCD 16.0↔17.0, см. §1).

ДВЕ ЛОВУШКИ ИНТУИЦИИ (снимаются явными тестами — НЕ читать «на глаз»):
  ЛОВУШКА-УЖЕ: «форматный = нулевой ширины». НЕТ. gc=="Cf" — это ЗНАЧЕНИЕ ПОЛЯ, а
    не «невидимый». Проверка поля Cf ВКЛЮЧАЕТ directional (LRM/RLM/embeddings/
    overrides/isolates) и теги — у них gc=="Cf" и DI=="Yes". Сузишь до «нулевой
    ширины» → потеряешь 12 directional + 97 tag → ошибка (~29 вместо 138).
  ЛОВУШКА-ШИРЕ: «любой невидимый». НЕТ. Тест — именно gc=="Cf", а не «нет глифа».
    Вариационные селекторы (Mn), Zs/Zl/Zp, braille blank U+2800 (So) — НЕ Cf,
    значит НЕ члены, хотя визуально пусты/незаметны. Притянешь их → выйдешь за 138.

ГРАНИЧНЫЕ ТЕСТЫ (образцы включения/исключения — исполнимы читателем):
  ВКЛЮЧЕНЫ (gc=="Cf" И DI=="Yes"):
    U+200B ZWSP, U+200C/200D ZWNJ/ZWJ, U+2060 WJ, U+FEFF BOM (ядро PURE);
    U+200E/200F LRM/RLM, U+202A..202E, U+2066..2069 (DIRECTIONAL);
    U+E0001 + U+E0020..E007F (TAG); U+206A..206F (DEPRECATED).
  ИСКЛЮЧЕНЫ (хотя бы одно свойство False):
    U+0020 SPACE, U+00A0 NBSP, U+202F NNBSP (Zs, не Cf);
    U+2028/2029 LINE/PARAGRAPH SEP (Zl/Zp, не Cf);
    U+2800 BRAILLE PATTERN BLANK (So, не Cf, есть глиф);
    U+FE00..FE0F вариационные селекторы (Mn, не Cf — присоединяются к СМЕЖНОМУ
      знаку [здесь «смежный» ≠ член класса], свой отдельный класс).
  Именно эти исключения — типовые ложные срабатывания интуиции; тест поля Cf их
  отсекает механически.

НОРМА ПРИ КОНФЛИКТЕ: определение = предикат (2 поля). Эта проза — исполнимая
  процедура ТОГО ЖЕ предиката, а не его вольный пересказ, поэтому расхождение
  проза↔предикат структурно исключено (проза = lookup, предикат = условие lookup).
  Если где-то в тексте проекта встретится словесный пересказ («невидимый»,
  «форматный») — истина всё равно за предикатом §1.

ЦЕЛЬ КЛАССА: МАКСИМУМ witness-детекции (балласт сегодня = поверхность атаки завтра);
  шум 97 тегов гасится СЛОЕМ РИСКА (§3), НЕ сужением класса.

СТАТУС (author decision 2026-07-17 — РОЛЬ ПРОЗЫ ЗАФИКСИРОВАНА): проза = EXPLANATORY_ONLY.
  Она ПОЯСНЯЕТ предикат §1, но НЕ является определением класса. ОПРЕДЕЛЯЕТ — предикат
  (Cf∧DI = 138, верифицирован прогоном). Поэтому:
    - reader-прогон «читатели сходятся на 138» НЕ требуется и НЕ является долгом: прозу
      не нужно доказывать как определение, ибо определяет не она;
    - при любом расхождении проза↔предикат ИСТИНА — предикат §1;
    - reader-долг СНЯТ честной фиксацией роли (а НЕ «слепой тест пройден» — слепого
      теста не было; предыдущий батч протёк, LOOPHOLE, в доказательство не идёт).
  Это авторский выбор ветки «предикат определяет, проза поясняет» — не понижение планки
  доказательства, а фиксация того, ЧТО чем является. Если когда-нибудь прозу захотят
  поднять до самостоятельного определения — тогда обязателен настоящий слепой прогон на
  СВЕЖИХ читателях (протёкший батч непригоден).

  рекомендация человеку — соразмерная.

============================================================
4. КЛАСС ≠ ВЗАИМОЗАМЕНЯЕМОСТЬ ≠ SAFE_TO_DELETE (расширено под 138)
============================================================
Класс — для ФИКСАЦИИ присутствия (witness), НЕ разрешение на удаление. Под 138
граница расширяется:
  - НЕЛЬЗЯ удалять directional из легитимного биди (арабский/иврит — там LRM/RLM
    несут смысл направления);
  - НЕЛЬЗЯ удалять теги из легитимных эмодзи-флагов (tag-последовательности);
  - ZWJ/ZWNJ — как раньше (эмодзи-сборка, персидская орфография);
  - deprecated — свидетельствовать, не трогать.
Присутствие показывается человеку; удаление — НИКОГДА вслепую.
