============================================================
0. ОТКРЫТИЕ, ИЗ КОТОРОГО ВСЁ ВЫРОСЛО
============================================================
КОМБИНАТОРНЫЙ ВЗРЫВ НЕВИДИМОК. Одно слово, визуально единственное, машинно —
миллионы неотличимых форм. paypal (6 букв, 7 щелей), 8 видов невидимых по щели →
9^7 ≈ 4,7 млн двойников, ВСЕ выглядят как paypal. sberbank → ~387 млн. Ловится
НЕ списком (бесконечен), а МЕХАНИЗМОМ реконструкции (_demask снимает все невидимые
→ обнажает оригинал → одно правило ловит все миллионы). Уже реализовано в детекторе.

СЛЕДСТВИЕ-УГРОЗА (найдено автором): чтобы система поняла «тут миллион невидимок»,
она должна их ВПУСТИТЬ и посчитать. Впустить миллион = атака уже сработала
(память/время съедены ДО вердикта). DoS через объём. «7 vs миллион» — две большие
разницы на впуске.

============================================================
1. БАЙТОВЫЙ ЯКОРЬ — РУБЕЖ НА ФИЗИЧЕСКОМ ДНЕ
============================================================
ИЕРАРХИЯ (снизу вверх, чем выше — тем больше обмана):
  БАЙТ     — физическая реальность. НЕ маскируется. «Байт сам мета» — не требует
             интерпретации, чтобы быть посчитанным.
  КОДПОИНТ — интерпретация байтов (можно спрятать: percent-encoding).
  ФОРМА    — как выглядит (грим: гомоглиф).
  СМЫСЛ    — что значит в контексте (ZWSP друг/враг).

КЛЮЧ: невидимость живёт ВЫШЕ байта. ZWSP невидим на экране, но его 3 байта
(E2 80 8B) физически в потоке. Спрятать знак от глаза можно; спрятать его ВЕС —
нельзя. Байты взвешиваются ДО любой интерпретации.

ПОРЯДОК ЗАЩИТЫ:
  1. взвесить (байты — физический якорь) — считать ПО ХОДУ чтения;
  2. перевалил лимит → early abort: СТОП, не дочитывая (миллион не входит целиком,
     рубится на первых сотнях);
  3. разбирать содержимое ПОТОМ — уже в безопасном объёме (обман есть, но не может
     сработать: объём ограничен).

ПРИНЦИП: приём ЕСТЬ первая проверка. Вердикт «слишком много» выносится В ПРОЦЕССЕ
чтения, не после полного приёма. Граница защиты — на самом впуске, не после анализа.
Это ФИЗИЧЕСКИЙ якорь защиты — как BY_CODE якорь истины: то, что нельзя подделать,
потому что оно ДО подделки.

============================================================
2. ЛИМИТ — ОТНОСИТЕЛЬНЫЙ, НЕ АБСОЛЮТНЫЙ; БАЛАНС, НЕ МИНИМУМ
============================================================
ЧИСЛО. Порядок — ДЕСЯТКИ КБ (10-50 КБ), НЕ сотни байт. Честный ввод уже весом:
тестовый фишинг проекта (paypal.com.security-check.ru/verify) ~40 Б; длинный URL
~65 Б; русский абзац ~200+ Б (кириллица ×2 байта); код ~2 КБ. Лимит 100 Б зарезал
бы собственную тестовую ссылку. Лимит = ПОТОЛОК реального использования + воздух,
НЕ «чем меньше тем лучше» (мал → режет честное; велик → DoS). Точное число — замером.

ПЛОТНОСТЬ, НЕ СЧЁТ (поправка автора: «7 или миллион — образно»). Абсолютное число
не судит. Судит СООТНОШЕНИЕ невидимого к видимому в КОНТЕКСТЕ (сквозной принцип —
контекстность):
  - машинный контекст (домен/код/id): порог низкий (даже единицы подозрительны);
  - CJK/typography: высокий (переносы легитимны);
  - плотность (невидимого ≥ видимого) → аномалия независимо от числа;
  - расхождение «мало видимого / много сырого веса» → сам по себе сигнал.
Человеку — ОТНОСИТЕЛЬНЫМ языком: «невидимого больше, чем видимого» / «аномальная
плотность для домена». Число показать, но не судить по нему.

СВЕЧЕНИЕ СВОРАЧИВАЕТ, НЕ ПЕРЕЧИСЛЯЕТ. При завале НЕ подсвечивать 100k знаков (flood
= оружие против свечения: утопить человека шумом, чтобы пропустил настоящую атаку /
отключил систему). Сводка: «⚠ N невидимых знаков (X% ввода). Нормальный текст так не
выглядит. Возможно: атака, мусор, повреждение. HOLD.» Одно число + вывод, не N
подсветок.

============================================================
3. ВХОД МНОГОЛИК — РУБЕЖИ ПО ТИПУ (не выплеснуть ребёнка)
============================================================
ОШИБКА, КОТОРУЮ АВТОР ОСТАНОВИЛ: свести вход к одной трубе «текст ≤ N байт» →
зарежет файлы ИЛИ оставит дыру бомб. Вход НЕ монолит.

── A. ИНТЕРАКТИВНЫЙ ТЕКСТ (вставка / набор) — ТЕКУЩИЙ РЕЖИМ ──
  - вставка: риск ПОТЕРИ невидимок при copy-paste (при вставке в окно часть не
    копируется — та же невидимость работает ПРОТИВ на входе; ср.
    SEMANTIC_INVISIBLE_LENGTH_WITNESS в Notarius);
  - набор руками: невидимок почти нет, завал физически не грозит;
  - байт-якорь ПРЯМОЙ, лимит-страница (десятки КБ) верен ЗДЕСЬ.
  СТРОИМ СЕЙЧАС. Простой байтовый лимит на детектор — дёшево, конкретно, закрывает
  реальную DoS-дыру, стоит на неподделываемом дне.

── B. ФАЙЛОВЫЙ ВХОД — КРУПНЫЙ ФРОНТ (наравне с гомоглифами) ──
  БАЙТЫ ФАЙЛА ≠ БАЙТЫ ТЕКСТА. Формат — контейнер: .docx = zip+XML; .pdf = бинарь
  (текст в потоках); .html = текст+теги; картинка = пиксели. Байт-якорь на файл =
  лимит на РАЗМЕР ФАЙЛА (от гигабайта), но анализ невидимок — по ИЗВЛЕЧЁННОМУ
  тексту, не по байтам контейнера.
  НОВЫЕ ВЕКТОРЫ (которых нет в тексте):
    - ZIP-БОМБА: мал файл (.docx 1 МБ) → распаковка в терабайты → лёг при извлечении.
      Нужен лимит на РЕЗУЛЬТАТ извлечения, не только на файл;
    - БЕЗОПАСНОЕ ИЗВЛЕЧЕНИЕ: бомба не должна сработать при распаковке;
    - СКРЫТОЕ В СТРУКТУРЕ: невидимки/атака в тегах, метаданных, потоках — извлекать
      ВЕСЬ текст, включая скрытый, иначе атака проедет в метаданных;
    - разные форматы = разные парсеры = разные риски.
  ЭТО ОТДЕЛЬНОЕ БОЛЬШОЕ НАПРАВЛЕНИЕ (парсинг форматов, безопасное извлечение,
  защита от бомб). Крупный фронт НАРАВНЕ с ГОМОГЛИФАМИ. НЕ строить сейчас, НЕ
  сводить к текстовому лимиту.

── C. ПОТОКИ / API — БУДУЩЕЕ ──
  Читать ОКНОМ фиксированного размера, всё в память не брать. Отдельный продукт
  (пакетный/сервисный режим), если понадобится. НЕ сейчас.

============================================================
4. РОДСТВЕННЫЕ РУБЕЖИ ВХОДА (все про вход, разной глубины)
============================================================
  - INGESTION (байт-якорь) — не дать завалить объёмом (самый низ, при чтении,
    early abort);
  - INTEGRITY — не потерять/добавить при передаче (copy-paste потеря невидимок;
    ср. Notarius INVISIBLE_LENGTH_WITNESS);
  - DENSITY_ANOMALY — аномальная плотность как сигнал (уже в анализе, относительная,
    контекстная).
  Три рубежа: от «физически впустить» до «оценить впущенное».

============================================================
СЛЕДУЮЩИЕ ШАГИ / СТАТУС
============================================================
СЕЙЧАС (дёшево, конкретно, после ZWSP): байтовый лимит на входе детектора (режим A).
  Стоит на неподделываемом дне, закрывает найденную DoS-дыру.
КРУПНЫЙ ФРОНТ (наравне с гомоглифами, НЕ сейчас): ФАЙЛОВЫЙ ВХОД — парсинг форматов,
  безопасное извлечение, защита от zip-бомб, скрытое в структуре.

СВЯЗЬ: метафора «грим на юникоде» (байт — под гримом и под лицом, самый низ);
  контекстность (плотность аномальна относительно контекста); система оповещения
  (свечение сворачивает, не флудит; лимит = природа инструмента для человека, не
  пакетного сканера); Notarius (целостность входа).
РЕЕСТР ФРОНТОВ: гомоглифы · файловый вход · PHAGO_NATURE · (input-guards INGESTION).
