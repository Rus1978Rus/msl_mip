2. ГЛАВНЫЙ ФАКТ, ДОКАЗАННЫЙ ЗАПУСКОМ (проба шаблона на ZWSP)
════════════════════════════════════════════════════════════════

МЕХАНИЗМ ДЕТЕКТОРА КАНОН-АГНОСТИЧЕН. МЕТАДАННЫЕ ОТНОШЕНИЯ — НЕТ.

`_demask` вычищает всё, что попало в `run_mask_chars`. Но `run_mask_chars`
набирается из SIGN_RELATIONS-кандидатов, а блок ребра ТРЕБУЕТ TARGET +
RELATION_TYPE из набора мимикрии {CONFUSABLE_OF, NFKC_MAPS_TO,
VISUAL_MIMIC_OF}. У ZWSP канона нет.

Три прогона одного входа (gоog<ZWSP>／le.com — известная открытая дыра):

  A — честно (нет ребра, канона нет):
      ZWSP роняется MATCHER_NOT_FOUND → FREE_TEXT → ДЫРА ОТКРЫТА.

  B — честный тип (выдуманный BOUNDARY_DISRUPTOR, TARGET=NONE):
      загрузчик пишет UNKNOWN_RELATION_TYPE warning, ребро активно →
      HOST/HIGH → ДЫРА ЗАКРЫТА ЦЕНОЙ ПРЕДУПРЕЖДЕНИЯ.

  C — валидный тип (VISUAL_MIMIC_OF, TARGET=U+0020, семантически ЛОЖНЫЙ):
      грузится без единого warning → HOST/HIGH → ДЫРА ЗАКРЫТА ЦЕНОЙ ЛЖИ
      (ZWSP НЕ мимикрирует пробел).

ВЫВОД: шаблон вынуждает выбор между ПРЕДУПРЕЖДЕНИЕМ и ЛОЖЬЮ. Честного
типа отношения для знака-разрушителя в оси не существует.

Природа ZWSP на этом входе — НЕ мимикрия под ZWJ и НЕ под пустоту, а
BOUNDARY_DISRUPTOR: он рвёт границу точного совпадения. Механизм риска —
диверсия, не подделка. Это отдельное семейство, которое конвейер в теории
поставил почти хвостом (адверсариальный: BOUNDARY_STATE_MISMATCH, тип 9),
а проба подтвердила как ПЕРВИЧНЫЙ для реального входа.

5. ТИПЫ ОТНОШЕНИЯ — СВОДКА ОБОИХ ПОТОКОВ
════════════════════════════════════════════════════════════════

Природа канона у невидимых тройственна (теория + практика сошлись):

  (а) невидимый → невидимый ПО КЛАССУ ФИЛЬТРА (не по Unicode-функции!).
      Уточнение адверсариального: ZWSP и ZWJ НЕ в одном классе Unicode
      (ZWJ Join_Control=YES, ZWSP=NO). ZWSP мимикрирует под ZWJ только
      в ГРУБОМ классификаторе «zero-width allowed». Канон = класс,
      назначенный конкретным фильтром → нужно поле CLASSIFIER_ID.
      Тип: CLASSIFIER_COLLISION_WITH.

  (б) невидимый → ПУСТОТА. Канон не кодпоинт. КРИТИЧНО: выражать явным
      TARGET_KIND: EMPTY_SEQUENCE, НЕ строкой "NULL"/"" и НЕ U+0000.
      Причина (адверсариальный, по дисциплине проекта): пустая строка
      неотличима от «поле забыто / парсер не прочитал / target неизвестен» —
      это тихий проход, ровно тот класс, что ловили весь день.
      Тип: VISUAL_ABSENCE_CONFUSABLE / TRANSFORM_COLLIDES_WITH_EMPTY.

  (в) невидимый → РАЗРЫВ ГРАНИЦЫ. Не мимикрия вообще, а диверсия точного
      совпадения. ДОКАЗАНО ЗАПУСКОМ на реальном входе gоog<ZWSP>／le.com.
      Тип: BOUNDARY_DISRUPTOR / BOUNDARY_STATE_MISMATCH.

Отдельно:
  RLO (U+202E) — НЕ zero-width mimic, а ORDER_TRANSFORM над span'ом.
    Stateful, нужны SPAN_START/END/TERMINATOR. Почти консенсус: отдельное
    семейство внутри общего конверта SIGN_RELATIONS со своим span-evaluator
    (вариант R3, гибрид).
  VS16 (U+FE0F) — НЕ мимикрия, а MODIFIES_VISIBLE_HOST (меняет представление
    соседа). Требует preceding valid base.

ВАЖНО (адверсариальный, VERIFIED): DEFAULT_IGNORABLE ≠ ПУСТО ≠ SAFE_TO_DELETE.
  ZWSP разрешает разрыв, WJ ЗАПРЕЩАЕТ, ZWNJ подавляет соединение — они
  ПРОТИВОПОЛОЖНЫ по функции, но все невидимы и все Default_Ignorable.
  Следствие для детектора: `_demask` НЕ должен слепо удалять все невидимые —
  удаление ZWNJ исказит смысл (персидская орфография), а не очистит.

6. ФОРКИ — ЗА АВТОРОМ (решать на свежую голову)

ФОРК 1 — РАЗМЕР ШАГА.
  A) Минимальный: 3-4 типа на первую карточку (ZWSP) + TARGET_KIND явным
     enum. Каналы/остальные типы добавлять по мере кейсов.
  B) Полный сразу: 9 типов + OBSERVATION_CHANNEL (12 значений) + TARGET_KIND
     (10 значений).
  Рекомендация синтеза: A — минимальный шаг, но с ПРАВИЛЬНЫМ фундаментом
  (TARGET_KIND явным enum, не строкой). Полный набор рискует стать
  «божественным relation-объектом», от которого предостерегает сам
  адверсариальный ревьюер.

ФОРК 2 — ПУСТОТА.
  Явный TARGET_KIND: EMPTY_SEQUENCE — ДА (против тихого прохода).
  TARGET: "" / "NULL" / U+0000 — НЕТ. По дисциплине проекта не должно быть
  спора: пустая строка = неоднозначность = тихий проход.

ФОРК 3 — RLO.
  Отдельное семейство ORDER_TRANSFORM внутри общего конверта SIGN_RELATIONS,
  со своим span-evaluator (гибрид R3). Почти консенсус.

ФОРК 4 — ПЕРЕИМЕНОВАНИЕ БЛОКА.
  Оставить имя SIGN_RELATIONS или переименовать в SIGN_EFFECT_RELATIONS
  (раз речь уже не только о «похож на канон»)?

ФОРК 5 — TARGET vs EFFECT.
  TARGET_KIND как discriminated union ИЛИ два раздельных поля TARGET (объект)
  + EFFECT (изменение объекта)? Для VS16/RLO второе чище.

ФОРК 6 — CLASSIFIER_COLLISION.
  Описывать конкретные внешние фильтры (нужен CLASSIFIER_ID) или только
  проектные policy-классы MSL/MIP?

ФОРК 7 — ЕДИНИЧНЫЙ СЛОЙ.
  Разрешать single-sign ставить LOW за неожиданное присутствие невидимого
  контроля, или single-sign всегда NONE, а весь риск только в sequence/context?
