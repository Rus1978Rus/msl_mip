════════════════════════════════════════════════════════════════
ЧАСТЬ 1 — КАРТОЧКИ-ЗАРОДЫШИ (EMBRYO CARDS)
════════════════════════════════════════════════════════════════

ПРОБЛЕМА, КОТОРУЮ ЗАКРЫВАЕТ:
Сейчас знак либо имеет полную карточку, либо проходит как неизвестный.
«Неизвестный» ловит отдельный механизм (регистратор) — только для
невидимок, отдельной сущностью. Это две параллельные системы
(карточки + регистратор) и дыра для всего, что вне регистратора.

РЕШЕНИЕ: знак ВСЕГДА представлен карточкой. Вопрос не «карточка или
дыра», а ЗРЕЛОСТЬ карточки. Добавляется нулевая ступень — ЗАРОДЫШ.

ЛЕСТНИЦА СТАТУСОВ (EMBRYO — новая нулевая ступень):
  EMBRYO             ← знак + юникод, БЕЗ суждения о риске
    → WORKING_DRAFT      (начали разбирать)
      → WORKINGLY_CLOSED
        → ARTIFACT_CONFIRMED

ЧТО В ЗАРОДЫШЕ (минимум, строго):
  CARD_STATUS: EMBRYO
  CODEPOINT: U+XXXX            ← ЛИЦО под гримом (ядро, обязательно)
  UNICODE_NAME: ...            ← из UnicodeData.txt
  SCRIPT: ...                  ← из Scripts.txt (когда подключим)
  GENERAL_CATEGORY: ...        ← грубый класс
  FIRST_SEEN: <контекст>       ← где система встретила (= заявка на разбор)
  VERDICT_CAPABILITY: NONE     ← КЛЮЧЕВОЕ: зародыш НЕ судит о риске

ПОЧЕМУ VERDICT_CAPABILITY: NONE — ГЛАВНОЕ:
Зародыш свидетельствует ПРИСУТСТВИЕ (вот знак, вот его код), НЕ выносит
ОПАСНОСТЬ. Иначе он превратится в антивирус, «на всякий случай»
подозревающий незнакомое. Зародыш только СМЫВАЕТ ГРИМ — показывает лицо.
Это UNVERIFIABLE как СТАТУС КАРТОЧКИ (не только как вердикт): честное
«вижу, не разобрал».

ЧТО ЭТО ДАЁТ:
  - убирает дыру «незнакомый знак проходит молча» (он теперь зародыш,
    светит лицом);
  - убирает антивирусный соблазн (зародыш не судит);
  - кормит экосистему: зародыши = ОЧЕРЕДЬ НА РАЗБОР. Система сама
    показывает, каких карточек не хватает (стратегия сообщества);
  - чистит архитектуру: одна лестница вместо «карточки + регистратор».
    РЕГИСТРАТОР становится ФАБРИКОЙ ЗАРОДЫШЕЙ (встретил незнакомый знак →
    завёл зародыш автоматически).

ГРАНИЦА (не переоценить):
  Зародыш НЕ защищает и НЕ заменяет полную карточку. Он мостик между
  «ничего» и «досье». Полный разбор (напр. гомоглиф через правило
  mixed-script) — на ступенях выше. Зародыш — честное «до разбора».

ЧАСТЬ 2 — SCRIPT_ANOMALY_HIGHLIGHT (контекстное свечение)
════════════════════════════════════════════════════════════════

ФАБУЛА (авторская): свечение юникодом — НЕ всегда и НЕ для всех знаков.
Свечёт только знак, ЧУЖОЙ для своего окружения.
  - латинский текст → латиница молчит, кириллица СИЯЕТ;
  - кириллический текст → кириллица молчит, латиница СИЯЕТ;
  - чужак подсвечивается ОТНОСИТЕЛЬНО большинства, не абсолютно.

ПОЧЕМУ ЭТО КРИТИЧНО (без правила идея мертва):
Если светит ВСЁ — paypal.com → p(0070)a(0061)y(0079)... — нечитаемая
каша, человек тонет в кодах и перестаёт смотреть. Свечение всего = шум
= смерть оповещения (тот же flood, что боялись на witness пробелов).
Правило убирает шум: сияет ТОЛЬКО аномалия.
  pаypаl → всё серое, кроме двух «а», которые ГОРЯТ. Глаз летит на них.
Тихо, пока не чужак; ярко — на чужаке. Это и есть оповещение.

МЕХАНИКА:
  1. Взять токен/строку.
  2. Посчитать скрипты букв (Latin / Cyrillic / Greek / ...).
  3. Определить ДОМИНАНТУ («свой» скрипт) — по большинству И по КОНТЕКСТУ.
  4. Подсветить знаки, чей SCRIPT ≠ доминанта.

  Пример: pаypаl → 4 Latin (p,y,p,l) + 2 Cyrillic (а,а) → доминанта
  Latin → кириллица СИЯЕТ.

ЛОВУШКА 1 — 50/50 (аaаa, ара):
  Арифметика большинства не работает. Решение (та же логика): доминанту
  задаёт КОНТЕКСТ ОКРУЖЕНИЯ, не только счёт. Домен с .com (латинский TLD)
  → ожидается латиница → кириллица чужая, даже если её половина.
  Контекст задаёт «свой скрипт».

ЛОВУШКА 2 — ЛЕГИТИМНОЕ СМЕШЕНИЕ (купил iPhone; бренды, термины):
  Есть тексты, где два скрипта ЗАКОННЫ. Русский текст с англ. словом:
  «купил iPhone» — латинское iPhone НЕ чужак.
  РЕШЕНИЕ = рамка ОПОВЕЩЕНИЯ: система НЕ решает, законно смешение или
  атака. Она ПОДСВЕЧИВАЕТ и показывает человеку: «тут латиница в
  кириллическом тексте». Человек видит iPhone → «бренд, ок». Видит
  pаypаl → «подмена». РЕШАЕТ ОН.
  Антивирус тут ломается (надо решить: атака или бренд?). Оповещение —
  нет: показал, человек разобрался.

ФОРМУЛИРОВКА ПРАВИЛА:
  SCRIPT_ANOMALY_HIGHLIGHT: определить доминирующий скрипт строки/токена
  (по большинству букв + контексту: TLD, язык окружения). Подсветить
  («зажечь юникодом») ТОЛЬКО знаки, чей скрипт ОТКЛОНЯЕТСЯ от доминанты.
  Свои буквы молчат — чужак сияет. Система НЕ судит «атака ли это» —
  показывает аномалию, решает человек.

СВЯЗЬ И СЛЕДСТВИЯ
════════════════════════════════════════════════════════════════

- ЕДИНЫЙ ПРИНЦИП КОНТЕКСТНОСТИ: аномалия ОТНОСИТЕЛЬНО контекста, не
  абсолютно. ZWSP опасен в домене / безопасен в тайском. Кириллица
  сияет в латинском / молчит в русском. Одно правило везде.

- СВЕЧЕНИЕ = ЧИСТОЕ ОПОВЕЩЕНИЕ: оно ничего не решает, делает ВИДИМЫМ.
  Подсвечивает ВОПРОС, не даёт ОТВЕТ. Метрика системы — не «сколько
  поймала» (антивирус), а «насколько ясно показала» (оповещение).

- ЗАВИСИМОСТЬ ОТ Scripts.txt: чтобы понять «латинская буква в кириллице»,
  нужен SCRIPT каждой буквы. Scripts.txt / ScriptExtensions.txt — НЕТ в
  источниках проекта. Свечение НЕВОЗМОЖНО без них. Ещё один довод
  подключить первыми в UCD-ревизии. (unicodedata частично умеет, но
  полный версионированный ответ — в Scripts.txt.)

- ГОМОГЛИФЫ через это правило = НЕ тысяча карточек на каждую букву, а
  ОДНО правило свечения + одна образцовая гомоглиф-карточка-эталон.
  Не строить сверху.

- ЗАРОДЫШ + СВЕЧЕНИЕ вместе: каждый зародыш несёт SCRIPT → mixed-script
  аномалия видна ДАЖЕ на зародышах, до полных карточек.

ЧАСТЬ 3 — VARIANT_DISCLOSURE (раскрытие вариантов)
════════════════════════════════════════════════════════════════

ОБРАЗ (авторский): сонар не различает карася и окуня — он видит, что
ЕСТЬ рыба, её размер, глубину. Вид определяет рыбак.
Развитие: система может пойти на шаг дальше голого сонара — сказать
«тут рыба; по эху похоже на карася, окуня или леща — смотри сам».
НЕ выбирает вид (это классификатор/антивирус, гадание о намерении),
а РАСКРЫВАЕТ возможные прочтения и отдаёт выбор человеку.

ТРИ УРОВНЯ ОПОВЕЩЕНИЯ (триада, ни один не решает за человека):
  1. СОНАР            — есть аномалия («тут рыба»)
  2. СВЕЧЕНИЕ         — вот она, подсвечена (SCRIPT_ANOMALY_HIGHLIGHT)
  3. VARIANT_DISCLOSURE — вот как её можно прочесть, суди

ГРАНЬ (критическая):
  «Тут фишинг»                    → антивирус, гадание о намерении. ❌
  «Тут кириллица в латинском домене; бывает при: фишинге / легитимном
   адресе / опечатке раскладки»    → оповещение с раскрытием. ✅
  Первое ЗАКРЫВАЕТ вопрос за человека. Второе РАСКРЫВАЕТ вопрос ДЛЯ
  человека. Проект — за второе.

ПРИМЕР (gоogle.com, кириллическая о U+043E):
  ⚠ Домен содержит знак, чужой для латинского окружения:
     поз.2: о — U+043E (Cyrillic), выглядит как латинское o (U+006F)
     Возможные прочтения:
     • ГОМОГЛИФ-подмена бренда (кириллица маскирует латиницу) — частый фишинг
     • легитимный не-латинский домен (если адрес осмысленно кириллический)
     • случайная опечатка раскладки
     Решение за тобой.
  Человек видит ФАКТЫ (знак, код, скрипт) + ВАРИАНТЫ → решает мгновенно.

ИСТОЧНИК ВАРИАНТОВ — КАРТОЧКА, НЕ ВЫДУМКА:
  Карточка уже содержит прочтения: SAFE_CASE (где легально), RISK_CASE
  (где опасно), AMBIGUOUS. Система НЕ изобретает версии на ходу
  (галлюцинация), а ПРЕДЪЯВЛЯЕТ содержимое досье. Оповещение =
  РАЗВЕРНУТЬ досье, а не свернуть в приговор.
  Нет карточки → зародыш → «знак чужой, код такой-то, прочтения ПОКА
  НЕ РАЗОБРАНЫ» — честно, без выдуманных вариантов.

ПРАВИЛО:
  VARIANT_DISCLOSURE: при обнаруженной аномалии система НЕ выносит
  вид/вердикт, а РАСКРЫВАЕТ известные прочтения знака в данном контексте
  (из карточки: safe/risk/ambiguous) как ГИПОТЕЗЫ, не как решение.
  «Возможно A, B или C — суди сам.» Только для ПОДСВЕЧЕННЫХ аномалий,
  только РЕЛЕВАНТНЫЕ контексту, только из ПРОВЕРЕННОГО досье. НЕ
  ранжировать уверенно (уверенный процент = скатывание в суждение о
  намерении = антивирус).

ГРАНИЦА ПРОТИВ FLOOD (из SCRIPT_ANOMALY_HIGHLIGHT):
  Варианты — ТОЛЬКО для подсвеченных аномалий. Норма молчит: обычная
  латинская o в латинском домене → ноль вариантов, тишина. 8 гипотез на
  каждый знак = flood = смерть оповещения. Аномалия → развернуть версии;
  норма → молчать.

СВЯЗЬ:
  - завершает триаду сонар→свечение→раскрытие, всё в рамке оповещения;
  - не требует нового механизма: система ПОКАЗЫВАЕТ safe/risk/ambiguous
    карточки, а не сворачивает в один вердикт;
  - метрика та же: не «сколько поймала», а «насколько ясно раскрыла».
