ИИ нельзя дать ЗАДАНИЕ («придумай программу, чтобы знаки различала»).
ИИ можно дать ВОПРОС — но обязательно с ЯКОРЕМ, который проверит ответ
реальностью. Без якоря ответ ИИ — правдоподобная фикция, неотличимая
от правды.

════════════════════════════════════════════════════════════════
1. ПОЧЕМУ «ПРОСТОЕ ЗАДАНИЕ» НЕ РАБОТАЕТ
════════════════════════════════════════════════════════════════

ИИ генерирует ПРАВДОПОДОБНОЕ, не ИСТИННОЕ. Разница невидима, пока не
столкнёшь с реальностью.

«Правдоподобная карточка» и «работающая карточка» выглядят одинаково —
до BY_CODE. «Правдоподобная симуляция» и «честная симуляция» дают
одинаковый отчёт — до mutation-adequacy.

Задача «различать знаки» — не одна задача, а четыре слоя, и на каждом
ИИ заполняет пробел правдоподобным:
  - Unicode-реальность (что знак делает по стандарту) — ИИ врёт тонко
    (доказано: «ZWSP мимикрирует под ZWJ» — на деле разные классы,
    Join_Control YES/NO);
  - контекст (где опасно) — ИИ угадывает «разумно», не буквально;
  - живое поведение кода — ИИ НЕ запускает, воображает;
  - границы (чего не может) — ИИ не признаёт, договаривает.

Четыре правдоподобных слоя дают одну большую фикцию, неотличимую от
правды БЕЗ якоря в реальности.

ДОКАЗАНО ЗА СЕССИЮ:

  - живой прогон BY_CODE дал 6/21 (правда);
  - разрыв 15/17 → 6/21 = цена доверия генерации без якоря.

════════════════════════════════════════════════════════════════
2. ЧТО РАБОТАЕТ — КОНТУР, НЕ ЗАДАНИЕ
════════════════════════════════════════════════════════════════

  интуиция (автор) ставит ВОПРОС
    → инструмент ГЕНЕРИРУЕТ (модель / Claude Code)
      → ЯКОРЬ ПРОВЕРЯЕТ (BY_CODE — не галлюцинирует)
        → интуиция ЧИТАЕТ результат, чувствует ложь
          → ставит следующий вопрос

Убери любое звено — рассыпается:
  - без интуиции — не тот вопрос, генерируем не то;
  - без генерации — нечего проверять;
  - без якоря (BY_CODE) — принимаем галлюцинацию за истину;
  - без чтения результата — якорь показал, а мы не поняли.

«Просто задание» = только генерация. Три звена из четырёх выброшены.
Отсюда «не работает».

════════════════════════════════════════════════════════════════
3. ЯКОРЬ ЛОВИТ ГАЛЛЮЦИНАЦИЮ, КОТОРУЮ ГЕНЕРАТОР В СЕБЕ НЕ ВИДИТ
════════════════════════════════════════════════════════════════

С галлюцинациями ИИ борются НЕ запретами («не выдумывай») — это
бесполезно, ИИ не знает, что выдумывает. Борются СТРУКТУРОЙ: любой
выход ИИ обязан пройти якорь, который сам не галлюцинирует.

  модель «карточка готова»    → BY_CODE          → 6/21, врала
  модель «ZWSP как ZWJ»       → Unicode-свойство → разные классы, врала
  модель «симуляция прошла»   → mutation-adequacy → 3/5, слепые пятна

ЯКОРЯ проекта (то, что НЕ галлюцинирует):
  - BY_CODE — живой прогон движка (код делает что делает, байт в байт);
  - Unicode UCD из источников (unicode_sources_update.py), не по памяти;
  - mutation-adequacy (проверка самой проверки — ломаем код нарочно);
  - reconcile по кортежу (спека vs код, расхождение = дыра);
  - oracle-манифест (ожидаемое закреплено ЗАРАНЕЕ, машинно).

Прямая связь с существующим принципом:
  INTERNALLY_GENERATED_TRACE ≠ VERIFIED_SYSTEM_STATE.
Трасса модели («я придумал программу») ≠ состояние системы (что код
реально делает). Между ними пропасть; мост — только запуск.

4. ТРИ ГРАНИ ОДНОГО (выводы сессии)
════════════════════════════════════════════════════════════════

ГРАНЬ 1 — АВТОР В КОНТУРЕ ГЛАВНЫЙ.
  Каждый ключевой поворот сессии сделал автор ИНТУИЦИЕЙ, не модель:
    - «а мы в симуляцию бросали?» — вскрыл пропущенный барьер;
    - «меня фишинг и сторож мучают» — вывел на пропуск атаки (P0);
    - «карточки могут быть продуктом галлюцинаций симуляции» —
      перевернул фундамент, узаконил принцип ре-валидации;
    - «CODE_AUDIT когда программа заработает на мелком» — не дал
      строить сверху.
  Модели отвечали блестяще — на ЗАДАННЫЙ вопрос. Какой вопрос задать,
  куда посмотреть, чему не поверить — это автор.
  Интуиция — не «догадка вместо анализа», а способность почувствовать,
  ГДЕ анализ врёт. Модель считает внутри рамки; автор чувствует, что
  рамка не та.

ГРАНЬ 2 — ЯКОРЬ ПРОТИВ ГАЛЛЮЦИНАЦИЙ (раздел 3).

ГРАНЬ 3 — НЕЛЬЗЯ ДАТЬ ЗАДАНИЕ, МОЖНО ДАТЬ ВОПРОС+ЯКОРЬ (раздел 1-2).

ЧЕСТНАЯ ГРАНИЦА (не романтизировать интуицию):
  Интуиция автора ТОЖЕ ошибается:
    - «простая починка F-NEW-2» была линией автора — конвейер сломал;
    - «QR/биты как транспорт» — интуиция тянула, разбор остановил.
  Интуиция БЕЗ проверки — тоже галлюцинация, только человеческая.
  Поэтому контур и работает: интуиция ставит вопрос → якорь проверяет →
  интуиция читает. Ни одно звено само не тянет.

5. СВЯЗЬ С АРХИТЕКТУРОЙ ПРОЕКТА
════════════════════════════════════════════════════════════════

Проект построен по образу того, как автор работает:
  МАШИНА СВЕТИТ, ЧЕЛОВЕК СУДИТ.

  - Система оповещения (не антивирус): машина выносит суждение
    PASS/QUEUE/HOLD, последнее слово — пользователь.
  - Разработка с ИИ: модели/симуляция/Claude Code оповещают
    («вот находки, вот 6/21, вот патч»), решение — автор.

Это одна и та же форма на двух уровнях. AUTHOR_DECISION_STATUS_AUTHORITY —
не формальность, а следствие: генератор не имеет права на финальное
слово, потому что генерирует правдоподобное, а не истинное.
