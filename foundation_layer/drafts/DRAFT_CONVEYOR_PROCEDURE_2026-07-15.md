ПРИЁМ РЕВЬЮЕРОВ ПО ОДНОМУ (дисциплина контекста)
============================================================
- автор называет ЧИСЛО ревьюеров (напр. 5-9), затем шлёт по ОДНОМУ;
- исполнитель на каждом: читает, считает, ПРИНИМАЕТ в контекст, ФИКСИРУЕТ
  «принял N, жду следующего» — и ОСТАНАВЛИВАЕТСЯ. Никакого анализа / сведения
  по ходу;
- сведение и вердикты — ТОЛЬКО по команде автора «поехали». До этого слова —
  копить молча, не начинать;
- причина: пакетом всех ревьюеров исполнитель читает хуже (смазывает часть); по
  одному — каждый прочитан целиком.

============================================================
ДВУНОГАЯ СИМУЛЯЦИЯ (барьер между CONVEYOR_REVIEW_PASS и WORKINGLY_CLOSED)
============================================================
- BY_SPEC — модели прогоняют батарею ПО ОПИСАНИЮ (вслепую к коду);
- BY_CODE — живой движок прогоняет ТУ ЖЕ батарею через реальный код;
- RECONCILE — сверка ПО КОРТЕЖУ (context / relation / risk / verdict / witness),
  НЕ по финальному вердикту. Расхождение = дефект (SAME_VERDICT ≠ SAME_SEMANTICS);
- одна нога = консенсус галлюцинаций (исторический разрыв BY_SPEC 15/17 vs
  BY_CODE 6/21). BY_CODE — единственный не-галлюцинирующий якорь.

============================================================
ЗАЩИТА ПРОВЕРКИ ОТ СЕБЯ САМОЙ
============================================================
- ORACLE-МАНИФЕСТ: ожидаемое пишется ЗАРАНЕЕ, машинно, ДО прогона ног (защита от
  «обе ноги ошиблись одинаково»);
- MUTATION-ADEQUACY: намеренно ломать код / предикат, проверять что батарея
  УБИВАЕТ мутацию (проверка самой проверки; 100% с первого раза ПОДОЗРИТЕЛЬНО —
  слабая батарея);
- PREFLIGHT кодпоинтов: вход реально содержит заявленные байты.
