1. «НАИВНЫЙ ФИЛЬТР» → ЯВНЫЙ UCD-ПРЕДИКАТ (это и есть CLASSIFIER_ID)
============================================================
РЕШЕНИЕ: прозаический «неразличимый для наивного фильтра» заменяется на
воспроизводимый предикат по UCD-свойствам:

  СОСЕД ⟺ General_Category = Cf
        ∧ Bidi_Class = BN
        ∧ Default_Ignorable_Code_Point = True
        ∧ ¬tag         (не теговый символ: не U+E0001, не U+E0020..E007F)
        ∧ ¬deprecated  (не U+206A..206F)

По этому предикату у ZWSP (U+200B) РОВНО 22 соседа (text-bucket). Строгий bucket
(+ directional-форматы + deprecated) = 40 — это НЕ канон соседства, а справочный
ВЕРХНИЙ ПРЕДЕЛ. КАНОН СОСЕДСТВА = 22.

FINDING_STATUS: VERIFIED (BY_CODE, UCD 16.0.0 / Python 3.14; воспроизведено
  повторным запуском; 22 text-bucket / 40 strict устойчивы).
CROSS_VERSION_UCD_15_0_0: RUN_IN_SEPARATE_ENVIRONMENT (Python 3.12 / UCD 15.0.0),
  результат идентичен (22/40, те же кодпоинты) — прогон выполнен ДРУГИМ
  исполнителем в другом окружении, НЕ воспроизведён в текущей сессии Claude Code.
  Провенанс: сверочный прогон 2026-07-15. Статус кросс-версии:
  VERIFIED_BY_SEPARATE_RUN, NOT_RE_RUN_HERE — устойчивость к версии UCD
  подтверждена двумя независимыми окружениями, но не единым прогоном; DI_RANGES
  захардкожены, все 22 кодпоинта назначены со стабильными gc/bidi (<= Unicode 7.0),
  что согласуется с наблюдением.
FINDING_BASIS: METHOD = прогон neighbors_criterion (stdlib unicodedata + DI_RANGES
  из UCD DerivedCoreProperties). TARGET = U+200B и класс DI. OBSERVED = text-bucket
  22, strict-bucket 40, ZW_TEXT_FMT в пуле = 23.

============================================================
2. КАРТОЧНЫЕ «5» = NAMED_SPECIMENS, НЕ «ВСЕ СОСЕДИ»
============================================================
РЕШЕНИЕ: пять знаков в карточке ZWSP — U+00AD SHY, U+200C ZWNJ, U+200D ZWJ,
U+2060 WJ, U+FEFF BOM — это NAMED_SPECIMENS (репрезентативная выборка), НЕ полный
список соседей. Подпись в карточке отныне: «репрезентативная выборка; полный класс
по предикату (§1) = 22».

ИСПРАВЛЯЕТСЯ ОШИБКА ОТБОРА: прежние 5 набраны ПО ФУНКЦИИ — оставлены текстовые
формат-знаки, ВЫКИНУТЫ невидимые матоператоры (U+2061..2064 FUNCTION APPLICATION /
INVISIBLE TIMES / INVISIBLE SEPARATOR / INVISIBLE PLUS), ноты (U+1D173..1D17A) и
скоропись (U+1BCA0..1BCA3). Правило ЗАПРЕЩАЕТ отбор по функции («НЕ похожий по
функции»). Отныне «КТО сосед» решает ПРЕДИКАТ (§1), а не функциональная близость.

FINDING_STATUS: VERIFIED (карточные 5 ⊂ 22 предиката, 0 лишних; 17 знаков предикат
  находит сверх карточки — среди них 2061..2064, уже присутствующие в собственной
  BY_CODE-батарее ZWSP как невидимые нулевой ширины — расхождение против своего же
  рантайма было реальным).

============================================================
3. КЛАСС ≠ ВЗАИМОЗАМЕНЯЕМОСТЬ ≠ SAFE_TO_DELETE
============================================================
РЕШЕНИЕ: предикат (§1) отвечает ТОЛЬКО на вопрос «кто в классе» — для witness /
подсветки / регистратора (свидетельствовать присутствие невидимого). Он НЕ
утверждает взаимозаменяемость и НЕ даёт права на удаление.

ФУНКЦИОНАЛЬНЫЕ РАЗЛИЧИЯ остаются в ТЕЛЕ карточки (для детектора, чтобы _demask не
удалял вслепую): ZWSP РАЗРЕШАЕТ разрыв строки; WJ ЗАПРЕЩАЕТ разрыв; ZWNJ ПОДАВЛЯЕТ
соединение (значимо в персидской орфографии) — функции РАЗНЫЕ, местами
ПРОТИВОПОЛОЖНЫЕ. Один класс по наблюдаемой невидимости НЕ означает одну функцию.

Согласовано с DRAFT_INVISIBLE_SIGNS_SYNTHESIS §5:
  DEFAULT_IGNORABLE ≠ ПУСТО ≠ SAFE_TO_DELETE.
