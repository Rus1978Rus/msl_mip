## КОНТЕКСТ (измерено)
VS16 (U+FE0F) и вся семья селекторов вариаций — категория Unicode **Mn**, а не Cf.
Надзорный класс-138 = Cf ∧ Default_Ignorable, поэтому VS в него НЕ входит
(`FE0F ∉ _monitored_138_set()` — замерено). Ядро видит VS как generic-uncarded →
witness/pass ОДИНАКОВО для всех случаев. Итог двойной: (а) ходовые эмодзи с VS16
шумят witness (6/8 сэмпла); (б) атака-носитель (цепочка VS = канал произвольных байт)
тоже только witness/pass — не эскалируется. Форк-сим кандидат-правила: benign FP 0/7,
атаки 6/6.

## ПРИНЯТЫЕ РЕШЕНИЯ (D1–D8)

**D1 — ТОЧКА ПОДКЛЮЧЕНИЯ: отдельная VS-ОСЬ (не расширение класса-138).**
VS = отдельная ось, НЕ второй надзорный класс Mn∧DI (слишком широко — захватит не-VS).
Двухуровневая: (1) классовый распознаватель семейства VS по диапазонам; (2) профиль
последовательности для конкретных допустимых контекстов. Ось работает ДО/в связке с
generic-регистратором с КОНТРАКТОМ: **распознанный и классифицированный VS НЕ считается
uncarded** (даже если его результат pass) — снимает дубль witness-канала. Основание:
свод 3–1 за (B) (Gemini/GPT/DeepSeek; Kimi за (A)-в-регистраторе — примирено контрактом).

**D2 — ВАЛИДНОСТЬ = ПОЛНАЯ СТАНДАРТИЗОВАННАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ, НЕ КЛАСС БАЗЫ.**
(реформулировка GPT, принята как правка дизайна.) Кандидат «один селектор на допустимом
КЛАССЕ базы → clean» — сам loophole. Валидность — свойство пары/последовательности из
пиннутой таблицы, не грубого класса базы. Закрывает 4 дыры: `цифра+VS16` (нужна полная
keycap-грамматика +U+20E3), `CJK+VS` (нужен IVD), `≥2 где угодно`≠цепочка (только СМЕЖНАЯ),
способность-нести-данные ≠ доказанная атака.

**D3 — УРОВНИ (V2, по авторской оценке атакуемости — синтез, не плоский hold):**
- легит-одиночка на таблично-валидной базе → **ЧИСТО (pass, без witness)**;
- СИРОТА (VS на не-базе / ведущий / после не-базы) → **ВОЗМОЖНАЯ (queue_for_review)**;
- смежная ЦЕПОЧКА (≥2 смежных селектора) → **ВОЗМОЖНАЯ (queue_for_review)** по умолчанию;
- отдельная карточка **KNOWN_CARRIER → РЕАЛЬНАЯ (hold_pending_review)** ТОЛЬКО при
  conclusive-декоде payload (известный кодек + framing + checksum), не по одной длине.
ОСНОВАНИЕ (оценка атакуемости): плоское «цепочка→hold» (голос 3) при ненулевой base-rate
безобидных смежных цепочек «кричит волк» → усталость сигнала → игнор hold → пропуск
реального носителя (и attention-DoS заливом benign-цепочек). Синтез (голос GPT, самый
глубокий) держит hold достоверным (только декодированный payload), всё остальное surface'ит
в queue (не silent). Способность ≠ намерение — hold без доказанного канала преждевременен.

**D4 — БАЗА-ВАЛИДНОСТЬ: ТАБЛИЦЫ ДЛЯ ПОДДЕРЖАННОЙ ОБЛАСТИ, ПОЭТАПНО (не сырая аппроксимация).**
Точные пиннутые таблицы (emoji-variation-sequences, keycap-грамматика) для VS15/16 СЕЙЧАС;
VS1..14 / supplement (IVD) — отдельным поздним шагом. Сырую аппроксимацию (цифра→keycap,
VS1..14→CJK) НЕ принимать как финальное правило освобождения (keycap-FN измерен). Инфра
запиненных данных с DEGRADED-fallback в проекте уже есть.

**D5 — ОБЛАСТЬ (V6): распознавать всю семью сразу, профилировать VS15/16 первыми.**
Распознавание семейства VS1..256 — СРАЗУ (иначе носитель уедет в supplement = байт/символ =
сильнейший канал; конкретный обход, не вкус). Полный профиль в FIRST_CUT — только VS15/16 +
keycap-грамматика + orphan/chain. VS1..14/supplement — таблицами позже; до таблиц —
UNRESOLVED_PROFILE (witness/queue по структуре), НЕ generic-unknown и НЕ освобождение по
CJK-эвристике.

**D6 — ЗАКРЕПИТЬ ОПРЕДЕЛЕНИЯ ДО КОДА.**
CHAIN = ≥2 СМЕЖНЫХ селектора / на одной базе / в одном кластере без новой валидной базы
(НЕ «≥2 в строке» — два эмодзи с VS16 каждый = две легит-одиночки, не цепочка). ORPHAN —
подклассы (NO_BASE / NONSTANDARD_PAIR / INCOMPLETE_SEQUENCE / AFTER_SELECTOR / BROKEN_CLUSTER).
Таблицы — источник+версия пиннуты, hash/integrity, обновление через delta-census. FAIL-CLOSED:
таблица недоступна → одиночки НЕ освобождаются, остаются witness.

**D7 — ВНУТРЕННЯЯ ТАКСОНОМИЯ (>бинарной):** STANDARDIZED_VALID / INCOMPLETE_OR_NONSTANDARD /
ORPHAN / CHAIN / UNRESOLVED_PROFILE / KNOWN_CARRIER.

**D8 — ИНВАРИАНТЫ.** zero-delta для не-VS входов, доказываемый дифференциалом по ПОЛНОМУ
отчёту (не только вердикту); МОНОТОННОСТЬ мультимеханизма (валидный VS снимает ТОЛЬКО свой
witness, не гасит соседние карточки); нормализация НЕ раньше фиксации evidence; O(n)-скан +
кап на число сериализуемых селекторов + БЕЗ неограниченного декода в основном процессе.

**D9 — HOST-КОНТЕКСТ IN-SCOPE (поднято из отложенной дыры замером 2026-07-26).**
VS-ось ОБЯЗАНА работать и в машинном/host-контексте, не только в прозе. Замер: VS-цепочка/
одиночка в host-метке (`paypal<VS16>.com`, `pay<VS16×3>pal.com`, supplement) сегодня → pass/
pass (полностью silent), тогда как Cf там → hold. Это худший случай (носитель + разрыв домена).
Решение: применять аддитивный шов по образцу AUTHOR_DECISION_20260722_D-INV-GEN — невидимка
(теперь и Mn) в host-метке нелегитимна ПО ПРИСУТСТВИЮ. Уровни в host: VS-одиночка/сирота в
host → как минимум ВОЗМОЖНАЯ (queue), паритет с D-INV-GEN (uncarded Cf в host → queue после
b97112a); VS-ЦЕПОЧКА в host (носитель + разрыв) → приоритетный кандидат в РЕАЛЬНАЯ (hold) даже
без KNOWN_CARRIER-декода, т.к. host-контекст добавляет структурный вред поверх D3 — точный
уровень host-цепочки закрепить delta-census'ом при реализации. Ни один VS-в-host не остаётся
silent pass. (D3 задаёт базовые уровни; D9 — их усиление в host по паритету с D-INV-GEN.)
