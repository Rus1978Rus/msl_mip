РЕШЕНИЕ ПО ЕДИНСТВЕННОЙ ЖИВОЙ РАЗВИЛКЕ (author decision)
============================================================
TOKEN (BOM×BYTE_EXACT_TOKEN → HIGH/hold vs оставить MEDIUM/queue) → ОТЛОЖИТЬ-ОТКРЫТО.
  Это ЦЕННОСТНЫЙ вопрос witness-рамки (Kimi: безобидно-аномальный BOM в hold = информативная находка,
  не FP; асимметрия цены; token — первичная поверхность) vs (OpenAI×2+Qwen: пере-эскалация/alarm-fatigue),
  а не факт рантайма. Замер сузил его до token (email убит, host no-op), но не решает — стержень в знании
  автора (queue = живой разбор-по-приоритету или свалка). АВТОР ВЫБРАЛ: НЕ закрывать token; отгрузить
  инкремент-0; решить token ПОЗЖЕ, увидев доказанно-инертный шов + замеренный token FP-бюджет на benign-
  корпусе. Запасной вариант обеих сторон, трудный вызов отложен до момента дешевле/информативнее.

УТВЕРЖДЁННЫЙ ОБЪЁМ ИНКРЕМЕНТА-0 (что писать)
============================================================
1. ШОВ RELATION_PATH_O1_HOOK_v0_1: в `_assess_relation_risk` ПОСЛЕ вычисления base_risk:RiskLevel,
   ДО сериализации risk.value. overlay всегда None → final = max(base, None) = base. Работает с ENUM,
   не со строкой (H1 ноги 1). Хотспот `_detect_context_at` НЕ зовётся (читает готовый detected_context).
2. ТИПИЗИРОВАННЫЙ PolicyDecision + СПАРС exact-match реестр (ПУСТОЙ в инкременте-0). Ключ по CODEPOINT
   sign_id (не имя/visible_form). Provenance-ID обязателен для строки (в инкременте-0 строк нет).
3. МОНОТОННЫЙ combine: final = max(base, overlay); absence = identity; ТОЛЬКО эскалация.
4. ЛИНТ реестра: ZWSP-ключ / wildcard / класс-дефолт / CRITICAL / без-provenance / lower / no-op-строка —
   все FAIL. (Пустой реестр линт проходит тривиально; линт-код существует и тестируется вхолостую.)
5. INTEGRITY-инвариант: слой видит base+overlay+final и сам проверяет final==max(base,overlay); подъём —
   не контаминация. В инкременте-0: overlay=None ⇒ final==base ВСЕГДА.
6. ФЛАГ OFF/ON (env/feature) для zero-delta дифф-харнеса.
7. ЧЕСТНОСТЬ ОТСУТСТВИЯ: инфраструктура аудита {base,final,rule_id,provenance} есть, но поле пишется
   ТОЛЬКО когда строка сработала (final>base). В инкременте-0 не срабатывает никогда ⇒ поля НЕТ ⇒
   батареи бит-в-бит идентичны (zero-delta не нарушен новым полем).
8. TARGET_SIGN_RISK_PATH_CENSUS (предусловие-гейт): фиксирует, что цели O1 (сейчас пусто) идут через
   relation_verdicts; при первой строке со знаком single_sign_risky>0 — активация БЛОКИРУЕТСЯ до
   confluence-review. Реализовано через row-liveness. НЕ README-заметка — машинно-проверяемо.

НЕ ПИСАТЬ в инкременте-0: НИ ОДНОГО поведенческого правила (BOM/ZWJ/token/email/host); occurrence-role
  эвристик; script-детекции; ingress-вывода; правок `_SCOPE_RISK`/гейта/карт.
