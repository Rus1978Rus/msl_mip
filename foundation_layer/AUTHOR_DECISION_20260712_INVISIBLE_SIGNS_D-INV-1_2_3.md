D-INV-1 (форк 1 — РАЗМЕР ШАГА): МИНИМУМ ТИПОВ
════════════════════════════════════════════════════════════════
Ось «отношение» расширяется МИНИМАЛЬНО — только типами, нужными для
первой карточки невидимого знака (ZWSP). Прочие типы (VS16-модификатор
MODIFIES_VISIBLE_HOST, BOM-позиция, RLO-порядок и т.д.) добавляются ПО
КЕЙСАМ, когда доходим до тех знаков. НЕ проектировать наперёд —
«божественный relation-объект» с 9 типами и 12-значным каналом наблюдения
отвергнут (предостережение адверсариального ревьюера).

Для ZWSP введены ровно три RELATION_TYPE:
  - BOUNDARY_DISRUPTOR       — знак РВЁТ границу точного совпадения.
                               Доказано запуском: ZWSP на gоog<ZWSP>／le.com.
                               TARGET_KIND: EMPTY_SEQUENCE.
  - INVISIBLE_CLASS_COLLISION — невидимый проходит по разрешению ДРУГОГО
                               невидимого в ГРУБОМ фильтре. Канон — НЕ
                               Unicode-функция (ZWSP и ZWJ в разных классах:
                               Join_Control YES/NO), а класс грубого
                               классификатора. TARGET_KIND: CLASS.
  - ABSENCE_CONFUSABLE       — визуально неотличим от ОТСУТСТВИЯ знака.
                               TARGET_KIND: EMPTY_SEQUENCE.

════════════════════════════════════════════════════════════════
D-INV-2 (форк 3 — RLO / bidi): ОТДЕЛЬНОЕ СЕМЕЙСТВО В ОБЩЕМ КОНВЕРТЕ
════════════════════════════════════════════════════════════════
RLO (U+202E) и прочие bidi-контроли — ОТДЕЛЬНОЕ СЕМЕЙСТВО (ORDER_TRANSFORM,
stateful, SPAN_START/END/TERMINATOR) ВНУТРИ общего конверта SIGN_RELATIONS,
со своим span-evaluator. НЕ отдельная ось.

ПОЧЕМУ не отдельная ось. Отдельный путь к финальному вердикту — это ровно
тот прецедент тихого обрыва, который ловили сторожем (relation_verdicts
доходили до финала единственным ручным путём; второй боковой путь = второе
место, где всё молча провалится). Bidi живёт в том же конверте, проходит
тот же сторож (D-GUARD-1..4).

Для ZWSP это НЕ нужно (ZWSP не stateful, не span). Решение зафиксировано
на будущее, чтобы к RLO не изобретать боковой путь.

D-INV-3 (форк 2 — ПУСТОЙ КАНОН): ЯВНЫЙ enum TARGET_KIND
════════════════════════════════════════════════════════════════
Когда у знака нет канона-кодпоинта, это выражается ЯВНЫМ enum
TARGET_KIND: EMPTY_SEQUENCE. НЕ пустой строкой, НЕ "NULL", НЕ U+0000.

ПОЧЕМУ. Пустое/отсутствующее поле TARGET неотличимо от «забыли заполнить /
парсер не прочитал / target неизвестен» — это ТИХИЙ ПРОХОД, тот же класс,
что ловили в детекторе весь день. Явный enum делает «канона нет»
НАМЕРЕННЫМ и проверяемым, а не совпадающим с ошибкой заполнения.

TARGET_KIND (enum): CODEPOINT | EMPTY_SEQUENCE | CLASS.
  CODEPOINT      — канон есть, TARGET обязателен (мимикрия: ／→U+002F).
  EMPTY_SEQUENCE — канона-кодпоинта нет (разрыв/пустота); TARGET опущен.
  CLASS          — канон = класс грубого фильтра; TARGET несёт имя класса.

РЕАЛИЗАЦИЯ (минимальная, под D-INV-1) — уже в коде
════════════════════════════════════════════════════════════════
- core/sign_core_card.py: SignRelation.target_kind (default "CODEPOINT").
- core/load_card.py: _VALID_TYPE расширен тремя типами; _VALID_TARGET_KIND
  = {CODEPOINT, EMPTY_SEQUENCE, CLASS}; TARGET_KIND парсится (отсутствует →
  CODEPOINT); TARGET опционален при kind ≠ CODEPOINT; предупреждения на
  несогласованность (CODEPOINT без TARGET; EMPTY_SEQUENCE с TARGET; неизвестный
  kind).
- single_sign/module_engine.py и sequence/sequence_engine.py: target_kind и
  relation_type пронесены до кандидата и до вердикта (не роняются на шве —
  урок аудита), честный тип виден в выводе рантайма.

СОВМЕСТИМОСТЬ (проверено): legacy-карточки (／, ☠, .) без TARGET_KIND →
default CODEPOINT, TARGET присутствует → без предупреждений, не ломаются.
