## ПРИНЯТЫЕ РЕШЕНИЯ (D1–D7)

**D1 — COMPAT = DUAL. 5 готовых карточек НЕ мигрируют.**
Форма обновляется до v0_4 как ADDITIVE-DUAL. Блок CONFUSABLES в 5
готовых карточках (. / 💀 ☠ @) семантически переопределяется:
«исчерпывающий список» → «ручной OVERRIDE поверх авто-слоя».
Карточки валидны как есть, ручной труд миграции = 0. Основание:
7/7 ревью + совпадает с 6/6 ревью норм-слоя.

**D2 — ГОМОГЛИФ: поле=отношение, тонкая карточка=рантайм-вход.**
Разрешено КОДОМ (не голосованием): scan_signs строит реестр из
visible_form карт (проверено: sign_chars = {c.visible_form: c}),
confusables в реестр НЕ попадают. Значит:
  - ПОЛЕ в карточке канона = документация связи «／ confusable /».
  - ТОНКАЯ КАРТОЧКА (visible_form=／) = вход в рантайм, наследует
    риск канона, scan_signs ловит.
Это буквально реализует R-B (гомоглиф входит как знак только через
карточку). Исправляет ошибку PA3 (склонялся к «только поле» — код
показал, что поле не заводит знак в scan_signs).
[ПРИНЯТО; механика тонкой карточки уточняется при реализации.]

**D3 — VERIFICATION = ГИБРИД.** Слой (NFKC/skeleton UTS#39) =
источник истины, логика не дублируется в карточках. Карточка
кэширует СНИМОК верификации как провенанс (unicode_version,
nfkc_canonical, uts39_confusable, verified_at). Валидатор
перепроверяет. Основание: 7/7.

**D4 — MINIMUM_5 СНЯТЬ.** «Минимум 5 confusables вручную» = рудимент
квадратичной модели, вреден (добор «для формы» → ложные связи).
Замена: «авто из слоя + опц. ручные override, МИНИМУМ 0. Ручной
override обязан нести BASIS + verification_status». Основание: 7/7.

**D5 — ПРАВИЛО КОНФЛИКТА авто vs override.** Консервативное:
  - авто нашёл, override нет → авто побеждает (добавляется);
  - override есть, авто нет → HOLD_FOR_REVIEW + пометка
    MANUAL_OVERRIDE_UNVERIFIED (не принимать тихо);
  - оба, разный risk → override побеждает (автор видит контекст),
    но флаг OVERRIDE_DISAGREEMENT → ревью.
В духе VERIFY_BEFORE_TRUST: спорное не принимается молча.
[ПРИНЯТО; формулировки уточняются при реализации правил.]

**D6 — ОБЯЗАТЕЛЬНАЯ ГИГИЕНА ФОРМЫ:**
  - unicode_version в карточке ОБЯЗАТЕЛЬНА (NFKC/skeleton меняются
    между версиями; совместимо с уже готовым version pinning
    sources/17.0.0);
  - skeleton НЕ хранить как «канонический текст» (UTS#39: skeleton
    только для внутреннего сравнения);
  - canonical_target как ПОСЛЕДОВАТЕЛЬНОСТЬ, не один codepoint
    (NFKC даёт ﬁ→f+i; связано с офсет-развилкой норм-слоя).

**D7 — ВАЛИДАТОР/ЛИНТЕР карточек сообщества — ЗАРЕГИСТРИРОВАТЬ,
не делать сейчас.** Будущее расширение существующего MSL/MIP Linter
(не новая сущность): при PR запускать норм-слой, требовать
verification_snapshot или override_justification. Часть будущей
библиотеки-стандарта.

## ЧТО ДАЛЬШЕ — УЖЕ НЕ КОНВЕЙЕР (решение принято)

Реализация идёт через КОД + gate + ПК (не новый конвейер):
1. SIGN_CORE_CARD_TEMPLATE v0_3 → v0_4 (поле-отношение, снять мин-5).
2. Новый тип THIN_HOMOGLYPH_CARD (visible_form, canonical_target,
   inherited_risk, verification_snapshot).
3. load_card.py + sign_core_card.py: читать новые поля,
   регистрировать тонкую карточку в sign_chars.
4. SIGN_CORE_CARD_CONVEYOR_RULES: правило конфликта D5 +
   обязательность верификации.
5. Прогон 5 готовых карточек на v0_4 (должны пройти как legacy).
6. gate + ПК + AUTHOR_DECISION + GitHub.
