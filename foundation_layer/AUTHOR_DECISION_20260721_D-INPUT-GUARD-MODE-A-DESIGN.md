============================================================
РЕШЕНИЕ (кратко)
============================================================
INPUT_GUARD режима A = аддитивный O(n)-preflight на входе analyze() ДО scan_signs/sequence.
Общий sequence-путь НЕ РЕДАКТИРУЕТСЯ (CI-пин). Один проход-взвешивание считает: байты (по
UTF-8-байт-паттернам класса-138 — байт-якорь), счёт класса-138, доминантную долю знака,
триггер-счётчики, script-profile видимого текста. Двухъярусный витнес: сигнал (анализ
продолжается + DENSITY_ANOMALY; ГОЛЫЙ pass при флуде ЗАПРЕЩЁН) / свёртка (одна HOLD-сводка +
анализ ВИДИМОЙ ПРОЕКЦИИ, чтобы флуд не спрятал хвост). Принят САМЫЙ НАДЁЖНЫЙ вариант по всем
6 развилкам (заземлён атака-симуляцией). Фикс O(n²) — ОТДЕЛЬНЫМ гейт-кругом. Не-контаминация
ZWSP — постройкой + обязательным acceptance-гейтом. КОД — только после author decision по плану
реализации, с зелёным гейтом.

============================================================
ВЕРИФИКАЦИЯ (атака-симуляция координатора на ЖИВОМ ядре — не только голосование)
============================================================
Каждая развилка прогнана атаками на реальном runtime (scratchpad: guard_fork1_sim2 / forks_sim /
crux_probe / g9_probe). Замеры:
- #1: 159 карточных невидимок в 477Б → сегодня pass, attention=NONE (молча). L_min(<500Б)
  пропускает → дыра флуд→pass открыта; count-floor(159>20) → SIGNAL. → count-floor.
- #2: распределённый слэш ab/×N (dom 0.33, невидимых 0, <64КБ) → доминанта/плотность/байт-потолок
  МИМО, время квадратично (3000→0.38с; 8000→~8с). Ловит только счёт триггеров. → trigger-aware.
- #3: честные 31КБ прозы → 0.024с, 31КБ код → 0.019с (ноль DoS). Тугой 8/16КБ = чистый FP на
  честном вводе десятков КБ (авторский черновик). → свободный backstop ~64КБ+.
- #4: легитимный персидский с ZWNJ → плотность класса-138 11.8% > плоский 5% (FP на легит i18n).
  → script-profile (жёсткий cap профиль-независим — против profile-spoof).
- #5: guard_shadow_oracle документирует инвариант «class_guard НИКОГДА не читается вердикт-путём»
  (report-only). Поглощение (Gemini) сломало бы его. → держать раздельно.
- #6-G10: smoke 6000ZWSP+«paypal.com.evil.ru/verify»; проекция (strip класса) → analyze →
  hold_pending_review за 0.27с (фишинг восстановлен). Голая свёртка спрятала бы. → проекция.
- #6-G9: overlong-ZWSP ×100 → счёт по каноническому паттерну E2 80 8B = 0, снисходительный
  декодер видит 100 → недосчёт 100%. → счёт по байт-формам / тем же декодером.

============================================================
РЕШЕНИЕ ПО РАЗВИЛКАМ (author decision — самый надёжный вариант, заземлён замером)
============================================================
1. КОРОТКИЙ ВВОД → COUNT-FLOOR (конъюнкция: count>N И ratio>%). НЕ L_min. Закрывает дыру
   флуд→pass на малых входах (у L_min слепое окно <500Б); голую дизъюнкцию без пола (Grok/Qwen)
   отвергнуть (FP на коротком плотном).
2. ЛИМИТИРУЕМАЯ ВЕЛИЧИНА → TRIGGER-AWARE (счёт триггеров: невидимые + слэши + sequence-роли) +
   байт как backstop. Байт+плотность распределённый триггер-флуд пропускают.
3. БАЙТ-ПОТОЛОК → СВОБОДНЫЙ backstop (~64КБ, порядок сотен КБ), НЕ тугой 8-16КБ. Байт —
   наименее важный cap; тугой = FP на честном длинном вводе; флуды ловятся плотностью/триггерами.
4. SCRIPT-PROFILE → ДА. Порог модулируется скриптом видимого текста (ASCII/машинный — базовый;
   CJK/Thai/Arabic — поднятый). ЖЁСТКИЙ вычислительный cap ПРОФИЛЬ-НЕЗАВИСИМ (профиль-spoof
   CJK-паддингом всё равно бьётся о hard cap).
5. GUARD-CAP → ДЕРЖАТЬ РАЗДЕЛЬНО. _GUARD_MEMBER_CAP остаётся report-only (свой shadow-oracle,
   инвариант «не в вердикт-пути»). Рубеж — отдельный слой на входе. Общая КОНСТАНТА-семья
   допустима, общая РОЛЬ нет. НЕ поглощать (сломало бы верифицированный инвариант).
6. ОБХОДЫ KIMI → БРАТЬ ОБА. G9 decoder-desync: счёт класса-138 по UTF-8 БАЙТ-ПАТТЕРНАМ (байт-якорь)
   либо строго тем же декодером, что анализ; mutation-кейс обязателен. G10 smokescreen: при свёртке
   анализ ВИДИМОЙ ПРОЕКЦИИ (strip класса → производный вид, позиции в orig, пометка PROJECTION) —
   НЕ принимать «маска-под-флудом не ловится» как компромисс (ошибка Qwen).

============================================================
УТВЕРЖДЁННЫЙ СКЕЛЕТ (что закрыто)
============================================================
0. ИМЯ/РОЛЬ: INPUT_GUARD режима A — защита ВХОДА (бюджет стоимости), НЕ уровень знака (это O1).
1. МЕСТО: первой операцией в analyze(), ДО scan_signs/sequence. sequence-файлы под CI-пином
   (ноль правок). НЕ внутри sequence, НЕ через _detect_context_at (звать хотспот = свой DoS).
2. ВЗВЕШИВАНИЕ (один O(n)-проход, early-abort внутри при доказанной патологии; БЕЗ regex/
   аллокаций/вызовов sequence; 10МБ < 50мс): байты (UTF-8-байт-паттерны класса-138), счёт
   класса-138, доминантная доля, триггер-счётчики (невидимые+слэши+sequence-роли), script-profile.
3. РЕШЕНИЕ (двухъярусно, конъюнктивно, script-модулированно):
   T_signal (count>N И ratio>%): анализ ПРОДОЛЖАЕТСЯ + DENSITY_ANOMALY (ВОЗМОЖНАЯ/queue);
     ГОЛЫЙ pass ЗАПРЕЩЁН при count>N (закрывает измеренную дыру флуд→pass).
   T_collapse (count>M И ratio>% ИЛИ trigger_total>K ИЛИ dominant_share>S ИЛИ bytes>BYTE_BACKSTOP):
     СВОДКА «⚠ N, X%, HOLD pending review» + анализ ВИДИМОЙ ПРОЕКЦИИ (G10).
4. WITNESS: сводка одна, не N подсветок; HOLD = рекомендация человеку, не блок; последнее слово
   за человеком. RESOURCE_LIMIT_EXCEEDED ≠ ДОКАЗАННАЯ АТАКА. content_risk=NOT_ASSESSED при свёртке.
5. ОТЧЁТ-КОНТРАКТ (anti-masquerade): top-level поле input_guard {schema_version, mode:A, status:
   OK|DENSITY_SIGNAL|INGESTION_HOLD_SUMMARY, reason_class, action_recommendation, счётчики,
   sampled_offsets, projection_verdict, truncated}. При short-circuit sequence_output=NOT_RUN.
6. ПОРОГИ — ФОРМУЛОЙ поверх замера (T ≥ ~10× max честного корпуса+батарея; T_count ≤
   sqrt(work_budget/измеренный k)); benchmark threshold−1/0/+1 обязателен. Не «на глаз».
7. НЕ-КОНТАМИНАЦИЯ: аддитивный pre-layer (карточный вход идентичен) + count-floor держит батарею
   структурно (батарея = count≤2, на 2+ порядка ниже порога) + acceptance-гейт.
8. ACCEPTANCE (ПЕРЕД мержем): ZWSP 21/21 + mutation 5/5 + oracle с НЕИЗМЕННЫМИ ожиданиями +
   DELTA-CENSUS (меняются ровно авторизованные) + FP-корпус (40Б/65Б/200Б/2КБ/CJK/Persian/код) +
   flood-bounce (<0.1с) + guard-mutation-батарея (off-by-one, byte/char, decoder-desync, overflow,
   smokescreen→проекция, оконный-скан-запрещён). Spy: при hard-bounce счёт вызовов
   _detect_context_at/_find_literal_matches/_demask = 0.
9. ГРАНИЦА: полный O(n)-проход по ВСЕЙ строке (НЕ оконный скан первых 4КБ — обход честным префиксом).
