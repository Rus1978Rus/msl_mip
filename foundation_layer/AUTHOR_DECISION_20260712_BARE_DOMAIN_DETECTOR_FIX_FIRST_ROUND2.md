БЛОКЕР → D-DET-4 — ВЕДУЩИЙ СТРУКТУРНЫЙ СИМВОЛ ПРОГЛАТЫВАЕТСЯ
════════════════════════════════════════════════════════════════
НАХОДКА (узкий круг). Позитивная выборка (FIX_FIRST_ROUND1) пропускает
ВСЁ до первого доменного символа и НЕ различает обёртку от структурного
разделителя. Ведущий @ (email/mention) и / (путь) исчезают бесследно.

Измерено (старое чёрным списком → новое позитивной выборкой без D-DET-4):
  #example.com／x   FREE_TEXT → PATH/MEDIUM
  /example.com／x   FREE_TEXT → PATH/MEDIUM
  @example.com／x   FREE_TEXT → PATH/MEDIUM
  :example.com／x   FREE_TEXT → PATH/MEDIUM

Нарушенный принцип: WRAPPER ≠ STRUCTURAL_SEPARATOR. Позитивная выборка
имела право пропустить обёртку (скобка, кавычка, звёздочка), но НЕ имела
права молча отбросить структурную границу.

РЕШЕНИЕ АВТОРА D-DET-4. Ведущие / \ ? # : @ — HARD_STOP: если такой
символ встречен ДО начала доменного блока, _domain_prefix возвращает
пустую строку (у токена нет доменного префикса). Остальную внешнюю
пунктуацию (обёртки) по-прежнему пропускаем.

  _LEADING_STRUCTURAL_STOPS = frozenset("/\\?#:@")
  while i < n and not (token[i].isalnum() or token[i] in ".-"):
      if token[i] in _LEADING_STRUCTURAL_STOPS:
          return ""
      i += 1

Это НЕ возврат чёрного списка: список пунктуации бесконечен, список
структурных границ — ЗАКРЫТ и уже имеет смысл в спецификации (path,
query, fragment, port, authority/email). Мы не гадаем «что добавит
атакующий», мы называем «что структурно значимо».

ПРОВЕРКА (измерено ПОСЛЕ правки, escape-строки где нужна однозначность
байтов):
  - четыре структурных кейса #, /, @, : → FREE_TEXT (были PATH/MEDIUM);
  - пять обходов-обёрток *, тире, ~, |, ＂ → HOST/HIGH (целы, обёртка ≠
    структурный разделитель);
  - базовые gоog／le.com, приме／р.рф → HOST/HIGH (не задеты).
Добавлено 4 gate-кейса (секция [D-DET-4]).

1.2 — ИСПРАВЛЕНИЕ ФОРМУЛИРОВКИ (документация врала, код верен)
════════════════════════════════════════════════════════════════
НАХОДКА (узкий круг). Везде, где написано «буква ЛЮБОГО алфавита» —
это ложь. Правда: «символы, для которых str.isalnum() = True».
Combining marks (Unicode-категории Mn/Mc) её НЕ проходят: IDN-домен на
деванагари с огласовкой (bharat.bharat, кодпоинты базовых букв U+092D
U+0930 U+0924 с огласовкой U+093E) под маской -> FREE_TEXT, потому что
U+093E DEVANAGARI VOWEL SIGN AA (категория Mc) даёт isalnum()=False, и
позитивная выборка обрывается сразу после базовой буквы. То же для
арабских диакритик, ивритских огласовок, NFD-разложенной латиницы.

СТАТУС. Это НЕ регрессия и НЕ баг кода: старый чёрный список оставлял
combining mark в строке, но неизменённая проверка метки
(all(ch.isalnum() or ch == "-")) всё равно её отвергала — итог тот же
FREE_TEXT. Меняется ТОЛЬКО документация: она обещала больше, чем код
делает.

РЕШЕНИЕ. Формулировка исправлена в: докстринге _domain_prefix
(sequence_engine.py), заголовочном комментарии детектора,
AUTHOR_DECISION FIX_FIRST_ROUND1 (через настоящий документ — см. ниже),
карточке (LIMITATION_STATEMENT). Точная формулировка везде:
«поддерживаются символы, для которых str.isalnum() истинно (буквы и
цифры Unicode), плюс дефис и точка; combining marks — НЕ поддерживаются
(isalnum()=False), это известное ограничение». Закрытие combining marks
требует полноценной IDNA/NFC-канонизации кандидата целиком — вне scope
грубого детектора, отдельное будущее решение.

ЗАКРЕПЛЕНО В GATE. Кейс с деванагари+огласовка (строка построена из
escape-последовательностей ради однозначности байтов) как
known_limitation → FREE_TEXT.

1.3 — ДОПОЛНЕНИЕ К D-DET-3 (маска ПОСЛЕ домена)
════════════════════════════════════════════════════════════════
Отдельный, но родственный D-DET-3 класс (тот же корень — грубая
эвристика без полного URL-парсера):

  gоogle.com*／path → HOST (ожидался бы PATH — маска в path-сегменте).

Механизм иной, чем у склейки D-DET-3: трейлинг-обёртка `*` обрывает
позитивный run на `gоogle.com`, и проверка left-only (и concat)
заново находит этот домен → HOST, хотя ／ физически стоит после домена.
Решение автора: ДОКУМЕНТИРОВАТЬ, не чинить (детектор консервативен,
HOST вместо PATH — не тихий пропуск). Дополнение вписано в секцию
D-DET-3 файла FIX_FIRST_ROUND1 и закреплено gate-ассёршеном.
