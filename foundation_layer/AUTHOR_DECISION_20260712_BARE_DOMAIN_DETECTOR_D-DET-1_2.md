Это НЕ применение патчей. Исходников патчей P1–P7 не существует —
код детектора голого домена написан ЗАНОВО по шести ревью,
использованным КАК СПЕЦИФИКАЦИЯ ТРЕБОВАНИЙ. Шесть ревью — источник
требований, НЕ одобрение. Поэтому:

  - реализация в sequence/sequence_engine.py: NEW_ARTIFACT, NOT_REVIEWED;
  - надёжной она считается ТОЛЬКО после прохождения конвейера и
    присвоения AUTHOR_DECISION по самому коду (та же дисциплина, что
    WORKING_DRAFT-предупреждения по карточкам).

Совокупный вердикт шести ревью по предложенному набору был РАСКОЛОТ:
три READY_TO_SAVE, три FIX_AGAIN/FIX_FIRST, разногласие по V5 (двойная
маска) и V3 (fail-closed). Разбор V5 показал: вердикты PASS содержали
арифметическую ошибку (полагали, что left+right сворачивается в
«google.com»; на деле остаётся вторая маска). Две находки признаны
реальными и закрыты настоящими решениями.

════════════════════════════════════════════════════════════════
D-DET-1 — НЕСКОЛЬКО МАСОК В ОДНОМ ТОКЕНЕ
════════════════════════════════════════════════════════════════
РЕШЕНИЕ. При проверке «рвёт ли маска домен» из токена убираются ВСЕ
маски (все вхождения всех объявленных масок), а не только текущая.
Если остаток похож на домен → HOST.

ПОЧЕМУ. Предложенный P6 проверял _looks_like_domain(left_part +
right_part), где left/right всё ещё содержали ДРУГИЕ маски. Для
«gоog／le.／com» обе маски давали FREE_TEXT (молчаливый пропуск того,
что на деле google.com). Это реальный обход: вторая маска в том же
токене подавляла детекцию первой (DeepSeek-R1, Qwen — FAIL по V5).

РЕАЛИЗАЦИЯ. _demask(s, mask_chars) в sequence_engine.py удаляет все
mask_chars из строки; вызывается для обеих сторон маски перед
_looks_like_domain. «gоog／le.／com» → «gоogle.com» → HOST.

ГРАНИЦА (не сузить решение молча). Сегодня единственная маска —
структурный разделитель ／ (fullwidth solidus), которого в настоящем
домене быть не может; удаление реконструирует домен. Если когда-нибудь
будет заведена БУКВЕННАЯ гомоглиф-маска (напр. кириллическая ‘о’ как
VISUAL_MIMIC_OF латинской ‘o’), сплошное удаление испортило бы метку —
там нужна не деляция, а подстановка канона. Это ОТКРЫТЫЙ вопрос,
требующий отдельного AUTHOR_DECISION; в текущем scope он не возникает
(таких карточек нет). Зафиксировано, а не спрятано.

════════════════════════════════════════════════════════════════
D-DET-2 — TLD-СПРАВОЧНИК НЕДОСТУПЕН → ТРЕВОГА, НЕ ТИШИНА
════════════════════════════════════════════════════════════════
РЕШЕНИЕ. Если TLD-справочник недоступен (пустой/битый набор),
домено-подобный токен с маской даёт ТРЕВОГУ, а не молчание; весь
прогон помечается DEGRADED.

ПОЧЕМУ. В предложенном P1 при деградации набор TLD становился пустым,
_looks_like_domain всегда давал False, и голый домен с маской проходил
как FREE_TEXT — молча. Флаг выставлялся, но ПОВЕДЕНИЕ не менялось:
fail-closed по метке, fail-OPEN по поведению (V3, CONCERN у 5 из 6).
«Fail-closed» обязано означать «при ошибке — консервативно, не
пропускать».

РЕАЛИЗАЦИЯ.
  - _tlds() проверяет здоровье набора (>= 100 записей); иначе
    _TLD_SOURCE_DEGRADED = True. load_single_tlds() и так имеет
    трёхуровневый резерв (live → cache → embedded ~200), поэтому
    DEGRADED срабатывает лишь при действительно битом источнике.
  - В degraded-режиме _is_tld принимает TLD-ПОДОБНУЮ метку
    (буквенная, длина 2..63) как TLD → домен распознаётся → HOST/PATH,
    а не FREE_TEXT.
  - Каждый вердикт несёт tld_source_degraded; SequenceOutput.degraded
    и предупреждение TLD_SOURCE_DEGRADED помечают ВЕСЬ прогон.
    Вердикты по голым доменам в этом режиме — provisional (метка +
    поведение вместе).

════════════════════════════════════════════════════════════════
АРХИТЕКТУРНОЕ ТРЕБОВАНИЕ — СПИСОК МАСОК ИЗ КАРТОЧЕК
════════════════════════════════════════════════════════════════
Список масок берётся из карточек (SIGN_RELATIONS → visible_form),
НЕ зашивается в код. Модули работают только с готовыми карточками
(ARCH_DECISION_HOMOGLYPH_VIA_CARD_ONLY). В коде: run_mask_chars в
_assess_relation_risk собирается из active_relation_candidates всех
sign_statuses прогона. Ни один mask-символ не появляется в детекторе
литералом; ／ нигде не захардкожен.

════════════════════════════════════════════════════════════════
ЧТО ЗАКРЫТО / ЧТО ОСТАЁТСЯ ГРАНИЦЕЙ
════════════════════════════════════════════════════════════════
ЗАКРЫТО (проверяется gate_bare_domain_detector.py):
  - внешняя пунктуация вокруг домена (P3): (gоog／le.com) и т.п. → HOST;
  - схема учитывается только в своём токене (P4): «http://safe.com/path
    then gоog／le.com» → HOST у второй маски;
  - домен с хвостом справа (P5): a.com／evil.com/path|:443|?x=1 → HOST;
  - IDN/punycode (P2): приме／р.рф → HOST; _looks_like_domain(пример.рф);
  - двойная маска (D-DET-1): gоog／le.／com → HOST;
  - деградация TLD (D-DET-2): при пустом наборе gоog／le.com → HOST +
    прогон DEGRADED.

ОСТАЁТСЯ ГРАНИЦЕЙ (честно, вне scope этого решения):
  - EMAIL-контекст (вне первого захода оси «отношение»);
  - zero-width между метками (напр. gоog​／le.com): невидимые
    символы — отдельный вектор нормализации; они НЕ объявлены масками
    в карточках, поэтому их удаление здесь нарушило бы «маски только из
    карточек». Зафиксировано как известная граница, gate это показывает
    явно, а не прячет.
