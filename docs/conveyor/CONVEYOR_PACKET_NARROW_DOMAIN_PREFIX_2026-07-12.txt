(informally "G1") was completed by four reviewers: architecture,

PART A — _domain_prefix: OLD vs NEW, side by side

--- The block-list constant the OLD version depended on (now DELETED) ---

    _STRIP_OUTER = "()[]{}<>\"'`,;!?»«“”‘’"

--- OLD (block-list; the bypass) — sequence/sequence_engine.py @ f9f0afd ---

def _domain_prefix(token: str) -> str:
    """P3 + P5: trim outer punctuation, then cut the tail at the first
    structural separator (path/query/fragment/port/space). Returns the bare
    domain candidate — 'evil.com/path' -> 'evil.com', '(a.com)' -> 'a.com'."""
    token = token.strip().strip(_STRIP_OUTER)
    cut = len(token)
    for sep in ("/", "?", "#", ":", " "):
        p = token.find(sep)
        if p != -1:
            cut = min(cut, p)
    return token[:cut].strip(_STRIP_OUTER)

    # BYPASS MECHANISM: token.strip(_STRIP_OUTER) only removes characters
    # that happen to be in _STRIP_OUTER. Wrap the domain in anything NOT in
    # that set — e.g. "*gоog／le.com*" (markdown emphasis) — and the leading/
    # trailing '*' survives. It then rides into _looks_like_domain, where the
    # per-label check `all(ch.isalnum() or ch == "-" for ch in lbl)` fails on
    # '*', so the string is NOT a domain -> FREE_TEXT. A real HOST mask goes
    # silent. Block lists only ever cover the punctuation someone enumerated.

--- NEW (positive extraction; the fix) — current working tree ---

def _domain_prefix(token: str) -> str:
    """POSITIVE extraction (FIX_FIRST 2026-07-12, blocker — three reviewers
    found the bypass in the first conveyor round): return the first maximal
    run of domain-shaped characters in the token — a Unicode letter (any
    script, so IDN labels such as a Cyrillic homoglyph attack still match —
    this is the thing we WANT to catch, not exclude), a digit, '-', or '.' —
    and discard everything outside that run.

    Replaces the old block-list approach (strip a fixed punctuation set,
    _STRIP_OUTER, off the token's outer edges). A block list only ever
    covers the punctuation someone thought to enumerate: markdown '*', an
    em dash, a tilde, a pipe, a fullwidth quotation mark and any other
    wrapping character NOT in that specific list stuck to the domain,
    made a label fail the isalnum-or-hyphen check in _looks_like_domain,
    and silently downgraded a real HOST mask to FREE_TEXT (a fullwidth-
    solidus mask domain wrapped in asterisks bypassed detection this way
    — the asterisks were never in _STRIP_OUTER; see the gate for the
    literal example). A positive allow-list closes the whole class at
    once instead of chasing individual punctuation marks.

    This also subsumes the old separate 'cut at the first /, ?, #, :,
    space' step (P5): none of those characters are in the allow-list, so
    the scan stops there on its own — no separate pass needed.

    Deliberately NOT trimmed here (known, deferred — see AUTHOR_DECISION
    D-DET-3 / FIX_FIRST_ROUND1 in foundation_layer): a leading/trailing
    hyphen on the extracted run (RFC-invalid but not rejected — v0.5
    tail), and the concatenation false positives this positive scan can
    itself produce when two unrelated fragments glue into a domain-shaped
    string once the mask is removed."""
    token = token.strip()
    n = len(token)
    i = 0
    while i < n and not (token[i].isalnum() or token[i] in ".-"):
        i += 1
    j = i
    while j < n and (token[j].isalnum() or token[j] in ".-"):
        j += 1
    return token[i:j]

KEY BEHAVIOURAL DELTA to scrutinise:
  - OLD kept the WHOLE token minus enumerated edge punctuation, then cut
    at the first structural separator.
  - NEW keeps ONLY the first maximal [letter-any-script | digit | - | .]
    run and drops everything before and after it. `token[i].isalnum()` is
    Unicode-aware, so non-ASCII letters (Cyrillic, Arabic, Devanagari, …)
    are INSIDE the allow-list on purpose — an IDN/homoglyph domain must
    still be extracted, not discarded.

def _is_tld(label: str, tld_set, degraded: bool) -> bool:
    """P2 (IDN): a label is a TLD if it is in the registry directly OR its
    punycode A-label is (an IDN ccTLD label -> its A-label, e.g. xn--p1ai).
    D-DET-2: when the registry is
    DEGRADED, accept a TLD-SHAPED label (alphabetic, 2..63) rather than go
    silent — alarm, not miss."""
    label = label.lower()
    if label in tld_set:
        return True
    try:
        alabel = label.encode("idna").decode("ascii").lower()
        if alabel in tld_set:
            return True
    except Exception:
        pass
    if degraded:
        return label.isalpha() and 2 <= len(label) <= 63
    return False


def _looks_like_domain(raw: str, tld_set, degraded: bool) -> bool:
    """A string looks like a bare domain: >= 2 labels, each a valid DNS
    label (alnum or '-', non-empty, <= 63 chars), last label a TLD. The
    tail (path/port/query) is trimmed by _domain_prefix first (P5)."""
    s = _domain_prefix(raw)
    if not s:
        return False
    labels = s.strip(".").split(".")
    if len(labels) < 2:
        return False
    for lbl in labels:
        if not lbl or len(lbl) > 63:
            return False
        if not all(ch.isalnum() or ch == "-" for ch in lbl):
            return False
    return _is_tld(labels[-1], tld_set, degraded)

NOTE on the interaction (this is exactly what the reviewer should probe):
_looks_like_domain calls _domain_prefix FIRST, then splits the result on
'.', then per-label runs `all(ch.isalnum() or ch == "-")`. So a character
survives to a label ONLY if _domain_prefix kept it. Since the positive
scan keeps `isalnum() or '.' or '-'`, and the per-label check accepts
`isalnum() or '-'`, the '.' is consumed by the split and everything else
was already dropped. That is the whole reason the bypass closes — but it
is also where any NEW miss or NEW false positive would live. Parts of the
label check that matter for the questions below: len>63 is rejected;
empty label (from '..' or a leading/trailing '.') is rejected; a hyphen
anywhere (including edges) is accepted; digits are accepted everywhere
including the last label (so a numeric TLD is shape-valid and then
gated only by _is_tld / registry membership).

БЛОКЕР — _domain_prefix: чёрный список → позитивная выборка
════════════════════════════════════════════════════════════════
НАХОДКА (три ревьюера, первый круг). _domain_prefix обрезал обрамление
домена по чёрному списку _STRIP_OUTER (фиксированный набор пунктуации).
Любой символ ВНЕ этого списка — markdown-звёздочка *, тире U+2014,
тильда ~, pipe |, полноширинная кавычка U+FF02 и т.п. — прилипал к
домену. Пример: `*gоog／le.com*` — после снятия маски label становится
`*gоogle.com*` (или после старой логики — `*gоog` / `le.com*` по
частям), в любом случае лишний символ остаётся ВНУТРИ метки, проверка
`ch.isalnum() or ch == "-"` на этот символ проваливается → домен не
распознаётся → тихий FREE_TEXT. Реальный обход HOST/HIGH-вердикта, не
краевой случай — блокирует READY_TO_SAVE.

РЕШЕНИЕ (не AUTHOR_DECISION в строгом смысле — обязательное
исправление корректности, не решение по вкусу). _domain_prefix
переписан с чёрного списка на ПОЗИТИВНУЮ выборку: находит первый
максимальный непрерывный блок домено-подобных символов — буква
ЛЮБОГО алфавита (Unicode-осведомлённая проверка `ch.isalnum()`,
поэтому IDN/гомоглиф-атака кириллицей по-прежнему ловится — это то,
что детектор ДОЛЖЕН ловить, а не исключать), цифра, дефис, точка — и
отбрасывает всё остальное. Закрывает весь класс обхода одним
изменением, а не патчами по символу.

Побочный эффект: этот же позитивный скан САМ ПО СЕБЕ подхватывает
старую функцию отреза хвоста (P5: `/`, `?`, `#`, `:`, пробел) — ни
один из этих символов не входит в allow-list, скан останавливается на
них естественным образом. Отдельный цикл `for sep in (...)` убран как
избыточный.

D-DET-3 — ЛОЖНЯКИ СКЛЕЙКИ: ДОКУМЕНТИРОВАТЬ, НЕ ЧИНИТЬ
════════════════════════════════════════════════════════════════
РЕШЕНИЕ АВТОРА. Позитивная выборка выше — эвристика, не полноценный
URL-парсер. Склейка левой и правой части токена вокруг маски
(left_part + right_part, механика D-DET-1) может дать ложный HOST на
двух НЕ связанных фрагментах, если результат синтаксически похож на
домен. Это признаётся и документируется как известное поведение
эвристики, НЕ как дефект, требующий немедленного исправления.

ПРИМЕРЫ (реальный вывод детектора, не предположение — прогнано
07-12):
  - `my-host／name.com` → HOST/HIGH. «my-host» и «name.com» — два
    самостоятельных фрагмента (например, из разных предложений или
    случайно соседствующих слов), которые после снятия маски
    склеиваются в синтаксически корректный `my-hostname.com`.
    Настоящей подмены домена здесь может не быть.
  - `example.com,／test` → HOST/HIGH (НЕ HOST/PATH — уточнено прогоном:
    запятая останавливает позитивный скан ДО «test», поэтому проверка
    «склеенное = домен» просто заново находит левый домен
    `example.com` и даёт HOST; «test» молча выпадает из рассмотрения).

ПОЧЕМУ НЕ ЧИНИТЬ СЕЙЧАС. Убрать этот класс ложняков означало бы
полноценный URL/токен-парсер с пониманием границ «слово / слово»
против «домен», что выходит за рамки текущего грубого детектора (Г1
исторически и есть «грубый», см. исходный докстринг
`_detect_context_at`). Правильный инструмент — отдельная итерация
детектора, не патч поверх позитивной выборки.

ХВОСТ 1 — уже-punycode вход вне активного справочника.
  Пример: `gоog／le.xn--zckzah` → FREE_TEXT/NONE (тихий пропуск) —
  проверено на пришпиленном тестовом TLD-наборе, НЕ содержащем
  `xn--zckzah`. `_is_tld` сперва проверяет метку как есть (не найдена),
  затем пробует `.encode("idna")` (для уже-ASCII `xn--...` строки не
  меняет её), тоже не находит. Это зависимость от ПОЛНОТЫ активного
  справочника, а не отдельный баг детектора: в проде (live IANA fetch
  или встроенный fallback ~200 записей) современные punycode ccTLD
  почти наверняка присутствуют. Помечено как известное, не чинится в
  этом круге.

ХВОСТ 2 — дефис на краю метки.
  Пример: `-example.com／x` → PATH/MEDIUM. Проверка метки
  `all(ch.isalnum() or ch == "-" for ch in lbl)` не учитывает ПОЗИЦИЮ
  дефиса — RFC 952/1035 запрещают дефис в начале/конце метки, текущий
  код это не проверяет, поэтому `-example` проходит как валидная
  метка. Не чинится в этом круге — записано как известное отклонение
  от строгого RFC.
