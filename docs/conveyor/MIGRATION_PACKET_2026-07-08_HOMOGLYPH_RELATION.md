D-REL-1. CARD_TYPE: FULL/HOMOGLYPH УДАЛЯЕТСЯ из ядра. Гомоглифность —
  отношение, не тип. Каждый знак — просто знак, одна карточка.
D-REL-2. Модель = блок SIGN_RELATIONS (минимальный): ребро с полями
  RELATION_TYPE (CONFUSABLE_OF/NFKC_MAPS_TO/VISUAL_MIMIC_OF), TARGET
  (кодпоинт/последовательность), CONTEXT_SCOPE (URL/PATH/EMAIL/
  IDENTIFIER/CODE/FREE_TEXT/ANY), VERIFICATION_STATUS. Ребро =
  RELATION_ONLY (само по себе НЕ риск). CANON_CARD_REF/CANONICAL_
  TARGET/HOMOGLYPH_CARD_REF → алиасы/представления того же отношения.
D-REL-3. Кейс ＠ (канон в CJK И маска @ в URL): выражается через
  CONTEXT_SCOPE, БЕЗ дубликата карточки. Вне scope — самостоятельный
  знак, внутри — активируется отношение.
D-REL-4. Локус риска маски = SEQUENCE-слой (ребро + защищённый
  контекст + соседи), НЕ single-sign. Инварианты: RELATION_FOUND ≠
  THREAT; CANON_MATCHER_RESULT ≠ FINAL_RISK; RISK = RELATION +
  PROTECTED_CONTEXT + SEQUENCE_PATTERN.
D-REL-5. Делегирование канону = только ЗОНД/PROBE. module_engine
  вызывает matcher канона за ГИПОТЕЗОЙ «что канон значил бы здесь» →
  это ДАННЫЕ в статусе, НЕ финальный риск. Маска в single-sign →
  risk NONE/DATA_ONLY + кандидат отношения.
D-REL-6. +шаг за обфускацию — в SEQUENCE (обфускация = свойство
  комбинации, не одиночного знака).
