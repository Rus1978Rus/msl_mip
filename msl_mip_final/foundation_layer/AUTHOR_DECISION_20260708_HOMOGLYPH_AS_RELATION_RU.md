  1. Ситуативное чтение знака — RICH, единогласно: поведение знака

  2. Гомоглифность: тип или отношение — FUNDAMENTAL_ERROR_CONFIRMED,

  3. Конструкция замены — CONVERGENT: минимальный блок отношений

     лагерь делегирования): риск маски решается в SEQUENCE-слое;
     делегирование канону допустимо только как ЗОНД/HELPER.

════════════════════════════════════════════════════════════════
РЕШЕНИЕ
════════════════════════════════════════════════════════════════

D-REL-1. ОСЬ «ТИП» ОШИБОЧНА. Поле CARD_TYPE: FULL/HOMOGLYPH
  удаляется из ядра (шаблон, парсер, module_engine). Гомоглифность —
  НЕ свойство знака, а ОТНОШЕНИЕ между знаками, активируемое
  контекстом. Каждый знак — просто знак, одна карточка.

D-REL-2. МОДЕЛЬ — БЛОК ОТНОШЕНИЙ. Вместо типа вводится блок
  SIGN_RELATIONS (минимальная форма): ребро с полями
  RELATION_TYPE (CONFUSABLE_OF / NFKC_MAPS_TO / VISUAL_MIMIC_OF),
  TARGET (кодпоинт/последовательность канона), CONTEXT_SCOPE
  (URL / PATH / EMAIL / IDENTIFIER / CODE / FREE_TEXT / ANY),
  VERIFICATION_STATUS. RUNTIME_EFFECT ребра = RELATION_ONLY (ребро
  само по себе НЕ риск). Существующие CANON_CARD_REF / CANONICAL_TARGET
  / CONFUSABLES.HOMOGLYPH_CARD_REF становятся совместимыми
  представлениями/алиасами того же отношения (миграция без потери).

D-REL-3. КЕЙС ＠ (двойная роль). Один кодпоинт может быть каноном в
  своей письменности и маской в другом контексте. Выражается через
  CONTEXT_SCOPE ребра, БЕЗ дубликата карточки (принцип «один знак —
  одна карточка» сохранён): вне scope знак работает как самостоятельный,
  внутри scope — активируется отношение.

D-REL-4. ЛОКУС РИСКА — SEQUENCE. Финальный вердикт о риске маски
  выносится в SEQUENCE-слое (ребро + защищённый контекст + соседи),
  НЕ в single-sign. Инварианты:
    RELATION_FOUND ≠ THREAT
    CANON_MATCHER_RESULT ≠ FINAL_RISK
    RISK = RELATION + PROTECTED_CONTEXT + SEQUENCE_PATTERN

D-REL-5. ДЕЛЕГИРОВАНИЕ КАНОНУ — ТОЛЬКО ЗОНД. module_engine может
  вызвать matcher канона в режиме PROJECTION/PROBE, чтобы получить
  гипотезу «что канон значил бы в этой позиции». Результат — ДАННЫЕ
  (гипотеза), прикрепляемые к статусу, НЕ финальный риск. Single-sign
  для маски эмитит risk = NONE/DATA_ONLY + кандидата отношения.

D-REL-6. +ШАГ ЗА ОБФУСКАЦИЮ — В SEQUENCE. Штраф за обфускацию
  (подмена канона маской в защищённом контексте) накладывается в
  SEQUENCE-слое, не matcher'ом канона (он не знает о маске) и не
  single-sign. Обфускация — свойство комбинации, не одиночного знака.

ОТКРЫТЫЕ ВОПРОСЫ РЕАЛИЗАЦИИ (решаются в КОДЕ через gate, НЕ конвейер)
════════════════════════════════════════════════════════════════
- Типизация canon_hypothesis: enum контекстов или свободные теги.
- Обратный индекс: ребро объявляется в карточке маски, канон не
  дублирует — рантайм строит reverse-index (кандидат, склонность ДА).
- Sequence Bloat: матчинг в sequence по свойству токена
  [is_homoglyph_of_X], а не отдельный SC на каждый вектор.
- Флаг «вызвано как маска» при зондировании канона.
Эти вопросы — реализационные, идут через КОД → code-review → gate →
ПК, не через новый дизайн-конвейер (дизайн решён).
